# samples/ —— 基线的输入对象

拆模块（破环）阶段对照基线之前，必须先证明**输入没变、管线没变**。否则读数一漂，
分不清是拆错了还是输入换了。这里的文件就是「输入是谁」这件事的唯一权威。

## 为什么这本 662 页的书不进仓库

`安乐哲 译本处理` 是用户库里的真实项目（662 页，源 PDF 2,597,736 B），不是合成的测试素材：

- 版权在用户/出版方，不进仓库；
- 用户库里的项目副本还会被用户的日常操作改动（重跑识别、改版心），仓库里放一份快照
  反而会让人误以为"仓库里这份就是基线输入"。

所以用 **指纹** 代替文件：只要某个项目副本的 `source_sha256` 和下面这些读数都对得上，
它就是同一份输入，不管是 `b2t_ZAQHGH` 还是别的副本目录。

## 三层指纹（判据见 `tests/e2e/artifacts/baseline-run-2026-10-28/BASELINE.md`）

| 层 | 字段 | 基线值（`2d33dd4` / tag `run-2026-10-28`） | 谁算的 |
|---|---|---|---|
| 输入 | `source_sha256` | `1c501e0f…ec407` | 直接读库（与代码无关） |
| 输入 | `page_count` / `text_pages` | 662 / 653 | 直接读库 |
| 输入 | `blocks` / `chars` | 4851 / 756247 | 直接读库 |
| 管线 | `body_segments` / `body_chars` | 4821 / 753335 | 当前代码现算导出预检 |
| 管线 | `body_pages` / `merged_segments` / `hyphenations` | 653 / 0 / 74 | 同上 |
| 管线 | `queue_total` / `queue_chars` / `queue_punct` | 859 / 567 / 292 | 当前代码现算审校队列 |
| 前端 | 队列 859(567+292)、进度 0/567、页码三方、导出字节与 sha | 见 BASELINE.md | 只能由真实界面跑出来 |

机器可读值在 [`baseline-input.json`](baseline-input.json)；守卫读它，不读本文。

## 一个真实陷阱：同名同源，不同产物

用户库里现在有 **3 个** `安乐哲 译本处理` 项目：

| 项目 | 源 PDF sha256 | 正文块 | 正文字符 | 2026-10-28 最后改动 |
|---|---|---|---|---|
| `b2t_ZAQHGH` | `1c501e0f…` | 4851 | 756247 | 12:56 |
| `b2t_4NWHBY` | `1c501e0f…` | 3325 | 572718 | 19:26 |
| `b2t_RHH2AC` | `1c501e0f…` | 3325 | 572718 | 15:19 |

源文件完全相同，识别产物不同（3325 vs 4851）。**只比 `source_sha256` 会漏掉后两个**，
它们能开出 662 页、看起来一切正常，但段数/字数/队列全对不上。所以守卫必须比管线层。

## 什么时候该换基线（而不是"修一下让对照过"）

只有两种情况可以换，且都必须**单开新基线**并在 `BASELINE.md` 标「输入变更」：

1. 用户重跑了识别 / 改了版心 / 换了源文件 —— 输入层会变；
2. 管线（`pipeline/`、识别/版心/导出相关后端）有意改了 —— 管线层会变，这属于产品行为变更，
   不是拆模块回归。

拆模块本身的提交**不许**碰这两层。真碰了，守卫会在 `qa.py up` 当场拒绝。

## 命令

```bash
# 离线比一遍（不起服务、不开浏览器，几秒）：输入层 + 管线层逐字段对
.venv/bin/python tests/e2e/qa.py fingerprint

# 起环境时自动守：不符就拒绝对照（要硬看也行）
.venv/bin/python tests/e2e/qa.py up                      # 不符 → 退出码非 0
.venv/bin/python tests/e2e/qa.py up --allow-input-drift  # 只做探索，读数不得当对照
```

指纹是在**临时副本**上算的（`/tmp/b2t-qa/b2t-qa-fp-*`，算完即删）：计算会写缓存文件，
绝不能落到用户库上。
