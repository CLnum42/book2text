## 0. 用户要求（验收标准）

> "上方的『页面』『审校』『导出』在类型上并不一致，建议调整为整个工作流的不同步骤（**页面确认、版心确认、文字识别、目录确认、正文审校、结果预览、文件导出**），每个功能完成后就显示绿色，没有完成的功能就显示正常按钮的颜色，从而可以视觉化地显示出整个项目的进度。下方窗口，则完全围绕 PDF 页面展开，现在的四级缩放保留。"

七步就是唯一的导航结构；页面永远是主角；进度条就是界面本身。

## 1. 步骤条

### 1.1 结构

```
《红楼梦》双语对照 3_正文_中文部分        ← 项目名，超长省略，点击回项目库
①页面确认 ✓  ②版心确认 ✓  ③文字识别 394  ④目录确认 !  ⑤正文审校 82  ⑥结果预览  ⑦文件导出
                                                        └ 微计数只在当前步 / 失败步出现
                                            右侧：已保存 ✓ 14:32 · 任务 45/394 ▸
```

- 步骤之间用 1px `--line-soft` 竖线分隔，**不用箭头**（箭头暗示必须按顺序，而这七步允许回看任意一步）。
- 每个步骤是一个 `<button>`：`aria-current="step"` 标当前步；编号 ①–⑦ 在图标位，已完成时替换为 ✓。
- **分页器搬走**：现在顶栏右半边的 `◀ 第 370 页 ▶ 跳转 全部页` 只属于"和页有关的步骤"，移到工作区工具条（§3.2），顶栏腾出约 220px 给七个步骤。

### 1.2 五种状态（颜色之外都有文字 / 图标）

| 状态 | 视觉 | 文字携带在哪里 | 依据 |
|---|---|---|---|
| **已完成** | 绿：✓ 圆形徽标 + 标签 `--ok-text`；底部 2px 绿色短条 | 徽标里是 ✓ 字形，不是纯色块；悬停 `title` 给 `已完成 394 / 394` | 用户要"完成后显示绿色" |
| **当前** | 蓝：左侧 3px 竖条 + 标签加粗 + `--accent-text`；**不是绿** | 竖条是形状差异；`aria-current` | 当前 ≠ 完成，别用绿色骗人 |
| **未开始** | 中性：灰底数字徽标（①）+ 标签 `--muted` | 数字本身说明"还没做" | 用户要"没完成显示正常颜色" |
| **有失败** | 红：! 徽标 + 标签 `--bad-text` + 微计数 `3 页失败` | "!" 与失败计数文字 | 失败不能只靠红 |
| **已跳过** | 灰虚线圆 + `--faint` + 标签后加 `（跳过）` | "跳过"两个字直接写在标签里 | 只有目录确认 / 页码可以跳过 |

规则：
- **完成** 只由后端状态算（§2 表），不因为"点开过"变绿；
- **当前**步即使在数据上已满足条件，也保持蓝色（它现在是你的位置），绿色只在离开后显示——同一时刻只有一个高亮，避免"又有绿又有蓝"；
- 有失败时，该步的微计数写 `3 页失败`，点击进去带筛选（失败页）。

### 1.3 点击行为

| 情形 | 行为 |
|---|---|
| 已完成 / 未开始 / 已跳过 | **都能进**。不做"锁死步骤"：这一行的七个步骤里，只有文字识别真正依赖版心（workflow 阶段 3→5），其余都是并列可回看的 |
| 前置没做完（例：版心 37 页未定就去文字识别） | 允许进入；该步工作区顶部出现一条前置提示：`⚠ 版心 37 页未定 · 先处理 → [去版心确认]`。**不用禁用态**，禁用会把用户关在门外 |
| 有失败 | 进入该步并自动筛到失败页 |
| 目录确认后端未上线 | **这一步不显示**（不是灰着）。显示一个做不了事的步骤违反"不显示未实现的功能" |
| 当前步再点一次 | 回滚到该步的默认子状态（例如审校：回到"待处理"筛选、队列第 1 处） |

### 1.4 14 寸与窄屏

| 宽度 | 方案 |
|---|---|
| ≥ 1320px | 全称：①页面确认 ②版心确认 ③文字识别 ④目录确认 ⑤正文审校 ⑥结果预览 ⑦文件导出 |
| 1120–1319px | 两字缩写：①页面 ②版心 ③识别 ④目录 ⑤审校 ⑥预览 ⑦导出（缩写固定，不做自动截断——截断会产生"正文…"这种歧义） |
| < 1120px | 步骤条压成一行：`③ 文字识别` 当前步全称 + 七个圆点（每点带编号数字，`title` 给全称） + `下一步 ›` |
| < 900px | 圆点也收进一个 `步骤 3 / 7` 按钮，点开是竖排列表（含状态） |

顶栏总宽预算（1440）：项目名 220 + 步骤 7×104=728 + 保存 96 + 任务 96 + 间距 ≈ 1180，剩余 260 给长项目名伸缩。分页器搬走后成立；不搬走就不成立（这是必须一起做的一步）。

## 2. 七步的完成判定（含"有没有数据"）

判定一律"**全部满足才算完成**"，并且**只由后端状态算**。下表最后一列是今天的真实情况。

| 步 | 完成判定 | 数据来源 | 现在拿得到吗 |
|---|---|---|---|
| ① 页面确认 | 所有纳入页 `page_confirmed = 1`；非正文页以类型为终态 | `finish-summary.page_type`（confirmed / total / complete） | ✅ 有 |
| ② 版心确认 | 每个正文页都有**生效版心**（`auto` 有框 / `custom` / `none`），`undetermined = 0`；`fallback > 0` 时仍算完成但标警告 | `finish-summary.margin`（set / total / fallback / undetermined / 页列表） | ✅ 有（"兜底页"单独可见） |
| ③ 文字识别 | 正文页 `recognized = total`、`failed = 0`；双引擎开启时 `engine.checked = total`；差异已算 | `summary.pages`（recognized / failed / unrecognized）+ `finish-summary.engine` | ⚠️ 前两项有；**"差异已算"没有单独计数**——需要后端给 `diff_done_pages`（或 `page_workflow.stage >= diff_done` 的页数） |
| ④ 目录确认 | 目录已确认：章节数 ≥ 1 且每章有 `printed_page` 或明确"本章无页码"；或用户明确"这本书没有目录"（跳过） | 无 | ❌ **全缺**，要新接口（§2.1） |
| ⑤ 正文审校 | `review.needs_human = 0` 且 `review.auto_passable = 0`（全部页已确认）且 `layout.remaining = 0`（版面是审校的前置，见 §4.3） | `finish-summary.review` + `.layout` | ✅ 有（版面确认本来就在收尾面板里，现在并进 ⑤） |
| ⑥ 结果预览 | 组装可生成：`segments > 0` 且预检里**没有未识别 / 失败的页**（`unfinished_pages = 0`，否则导出必然缺内容） | `POST /export/preview`（segments + preflight.unfinished_pages） | ✅ 有（**注意**：这是"现在能不能组装"，不是"用户看没看过"——文案写"可组装"，不写"已完成"） |
| ⑦ 文件导出 | 至少一次**成功**导出，且导出时的 `manifest.workflow` 快照与当前状态一致；不一致显示「内容已变，需重新导出」 | 导出记录 + `manifest.json` 里的 workflow 快照（任务 61 已写） | ⚠️ 记录有、快照有；**缺一个"快照 vs 现状"的对比**——两个选择：前端拉最近一次导出的快照摘要，或后端加 `GET /exports/latest/status` |

### 2.1 目录确认要补的接口（给 Builder 的最小契约）

```jsonc
// GET /api/projects/{id}/toc/candidates  —— 只读，不改任何东西
{ "chapters": [ { "block_id": "...", "page_no": 87, "printed_page": "58",
                  "title": "第四回", "source": "heading_block", "confidence": "high" } ],
  "unresolved": [ { "page_no": 90, "reason": "标题在版心外 / 印刷页码缺失" } ] }

// GET /api/projects/{id}/toc  → { "confirmed": true|false, "skipped": bool, "entries": [...] }
// PUT /api/projects/{id}/toc  → 写 entries / skipped（一条事件，可撤销）
```

- 章节候选的来源只有两种，不引入新模型：**版心内的 `heading` 块**、**版心外的竖排书眉**（`header` 块 + `printed_page`）；
- 页码沿用现有 `printed_page` / `page_number_template`，不重算；
- 确认状态**必须存库**，否则步骤条无法变绿、审校左栏也无法引用。

## 3. 下方工作区：一个容器，七种装法

### 3.1 统一容器

```
┌ 步骤条 ─────────────────────────────────────────────────────────────┐
├ 工作区工具条：本步主操作 · 筛选 · 缩放（四级） · 视图开关 · 分页器 ─────┤
├──────────┬──────────────────────────────────┬─────────────────────┤
│ 左栏      │ 页面画布（PDF 页）                │ 右栏                │
│ 可选      │ 四级缩放：网格 / 大网格 / 单列 / 单页│ 本步分区            │
└──────────┴──────────────────────────────────┴─────────────────────┘
```

| 步 | 左栏 | 画布 | 右栏 |
|---|---|---|---|
| ① 页面确认 | —（可收起） | 网格（默认大网格）+ 类型角标 | 页面类型（现有手风琴第 1 节） |
| ② 版心确认 | — | **单列**默认（可切网格）+ 版心压暗、四边可拖 | 版心（第 2 节，去掉模式选择） |
| ③ 文字识别 | — | 网格 + 识别状态角标 + 块框（默认开） | 识别设置 + 任务进度（第 4 节） |
| ④ 目录确认 | **章节列表** | 单页 + 书眉/标题高亮 | 目录候选 / 页码定位 |
| ⑤ 正文审校 | **目录 + 审校清单** | 单列/单页 + 差异标记 | 块列表 + 队列条 |
| ⑥ 结果预览 | — | 单页（跟随所选段落） | 组装正文（宽 520） |
| ⑦ 文件导出 | — | 预检摘要 + 导出选项 | 导出记录 / 结果 |

### 3.2 四级缩放怎么在各步之间保持一致

- **一份状态**：`{mode: "grid" | "large" | "single" | "page", zoom: 1.0}`，存在项目里（沿用现有 localStorage 键），七步共用同一份。切步骤不重置。
- **步内最低档**：⑤ 正文审校 需要看得清差异字，最低 `单列`；从 ① 的网格点进来时**自动抬到单列**，并把用户原来的网格选择记在 `modeBeforeReview`，离开 ⑤ 时恢复。只抬不降，且只抬一次（用户手动改回网格允许，但会给一行提示"网格下看不清差异标记"）。
- **⑥ 结果预览** 固定单页（对照要一一对应），缩放仍可 ±（0.5–3×）。
- **工具条位置统一**：`－ [单列] ＋` 永远在工作区工具条右侧，位置不随后续步骤变化（今天的页面视图缩放条在筛选条里，审校视图在左下角——同一个功能两种位置，这是要消除的不一致）。

### 3.3 ⑤ 正文审校：左栏放什么

```
┌ 目录 ─────────────┐
│ 第一回   12        │  ← 章节 + 印刷页码；当前章高亮
│ 第二回   48        │     点一下跳到该章第一页
│ 第三回   96        │
│ …                  │
├ 审校清单 ──────────┤
│ 全书 1733 处 · 还剩 1024 处  │
│ ▸ 第 87 页  4 处（2 未判）   │  ← 只列还有未判差异的页
│ ▸ 第 90 页  1 处（1 未判）   │
│   第 96 页  ✓               │
│ …                  │
└────────────────────┘
```

- 目录数据来自 ④ 的确认结果；④ 没做时退化为"标题块 + 印刷页码"的只读列表（有数据、无确认语义），**不留空面板**。
- 审校清单 = 今天的"工作流筛选=待处理"的专业版：页级 + 剩余差异数，点一行跳页，当前页高亮并随翻页滚动（虚拟滚动，394 页也要秒开）。
- 左栏可收起成 44px 图标轨（目录 / 清单两个图标），窄屏自动收起。

## 4. 正文审校内嵌：右栏块列表去哪

现状是独立视图（左图 + 右块列表 + 顶部队列条）。用户要求"不单独开页面，直接在页面视图的单列/单页里审"，且"左侧可增加目录和审校清单"。三个方案：

### 方案 A（推荐）：三栏 —— 左目录/清单 · 中页面 · 右块列表

```
│ 目录/清单 220 │ 页面（单列/单页） flex │ 块列表 380 │
```

- 信息密度：**高**。图和文同时在场，目录/清单一键跳转；右栏保留现有的编辑、类型、状态、块菜单——**任务 64 的右栏一行不改**，只是变窄。
- 跳转效率：最高（清单点页 = 换页；目录点章 = 换页；队列条在页面顶部走完全书）。
- 取舍：右栏从 ~420px 缩到 380px，块正文一行约 24 字（今天约 28 字），段落手感略差；中间页面在 1440 下约 820px，A4 竖排足够。
- 窄屏：< 1320 左栏收成图标轨；< 1120 右栏改成**底部抽屉**（拖起半屏），页面占满宽度。

### 方案 B：两栏 —— 左目录/清单 · 中页面 + 浮动块卡

- 页面吃满剩余宽度（约 1200px），块卡悬浮在页面右侧（420px，可收起）。
- 取舍：页面最舒服；但浮层必然遮挡页面右侧正文，拖框/翻页时来回开关，**审校时遮挡的恰好是要对照的那半页**。不推荐作为主方案。

### 方案 C：两栏 —— 中页面 · 右块列表（现状搬迁）+ 目录/清单做抽屉

- 改动最小（把 review 视图左图换成页面视图的页即可），今天的代码直接可用。
- 取舍：**没有全局位置感**——看不到"我在第几章、还剩多少页"，这正是用户加左栏的原因；抽屉每次要开，跳转多一次点击。作为 A 的降级形态（窄屏）可以，但不应是主方案。

**结论**：选 A，B 作为"页面宽度不够时的临时浮层"，C 只作为窄屏降级。三栏的中间列保留今天的队列条（页面顶部），右栏因此**删掉块内差异条**（同一事实只在一处，沿用上一单的结论）。

## 5. 结果预览

```
┌ 工具条  组装：1284 段 · 跨页段 96 · 22.4 万字 · 版心外剔除 41 块   [段落已合并] [重新组装] ┐
├ 左：PDF 单页（跟随所选段落） ───────────────┬ 右：组装正文 ───────────────────────────────┤
│                                            │ §128 第 87–88 页 · 跨页 2 页 · 3 块  ⟵ 选中 │
│   ┌──────────────────────────┐             │ 维太平不易之元，蓉桂竞芳之月，无可奈何之日…  │
│   │ 高亮：本段来源块（2 个）   │             │                                              │
│   │ 虚框：跨页的第二页来源     │             │ §129 第 88 页 · 2 块                        │
│   └──────────────────────────┘             │ 窃思女儿自临人世，迄今凡十有六载…            │
├────────────────────────────────────────────┴──────────────────────────────────────────────┤
│ 问题段落：跨页 96 · 段首缩进异常 3 · 空段 2        [只看问题段]   [导出 TXT…]（→ ⑦ 文件导出）│
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

规则：

- **来源可追溯**：每段头一行 `§序号 第 X–Y 页 · N 块`；点段 → 左图跳到该段**第一页**并把来源块高亮（accent 框 + 顺序号），跨页段在左图另给一个"还有 1 页"的小 chip，点它跳第二页来源。
- **跨页段**：段头徽标 `跨页 2 页`；正文里在两页交界处插一条 1px 虚线 + 页号小字（不影响复制与导出，只是显示层）。这是"组装是否靠谱"最需要人眼确认的地方。
- **筛选**：只看跨页段 / 只看问题段（`segments` 里 `pages.length > 1` 是现成数据；"段首缩进异常/空段"要新判据 → 第一版只做跨页，其它标"需要后端判据"，不做假筛选）。
- **预览是真预览**：直接用 `POST /export/preview` 的 `segments`（含 `pages` / `block_ids` / 文本），与 ⑦ 导出同一套代码，**不另写一个组装器**。
- 预览只读：任何修改都必须回到 ⑤ 正文审校，避免"预览里改一处、导出时忘了更没更新"。

## 9. 未验证 / 风险

- **"差异已算"没有独立计数**：③ 的完成判定需要 `diff_done_pages`；没有它就只能用"已复核页数"近似，会漏掉"复核了但差异没算"的页。建议后端补一个字段（低风险）。
- **⑥ 的"完成"语义**：本文定义为"当前可组装"，不是"用户看过"。若用户坚持要"看过才算完成"，需要后端记录一次预览事件（不推荐：那会让步骤条变成打卡器）。
- **⑦ 的快照对比**：需要最近一次导出的 workflow 快照；如果导出记录列表不回传快照摘要，就得读 manifest（多一次 IO）。第一版可以只在"最近一次导出的页数与当前不一致"时提示，精度够用。
- **目录的章节识别质量未验证**：真书里标题块可能有漏、有把正文首行误判成标题的；④ 的确认流程必须允许删除/新增章节（不只勾选）。这一条需要真书跑一遍才知道阈值。
- **三栏在 13 寸（1280×800）下的实际观感**未截图验证；按预算中间列约 680px，13 寸可能偏窄，需要真机确认后再决定是否默认收起左栏。
