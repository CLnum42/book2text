## 0. 两个数（DevLead 要的结论，先给）

### ① 下区两列：**与上区对齐，左列 420px**（不是 50/50）

| 方案 | 裁切列宽 | 可用内宽 | ±15% 窗口(496px) 下 zoom | 显示行高 | 结论 |
|---|---|---|---|---|---|
| **对齐 420** | 420 | 404 | **0.81** | **28.5px** | ✅ 在 26–36 目标内，5 行 = 142 |
| 50/50 | 711 | 695 | 1.40 | **49px** | ❌ 超过 PM 定的 40px 上限（再压回 40 就得把窗口放到 ±18%，自相矛盾） |

- **选对齐**。理由不是倍数，是**同一条竖线贯穿上下**：裁切图正对上面的 PDF，编辑框正对上面的正文，眼睛上下移动不需要重新定位；50/50 会在中间多出一条错位的竖线。
- 倍数的真实值（以本书 L≈35 为例，不是 1.9×）：上区 PDF 显示行高 **8.9px**（= 420/1654 × L），对齐 420 + ±15% 窗口时下区 **28.5px → 3.2×**。PM 稿里的 1.9× 对应的是 **±26% 窗口**（871px，几乎整行塞进列里），那已经不是"局部放大"，建议弃用这个口径。
- **窗口是高度的因变量**（DevLead 已定为硬约束）。先定"5 行填满内容区"，再反推 zoom 与窗口：

```
L  = 该块相邻行中心距的实测中位数（像素；不写死 35）
Ht = 内容区高 − 16                          # 900 高：182−16 = 166；628 高：158−16 = 142
s  = min(Ht / (rows × L), 40 / L)           # rows 从 5 起；40/L 是源分辨率上限
W  = 404 / s                                # 404 = 420 − 16 内宽
```

| 场景（示例：本书实测 L ≈ 35） | Ht | rows | s | 下区行高 | 窗口 | 放大（下区行高 ÷ 上区 8.9） |
|---|---|---|---|---|---|---|
| 900 高、下区 276 | 166 | 5 | 0.949 | **33** | 430px（±13%） | **≈3.7×** |
| 628 高、下区 252 | 142 | 5 | 0.811 | **28** | 498px（±15.1%） | **≈3.2×** |

- 上表是 L≈35 的**示例**，不是常数：换书、换块，L 变、窗口跟着变。
- 倍数在文案/界面上只写公式 **`下区行高 ÷ 上区行高`**（上区行高会随 PDF 列宽变），不留固定数字。
- PM 稿的"±15% 窗口"与"34px 行高"在 420 列里互斥（34px ⇒ ±12.6%；±15% ⇒ 28.5px）；这里以"5 行填满 + 40 上限"为准，窗口随高度浮动。±15% 只在"下区 ≈253 高"时成立。

### ② 标题栏 34px 放什么

```
┌ 第 147 页 · 第 3 行  [汉字级]                                  3 / 567   收起 ⌄ ┐
```

| 位置 | 内容 | 说明 |
|---|---|---|
| 左 | `第 {页} 页 · 第 {行} 行` + 等级徽标 `汉字级` / `标点级` | 只用用户词；点标题 = 把上区滚回这一行（`title="回到这一行"`） |
| 右 | `3 / 567` + `收起 ⌄` | 计数器与工具条同源；用 **⌄ 不用 ✕**——这是"收起常驻面板"，不是关对话框；Esc 同效 |
| 不放 | "第二路""草稿""收尾" | PM 审计已列为内部词；候选/原文放在右列正文上方（见 §2.3） |

34px 的分配：标题 12.5px/600 + 徽标 10px + 计数 11px + 收起 24×24。≥1120 宽全显示；<1120 隐藏 `3 / 567`（工具条里有），<900 隐藏徽标（正文上的红字已经表达等级）。

## 3. 5 行裁切（几何定稿）

| 项 | 规则 |
|---|---|
| 行的判定 | `block_line.bbox`（归一化行框），不是 DOM 行盒 |
| 行距 L | 该块**相邻行中心距**的实测中位数；不是全书定值，更不是 35 |
| 行距的三种边界 | **块首行**：取下方相邻对；**块末行**：取上方相邻对；**跨页段**：只用**同一页内**的行对（页与页之间没有几何关系，不跨页取距） |
| 取不到 L | 块内只有 1 行 / 缺 bbox → 用该行 bbox 高 × **1.35** 兜底；仍取不到 → **降到 4 行**，不硬撑 5 行 |
| 纵向 | 以审校行为中心，上下各取"距中心 ≤ 2L"的行，合计 ≤5；贴边时整体滑动、向另一侧补足 |
| 横向 | 以差异 span 的 bbox 中心为锚；窗口 W 由 §0-① 的公式算出（**因变量**） |
| 跨页 | **不拼两页**：只取审校行所在页；上下不足按"滑动贴边"处理 |
| 缩放 | `s` 由公式得；倍数 = `L × s ÷ 上区行高`（上区行高 = PDF 列宽 ÷ 页宽 × L），**只写公式不写死数字** |
| 对齐容差 | **0**：裁图与高亮同源 `bbox`；**禁止**在裁切图上按字宽/行距估算位置（估算只允许留在上区） |
| 缺行框 | 旧项目没有 `line_spans` / 行框 → 3 行（目标 ±1）+ 标题不显示行号 + 不画估算框 |

### 3.1 降级算法（DevLead 硬约束：行高 ≥26、窗口随行数重算）

```
plan(L, dockH):
  Ht = dockH − 94 − 16                 # 内容区再扣上下 8；900：166，252：142
  for rows in [5, 4, 3]:
    s  = min(Ht / (rows × L), 40 / L)  # 下限靠"减行数"拿，不靠压 s
    h  = L × s                         # = min(Ht / rows, 40)
    W  = 404 / s
    if (26 <= h <= 40) and (W <= 0.45 × pageW):
      return { rows, s, h, W, level: String(rows), degrade: null }

  # 5→4→3 都不满足时：628 档先换高度（硬规则），且**固定试 4 行**，不是重新从 5 行规划
  if viewportH <= 700 and dockH < 252:
    dockH = 252; Ht = 252 − 94 − 16 = 142
    for rows in [4, 3]:
      s = min(Ht / (rows × L), 40 / L); h = L × s; W = 404 / s
      if (26 <= h <= 40) and (W <= 0.45 × pageW):
        return { rows, s, h, W, level: "252+" + rows, degrade: null }

  # 最后一级：封顶留白，写原因
  s = 40 / L
  return { rows: 3, s, h: 40, W: 404 / s, level: "capped-40",
           degrade: "window>45%" 或 "lineH>40" }
```

- **行高硬下限 26**（DevLead 口径，不是 24）：到不了 26 时**先降行数**（5→4→3），再（628 高）**把下区提到 252 用 4 行**，最后才封顶留白。**不许压 s 兜底**。
- **`W > 45% 页宽` 或 `行高 > 40px` → 同样降行数**；行数越少 s 越大、窗口越窄，这是唯一能同时满足上下限的方向。
- 窗口与行高**同时重算**，不许只减行数（只减行数会切字/漏字）。
- **3 行是地板**：仍不满足时 `s = 40/L` 封顶 + 允许横向截断，并写 `degrade` 原因（QA B5 口径）。
- **2 行以下不做**：上下文不足，宁可收起面板让用户看上方 PDF。
- 行距未知（B6）：固定 **4 行**、不受 40px 约束、标 `no-line-gap`；纵向只按 bbox 中心排，不按"行高 × 2"外推。

### 3.2 返回值契约（验收 B9：没有 `L/n/level` 就查不出"窗口为什么这么宽"）

```js
{
  L,          // 实测中位行距（px）
  L_source,   // "median" | "bbox×1.35" | "none"
  n,          // 实际行数 3|4|5（块内不足就取实际行数）
  level,      // "5" | "4" | "3" | "252+4" | "252+3" | "capped-40" | "no-line-gap"
  dockH,      // 本次用的下区高度
  s, lineH,   // 缩放 / 下区显示行高
  windowPx, windowPct,   // 窗口宽与占页宽比
  degrade,    // null 或原因：window>45% / lineH>40 / lineH<26 / no-line-gap
  bbox: []    // 参与裁切的行框（原样，供 20 条对齐抽检）
}
```

- 三类边界各抽 3 条验 `L`：块首行（取下方相邻对）、块末行（取上方相邻对）、跨页段（只用同页行对）。
- `level` 与 `degrade` 必须同时落进调试输出；`windowPct` 用于回答"为什么窗口这么宽"。

## 5. 上下联动（PM §6 + 我补的视觉）

| 动作 | 上区 | 下区 |

## 6. 键盘（与 PM §8 一致）

| 键 | 行为 | 前提 |
|---|---|---|
| `Enter` | **保留原文**并下一处 | 下区打开、非编辑态、焦点不在输入框 |
| `Space` | **采用候选**并下一处 | 同上 |

| `Esc` | 编辑态 → 判决态；判决态 → 收起 | — |
| `[` / `]` | 收起 / 展开左树 | — |

**同一刀必须修**：现在 `Enter` 在面板开着时走 `gotoNextUnreviewed()`，会跳过当前条且不记录——进下区后用户会一直按 Enter，这个缺陷等于批量漏审。

## 9. 风险

- **行距 L 的测量是新的失败点**：块首/块末/跨页段各自取距的规则已定（§3），但真书里块只有 1–2 行、bbox 缺失、页边注混进来的情况仍需实测；这类样本必须走"4 行降级"，不能靠兜底值硬撑 5 行。
- **628 高 + 大行距**已是硬规则（A4/B5）：行高给不出 26 时，顺序是**先降行数 → 252+4 行 → 才 3 行封顶**。真书出现时按规则执行，不需要再判断。
- **±13%（900 高）/ ±16.4%（628 高）窗口**会让阔行两端被裁掉（约 17–20 字可见）；用户想看整行必须看上方 PDF——这是"放大镜"的取舍，PM 已认。
- **浮层态（<620 高）**与上区虚拟滚动叠加时，被遮住的段仍会渲染 1–2 段，可接受。
- **`setCaretAfterLastChar`** 在 Safari 对行末换行的处理需逐一验证（本次未测）。
