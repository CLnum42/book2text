# 正文审校一屏：UX 重做（V3）

> 状态：设计稿，未改产品代码。基线 `main@e0a228c`。
> 依据：`docs/pm/review-ux-audit.md`、用户 2026-10-27 原话、`docs/spec-v1.0.md` §7、当前 `backend/book2text/static/{app.css,app.js,index.html}`。
> 产出：本文 + `review-screen-ux-v3-mockup.html`（F1–F7，可点单个 `#F1`…`#F7` 查看）+ `review-screen-ux-v3-mockup.png`。
> 范围：只改「正文审校」这一屏。不动数据模型、导出、识别、目录。

## 0. 结论

**三改，一条推荐，不给备选。** 本文所有数字的来源与时点见 §0.1；未标来源的耗时/比例都是估计，按「未实测」引用。

1. **一条 = 一处差异，不是一整行。** 点红字后的面板只显示差异片段 ±6 字，原文 / 候选各一行；差异字加粗 + 2px 下划线；「看整行」才展开整行。默认按钮是「保留原文」（80.9% 的情况），不是「采用」。
2. **判决即前进。** 判完面板不关，内容换成下一条，当前行钉在视口同一高度；`Enter`=保留并下一处，`空格`=采用并下一处，`E`=改，`Esc`=停手。同时修掉「面板开着按 Enter 会跳过当前条且不记录」。
3. **进度说人话。** 工具条只留两条轨：`汉字 100/899`、`标点 0/724 行`；**不设「待判 N 处」这个第三个数**，避免汉字判完就以为全书完了。轨上方只放一行 ETA（判过 20 条后给「约剩 M 分钟」），标点不混进汉字百分比；左树 394 行 → 27 回折叠。

**一个明确的取舍：** 把「跟随」「提交」两个动作、以及「成稿」这个词从界面上拿掉。它们都是实现细节：同步是默认行为，保存是判决的副作用，修订标记是「显示」里的一档。界面只留用户要做的判断。

**一个对 PM 审计的修正：** 「27 回折叠」**不需要后端切片**。`GET /review/tree` 已经返回 `chapters[]` 和每页的 `chapter`（`core/project/review_status.py:502-560`），前端 `renderReadingTree()` 只用了 `pages`，把 `chapters` 丢了。这是纯前端改动。

## 1. 现状实测（为什么是这三件）

### 1.1 尺寸与断点

| 宽度 | 左树 | 页图 | 正文（可用） | 问题 |
|---|---|---|---|---|
| 1280 | 232 | 422 | 614 | 可用，但页图偏窄 |
| 1120 | 200 | 340 | 570 | 页图字高 ≈10px，判字吃力 |
| 1000 | **44** | **260** | 696 | 左树只剩一列 ✓（页码被隐藏）；页图字高 ≈7px，读不了 |
| <820 | 0 | 0 | 全宽 | 页图直接消失 |

- 628 高：顶栏 48 + 工具条 40（≤700 时）= 88，正文 540。
- 正文 `15px / 2.05`，行宽 614 → 约 40 汉字/行；面板展开后 `scrollIntoView({block:"center"})`，判完 `closeReadingPanel()`。
- 当前断点：`1319 / 1119 / 819`（`app.css:2538-2553`）。`<1120` 把树压成 44px，同时 `.reading-tree__no { display:none }`——用户看到的是一列没有页码的 ✓。

### 1.2 四个硬伤（按 PM 审计的耗时排序）

1. **判断单位是「一处差异」，显示单位是「一整行」。** `openReadingPanel()`（`app.js:18798`）把 `entry.candidate` 整行铺在面板里，头写「第 N 页 · 第 N 行第二路」；用户读两行约 40 字，自己在心里做 diff，而 80.9% 读完什么都不用改。这是 2–3 小时的真实去处。
2. **判完不前进。** `draftReading()`（`app.js:18910`）只做 `closeReadingPanel + rerender + 进度`，不推进游标；要再点顶部「下一处未审」。更糟：面板开着按 `Enter` 会走 `gotoNextUnreviewed()`，从游标**之后**找，当前条被跳过且不记录（`app.js:20220`）；阅读视图里采纳/保留**没有键位**。
3. **进度口径三重不一致。** `renderReadingProgress()` 写 `已审 ${processed}/${total} 字`（数的是条数，`app.js:18770`）；步骤条写死「汉字剩 N」（`app.js:393`，英文书也这么写）；进度条只覆盖汉字级 899/1623，标点 724 行藏在按钮里，能到 100% 却没完成。
4. **左树是 394/662 行平铺页码。** `renderReadingTree()` 的 `pages.filter((page) => page.unacked > 0 || true)`（`app.js:18949`）把所有页都列出来；`chapters` 就在同一个响应里，没用。662 页的心理负担主要来自这里。

补充：

- 工具条 10 个控件，`跟随：开` 与「显示 ▾」里的「跟随滚动」是同一个开关的两份；「成稿」藏在「显示」里，用户不知道那是什么。
- 页图上**始终画着块框**（蓝色描边），380px 宽时块框比字还清楚，进一步压低可读性。
- 文案里的「第 N 页第 N 行第二路」「草稿」「收尾 0/6」「版心外 91 · 其他 6」都是内部坐标。

### 1.3 不动的部分

- 数据：`diff_ack`、`line_spans`、`drafts`、`segments`、导出组装；两路 OCR 的候选只在面板里看，不写回原文。
- 结构：左树 + 左页图 + 右连续正文流；不拆成三个页面，不引入框架。
- 原则：不显示未实现的功能；状态必须来自真实数据；颜色之外必须有文字/形状。

## 2. 改一：一条 = 一处差异

### 2.1 单位

| 单位 | 职责 | 不变 |
|---|---|---|
| 页 | 同步、跳转、进度 | 是 |
| 段 | 排版容器（跨页段已合并） | 是 |
| 行 | 审校数据单位（`block_line`） | 是 |
| **差异窗口** | **本单新增：面板里显示的范围** | 只影响显示 |

- 一次判断仍然对应一个 `entry`（一行一处）；判断的**阅读量**从「整行」缩到「差异 ±6 字」。
- 面板仍然用现有的 `line.after(panel)`（`app.js:18850`）插在当前行之后——不是段后。所以差异在第一行时，面板就在第一行下面。
- 「看整行」只是把同一份 `current / candidate` 换成整行显示，不改变判断对象。

### 2.2 面板规格

```
┌──────────────────────────────────────────────────────────────┐
│ 第 87 页 · 本页 3/7     其余 19 字相同                看整行 │  18px
│ 原文   …你们去罢，他们倒便[宜]些呢。”贾珍等…                  │  24px
│ 候选   …你们去罢，他们倒便[意]些呢。”贾珍等…                  │  24px
│ [保留原文 ⏎] [采用候选 空格] [自己改 E]        Esc 停手 · ⌘Z │  26px
└──────────────────────────────────────────────────────────────┘
   3px 蓝色左边条 + 上方指向当前字的小三角（--caret-x）
```

| 项 | 值 |
|---|---|
| 宽度 | 正文列宽（≤600），不缩进 |
| 内边距 | 上 7 / 右 12 / 下 9 / 左 12（左边条 3） |
| 总高 | **112–124px**（628 下必须 ≤124） |
| 头 | 11.5px，`第 87 页 · 本页 3/7`；「其余 19 字相同」用 `--faint`；「看整行」是 11px 虚线下划线链接 |
| 两行 | 14.5px / 24px；标签列 44px 右对齐，`原文` 灰、`候选` 蓝；行首行尾截断时加 `…` |
| 差异字 | `font-weight:700` + `box-shadow: inset 0 -2px 0 var(--accent)` + `background: var(--accent-soft)`；**不用红/绿**，这是 A/B 不是对/错 |
| 按钮 | 保留原文 = 主按钮（蓝）；采用候选 = 次按钮；自己改 = 文字按钮；右侧 `Esc 停手 · ⌘Z 撤销` 10px |
| 关闭 | 没有 ✕。`Esc` 收起；点另一处红字自动换条 |

**文案：**

- 头：`第 87 页 · 本页 3/7`（3 是这一页未决项里的序号，7 是本页未决总数）。数据拿不到序号时退化为「本页 7 处」，不编。
- 「其余 19 字相同」：`current.length - Σ(aEnd-aStart)`；0 时写「整行为替换」。
- 候选为空：写「候选为空（另一个 OCR 版本没有识别出字）」，「采用候选」禁用；「保留原文」仍可用。
- 不出现「第二路」「第 N 行」「草稿」。

### 2.3 差异窗口算法（前端可算，无新接口）

```js
const spans = computeCharSpans(entry.current, entry.candidate); // 现有，app.js:11557
if (!spans.length) { /* 整行替换 */ }
const a0 = Math.max(0, Math.min(...spans.map(s => s.aStart)) - 6);
const a1 = Math.min(entry.current.length, Math.max(...spans.map(s => s.aEnd)) + 6);
const b0 = Math.max(0, Math.min(...spans.map(s => s.bStart)) - 6);
const b1 = Math.min(entry.candidate.length, Math.max(...spans.map(s => s.bEnd)) + 6);
```

- 窗口覆盖**本行所有差异段**，不是只标第一处；同一条判断一次看全。
- 窗口两端被截断时补 `…`；`±6` 是上下文，不是可调参数（避免又出一个设置）。
- 词级（英文）同样按字符窗口，但断词边界向外扩到空格；`computeCharSpans` 已支持不等长。
- 映射到 DOM：`entry.current` 和 `entry.candidate` 都是纯文本；面板自己切片，用 `<mark>` 包差异段；**不要**改正文 DOM 的文本。

## 3. 改二：判决即前进

### 3.1 状态机

```
idle ──点红字 / Enter──▶ judging ──Enter(保留)──▶ judging(下一条)
                          │  └──Space(采用)──────▶ judging(下一条)
                          ├──E──▶ editing ──Esc──▶ judging(同一条, 已改)
                          └──Esc──▶ idle(显示「继续审校」)
judging ──最后一条判完──▶ finished(收尾卡)
```

- **judging**：面板开，当前行蓝，左页图蓝框；工具条不出现「继续审校」。
- **editing**：面板收起，编辑条出现；左页图保持蓝框 + 铅笔角标。
- **idle**：面板关，页面上仍有红/绿；工具条出现「继续审校 ⏎」。
- **finished**：见 §3.6。

### 3.2 键位（这是本单的核心）

| 键 | judging | editing | idle |
|---|---|---|---|
| `Enter` | **保留原文**并下一处 | 段内换行（现有行为） | 打开下一处未审 |
| `空格` | **采用候选**并下一处 | 输入空格 | — |
| `E` | 光标落在差异字上编辑 | — | — |
| `Esc` | 收起面板（停手） | 完成编辑，留在本行 | — |
| `⌘/Ctrl+Z` | 撤销上一判 | 撤销这次编辑 | 撤销 |
| `⌘/Ctrl+Enter` | — | 完成并下一处 | — |

- **必须 `preventDefault`**：空格会滚页、Enter 会触发默认按钮。
- **`Space` 的守卫要严到「面板持有焦点 + 焦点环可见」**：面板 `tabindex="-1"`，打开时 `panel.focus({preventScroll:true})`，给 2px 蓝色焦点环（和左边条同色）。焦点在 `body` / `.reading-stream` / 输入框时，`Space` 一律不接管，照常滚动。**验收：焦点不在面板时按 `Space` 必须滚动，不能写成候选文本。**
- `E` **不是全选整行**：把光标放到第一个差异段的 `aStart`，选中该段（方便直接替换），其余正文不动。
- 编辑时 `Enter` 仍是段内换行（现有行为），不要抢；「完成并下一处」用 `⌘/Ctrl+Enter`。
- 保留/采用都要先写草稿再推进；写失败不推进，并显示「未保存 · 重试」。

### 3.3 「下一帧」怎么发生（判完的下一帧）

1. `draftReading(entry, ack)` 写草稿（**不再 `closeReadingPanel`**）。
2. `rerenderReadingLine(entry)`：旧行变绿（只换这一行的 class/内容，不整页重绘）。
3. 取**当前 key 之后**的下一条未决项；没有就回到第一条未决（回卷）；一条都没有 → finished。
4. 面板 DOM 不删，**只换内容**（避免高度闪动）；`readingPanelKey` 更新。
5. 滚动：把新当前行的顶端放到 `anchor`：
   - 800 高：`anchor = 280`（视口 40%）；
   - 628 高：`anchor = 180`（视口 33%）。
   - 用 `scrollTop = lineTop - anchor`，`behavior:"auto"`，**不要 smooth**（2–3 小时里每次平滑滚动都会晕）。
   - 只在新行不在 `[anchor-1 行, anchor+1 行]` 时滚；相邻行不滚，眼睛不动。
6. 左页图：`updateReadingPage(page_no)` + `drawReadingPdfBox(entry.bbox)`，并把页图内部滚到这一行（不是页顶）。
7. 进度、页内 `3/7`、ETA 同时更新。

> 这一帧是「判完了」最强的反馈：**下一条已经在眼睛的位置**。不要用 toast 盖住正文，不要用动画庆祝。

### 3.4 完成反馈（四个信号，缺一不可）

1. 旧行标记变绿（120ms 内），下划线从 2px 变 1.5px。
2. 面板头出现 `✓ 已保留` / `✓ 已采用` 绿色小胶囊，2.5s 后淡出（截图 F3）。
3. 工具条 `汉字 100/899 → 101/899`、`本页 3/7 → 4/7`（或换页 `1/5`）、ETA 减 1 分钟。
4. 下一条的红字已经在新位置；旧条留在上方可见。

### 3.5 误按与撤销

- `Enter` 的语义变严（从「跳过不记录」变成「记录一次保留」）。这是有意的：静默跳过比误记更糟。
- 每次判决都进撤销栈；`⌘Z` 撤销后：标记回红、进度回滚、面板重新打开被撤销那一条。
- 自动保存：判决后 600ms 防抖提交；失败显示 `未保存 1 处 · 重试`，不挡下一条。草稿仍在 localStorage，刷新不丢。
- **按条保存，不许全局定时器**：`Map<item_key, timer>`；「前进」之前先 `flush` 当前条，否则连判三行只有最后一行落库（`onInlineInput` 的旧教训）。
- **同一 `item_key` 的旧草稿不得覆盖新判断**：断网重连补齐时按时间/版本拒绝旧写；草稿带 `at`，服务端/本地合并以新为准。
- **已定：自动保存放在 P2**；验收是断网状态下判 5 条，重连自动补齐、进度不回退。不做「提交」按钮的退路，不再把保存做成用户动作。

### 3.6 最后一条判完

- 面板关闭，正文末尾出现**收尾卡**（不是「收尾 0/6」）：
  - 汉字判完、标点未判：`汉字 899 处已判完 · 还有 73 组标点 / 724 行，可批量判` + [先判标点]；
  - 都判完：`全部判完 · 可以导出` + [去导出] + [抽检可疑行]；
  - 还有未提交：`3 处未保存` + [重试]。
- 不显示内部六个检查项；只显示「能不能导出」和「还差什么」。

### 3.7 边界

- 下一条在不同页：同帧内换页 + 页图滚动 + 树高亮，不要等第二轮。
- 下一条在跨页段：照常，锚点按行。
- 下一条是标点级（如果标点没批量判）：同样进 judging，面板照常；但建议先批量判标点，收尾卡会提示。
- 面板开着时用户滚走：不自动弹回；面板留在原处，`Esc` 关。滚回来自动恢复当前高亮（现有 `readingPanelKey`）。

## 4. 改三：进度说人话

### 4.1 数字口径

**不设「待判 N 处」这个第三个数。** 工具条只有两条轨：汉字「已判/899」、标点「已判/724 行」；两条都满才算完成。899+724=1623 是数据口径，不搬到界面上做第三个数字。

| 数字 | 来源 | 文案 |
|---|---|---|
| 汉字轨 | `1 - chars_pending / chars_total`（分母 899） | `汉字 100/899` |
| 标点轨 | `1 - punct_pending / punct_total`（分母 724） | `标点 0/724 行` |
| 标点动作 | `punct_groups.undecided_groups / groups` | `标点 73 组`（批量入口） |
| 页内 | 当前页 `unacked` + 当前序号 | `本页 3/7` |
| ETA | 最近 20 条判决间隔的中位数 | 两条轨上方一行：`约剩 1 小时 47 分`（按 8s/条示例，未实测） |

- **ETA 只在前 20 条之后出现**；之前写「判 20 条后估时」，不编。
- 公式：`M = ceil(剩余处数 * median_interval / 60 / 5) * 5`；`M < 20` 写「不到 20 分钟」，`M > 180` 写「3 小时以上」。**永远加「约」**。
- 记录只存本地（`localStorage`），按项目分开；不当作承诺，不写进导出。
- **工具条上没有第三个数字**：不写只减汉字的「待判 N 处」，也不写「剩 1523」；「还剩多少」由两条轨的分子分母回答。899+724=1623 只留在数据口径与收尾卡，不上工具条。
- 标点**不混进**汉字百分比：两条独立轨，各自有自己的分母（899 / 724）；ETA 只按汉字轨估，标点的 73 组在 chip 里单列。
- 只有 `finish_summary.complete` 为真才说「全部判完」；不靠前端算。

## 7. 取舍与不做

| 决定 | 理由 | 代价 |
|---|---|---|
| **不做「一键通过」** | 没看的页等于没审；置信度没有可靠信号（D-042） | 用户仍要逐条判 |
| **不做按分歧等级排序** | 标点级真错率 23.1% > 汉字级 13.2%，排序会误导 | 队列顺序固定 |
| **不做全页逐字高亮** | 页图是位图，只有行 bbox；逐字框要 OCR 字框，数据没有 | 左图只框当前行 |

| **不把「跟随」做成开关** | 同步是默认行为；开关是实现的漏出 | 极端情况下用「显示」关 |
| **不把「提交」做成动作** | 保存是判决的副作用 | 见 §9 的自动保存实现（P2） |
| **不在审校页画块框** | 块框属于页面确认/版心步骤；审校只看当前行 | 需要时「显示」打开 |
| **628 不缩字号** | 这是要坐 2–3 小时的屏，15px 是下限 | 上下文少 1–2 行 |
| **不引入前端框架** | 项目原则 | 无 |

**自动保存（已定，P2）**：判决即写；按 `item_key` 防抖、前进前 flush、旧草稿不得覆盖新判断；界面上的「已保存 / 未保存」必须真实。验收：断网判 5 条，重连自动补齐、进度不回退。
