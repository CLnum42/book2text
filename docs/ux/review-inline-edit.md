# 正文审校：就地编辑 + 修订视图 + 工具栏重排

> 状态：设计稿（未改产品代码）。基线 `main@523e70c`（字级差异、标点分组、连续流已实现）。
> 依据：用户 2026-10-28 原话（A 就地编辑与修订模式 / B 工具栏重命名与精简）、真机截图里那排 11 个控件。
> 产出：本文 + `review-inline-edit-mockup.html` / `.png`（三档宽度 + 修订三档各一帧）。
> **一个推荐方案。** 复用：现有草稿层（localStorage + `readingDrafts`）、`diff_ack`、字级 spans、事件表 `before/after`。

---

## 0. 用户要求（验收标准）

> "不需要专门加一个『自己改』的按钮。直接鼠标点击文本的具体位置，就可以自主编辑（数据层面以修订模式保存，可以选修订视图：全部标记、简单标记、无标记）。不仅可以修改需审校的内容，也可以改变其他正文内容（两个引擎都出错的情况）。"

> "上方一系列按钮功能上很不直观，该重命名的重命名，该精简的精简。"（现状 11 个控件，其中"标点差异 2351 行 · 514 组"出现两次）

---

## 1. 结论

1. **单击即改，取消"自己改"按钮。** 单击正文任意位置 = 落光标 + 该行成为当前行（左侧 PDF 同色高亮）；单击红/绿**标记** = 打开候选面板（标记优先于光标）。一个手势同时满足"看"和"改"，因为"当前行"就是光标所在行。
2. **修订三档是纯视图开关**：全部标记（删除线 + 下划线 + 来源角标）/ 简单标记（终稿 + 左边距改动条）/ 无标记（终稿，无痕）。默认"全部标记"。
3. **两种改动用同一个文本表达**（删除线 / 下划线），来源用**角标**（`B` 候选 / `✋` 手改）区分，因为颜色已经承担"增/删"，再加一维必然崩。
4. **草稿 = 块级文本补丁**（`base_text → new_text` + ack + 来源），存 localStorage，刷新/切页/关应用都不丢；提交一次写库，变更进事件表。**不做"待接受的修订"状态**（理由见 §6.3）。
5. **工具栏 11 → 5 组**：导航 / 进度（含唯一的标点入口）/ 下一处 / 筛选与显示 / 提交与 ⋯。删掉的入口全部有归处（§8）。

## 2. 就地点哪里就能改

### 2.1 手势与命中规则

| 你点的东西 | 发生什么 |
|---|---|
| 正文里的普通文字 | 落光标（可编辑），该行成为当前行，左侧 PDF 滚到该行并同色高亮 |
| 红字 / 绿字（差异标记） | 打开该处的候选面板（不落光标）；该行同时成为当前行 |
| 行尾的来源角标 `B` / `✋` | 打开该处的候选面板（查看来源） |
| 空白（段后、页边） | 无事发生；只关闭面板 |
| 双击 | 浏览器原生选词（整词替换用），不额外绑定动作 |
| 移动端/触屏 | 单击 = 选中行；长按 = 进入光标（避免一碰就出键盘） |

**为什么不用"双击编辑"**：双击已经是"选词"，再抢一个手势会互相打架；而"单击=看、双击=改"会让 1733 次的审校循环每次多一次点击——这正好是用户想省掉的那一次。单击落光标不会改任何数据，误触的代价只是多一个光标，`Esc` 即退。

### 2.2 编辑单位：块，块边界是硬边界

- 连续流里，**一个块 = 一个 contenteditable 区域**（单块段就是整段；跨页段由多个块拼成，视觉上连续、编辑上以块为界）。
- **块边界不可跨越**：删除到边界即停；在边界处按 Backspace 不会把上一块的字吸进来。边界处有一条 0.5px 的极淡竖线（hover 时才显示 `跨页` 小标），点它可以去单页审校处理结构（合并/拆分）。
- **回车 = 段内换行**（写进 `block.text` 的 `\n`，仍是同一个块）；要拆成两个块，走单页视图的"在光标处拆分"。
- 为什么不是"整段/整条流一个编辑区"：保存时要把改动映射回带 `line_index` 的块文本，一个编辑区跨多个块时，块边界处的增删无法可靠归属（还会把 `diff_ack` 的"按行"语义打乱）。

### 2.3 编辑时不能丢的三件事

1. **行身份**：每一行有 `data-block-id` / `data-line-index`；编辑只是改文本，行不被重建（重渲染只发生在提交/切页）。
2. **当前行**：光标所在行永远有"当前"样式（左边 2px 琥珀竖条 + 浅底），左侧 PDF 同步高亮该行框。
3. **未提交标记**：只要该块有草稿，行尾就有 `草稿` 角标（文字），切页回来仍在。

## 3. 修订视图三档

三档只改**显示**，不改数据、不改草稿。默认「全部标记」。

### 3.1 全部标记（All Markup）

```
维太平不易之元，蓉桂竞芳之月，无可奈何之日，怡红院浊玉，谨以群花之蕊、冰鲛之〔殼〕〔縠〕，沁芳之泉…
                                                                    └删─┘ └插┘
                                                                           B
```

| 元素 | 画法 |
|---|---|
| 删除 | 红删除线 + 红 8% 底；字仍在原位（不挪动阅读节奏） |
| 插入 | 绿下划线 + 绿 8% 底 |
| 替换 | 删除与插入相邻（`殼縠`），不写成"→" |
| 来源角标 | 行尾 9px 小块：`B`（采用第二引擎）/ `✋`（手改）；`↩`（保留原文，无文本变化，只在差异标记处显示灰点） |
| 待审红字 | 与修订标记**同时**存在时：该行已被改动 → 红字立刻转成"已处理"（消失），只留修订 |

### 3.2 简单标记（Simple Markup）

```
│ 维太平不易之元，蓉桂竞芳之月，无可奈何之日，怡红院浊玉，谨以群花之蕊、冰鲛之縠，沁芳之泉…
└ 左边距 2px 琥珀条 + 小三角：这一行/段被改过
```

- 文本显示**终稿**，行内不画删除线/下划线；
- 改动过的行在左侧**页边**（不是行内）画一条 2px 琥珀竖条，段首加一个 `▸` 小三角；点三角 → 该段临时切到"全部标记"；
- 适合"通读一遍，看看哪里动过"。

### 3.3 无标记（No Markup）

- 只显示终稿，没有任何痕迹；
- 草稿仍在（顶部 `未提交 N` 还在），只是不画。

### 3.4 与旧「成稿」的关系

旧的「成稿」= 隐藏待审红字 + 隐藏草稿标记。新模型把它拆成两个正交开关：

| 开关 | 位置 | 作用 |
|---|---|---|
| 待审红字（勾选） | 显示 ▾ | 取消勾选就是旧的"成稿"（纯文本通读） |
| 修订标记：全部 / 简单 / 无 | 显示 ▾ | 只影响"我改过的地方" |

所以「成稿」按钮被吸收，不再单独存在。

## 4. 修订怎么画（各种改动形态）

| 改动 | 全部标记 | 简单标记 | 无标记 |
|---|---|---|---|
| 改 1–3 字 | `〔旧〕〔新〕` 删除线 + 下划线 | 终稿 + 边条 | 终稿 |
| 改一整句（连续 > 12 字） | **折叠成一行摘要**：`⟦替换 18 字 · 点击展开⟧`，展开后上行删除线、下行下划线 | 终稿 + 边条 | 终稿 |
| 删一段 | 段落位置留占位：`¶ 已删除 32 字 · 展开`（不占正文行高） | 边条 + 极小的 `−` | 不显示 |
| 新增一段 | 绿下划线 + 左边距 `+` | 边条 + `+` | 正常文本 |
| 采纳候选 | 同"改 1–3 字"，角标 `B` | 边条 | 终稿 |
| 保留原文 | 无文本变化；差异标记变灰点 `↩`（仍在原位） | 无 | 无 |
| 合并/拆分块、改类型 | **不在这里做**（结构操作去单页视图） | — | — |

- 折叠阈值 12 字：超过就不是"改字"，而是"重写一句"，逐字配对会把一行撑成两行、阅读全断。
- 删除段落用占位而不是直接消失：审校期必须能看见"我删了什么"，否则删错了无从发现。

## 5. 撤销与出口

| 场景 | 操作 | 粒度 |
|---|---|---|
| 正在打字 | `⌘/Ctrl + Z` | 浏览器原生**字级**撤销（contenteditable 自带） |
| 离开该行之后 | 工具条 `⋯ → 撤销上一条草稿` | **行级**（一条草稿 = 一行/一块的补丁），可连续撤销 50 步 |
| 只想撤这一行 | hover 行尾的 `↶` | 该行还原到 base_text，草稿删除 |
| 全不要了 | `⋯ → 放弃全部未提交（3 处）` | 二次确认，列出 N 处 + 时间 |
| 已经提交错了 | `⋯ → 撤回上次提交` | 走现有事件表撤销（块级） |

- **误操作的三道闸**：单击只落光标（不改字）→ 输入后才产生草稿 → 提交才写库。最坏情况是"输入了几个字忘了"，`放弃全部未提交` 一步还原。
- 编辑态与非编辑态的键盘分工见 §9（这是"⏎ 下一处"与"⏎ 换行"不打架的关键）。

## 6. 草稿、修订与提交

### 6.1 草稿的数据形状

```js
draft = {
  block_id, page_no,
  base_text,          // 提交前的块文本（服务端版本，用于算修订与还原）
  new_text,           // 现在的块文本
  sources: { "2": "B", "5": "user" },   // line_index → 来源（B = 采用候选，user = 手改）
  acks: { "7": "adopted", "9": "kept" },// 裁决记录（提交时一并写 diff_ack）
  at,                 // 时间
}
```

- 修订显示 = `base_text` 与 `new_text` 的字符级 diff（复用现有 LCS），按行投影；
- 不存"修订对象"数组，**只存前后文本**：这样"撤销这一步"就是删掉这条草稿，不需要反向应用。

### 6.2 不丢的三层

| 场景 | 结果 |
|---|---|
| 切页 / 滚动 | 草稿在内存 Map 里，行尾 `草稿` 角标仍在 |
| 刷新 / 关标签页 | localStorage（沿用现在的 `readingDraftStorageKey`），重开弹 `有 3 处未提交（10-28 09:41）[恢复] [丢弃]` |
| 关应用 / 崩溃 | 同上；localStorage 是同步写的，最多丢最后一个字符的 500ms 防抖窗口 |
| 提交失败 | 该块留在草稿，列出失败原因（"这一块在别处改过"→ 重新载入该块再试） |

### 6.3 "数据层面以修订模式保存"的落地方式（明确取舍）

- **提交时**：逐块 `PATCH` 文本 + `diff_ack`，事件表已经存 `before_json / after_json`（现有实现），所以**修订记录天然持久**，不需要新表。
- **不做"待接受的修订"状态**（Word 那种"修订挂着、需要接受/拒绝"）：
  - 导出必须永远是干净文本，库里挂着一堆未接受的修订，等于给导出埋雷（说明书 1.5：不显示假状态、导出可验证）；
  - 需要一套新的状态机（每个修订的接受/拒绝状态）与导出闸门，成本远大于收益。
- 想回看"我改了什么"，提供一个只读的 **改动记录**（`⋯ → 改动记录`）：按时间列出本次会话已提交的块级 before→after 与草稿。

## 7. 工具栏重排

### 7.1 现状（用户截图，490 页项目）

```
◀ 第35页 ▶ | 下一处未审 ⌘↵ | 汉字 0/2084  另有标点 2351行·514组(已判0组) | 未提交1 |
跟随 | 成稿 | 定向补审 | 中文按字/英文按词 | 全部差异▾ | 标点差异 2351行·514组 |
撤销 | 提交1处改动
```

问题：① 11 个控件平铺，无主次；② "标点差异 2351 行 · 514 组"出现两次（小字 + 按钮）；③ 三个视图开关（跟随/成稿/筛选）混在动作里；④ "汉字 0/2084" 读者不知道分子分母是什么；⑤ "定向补审""中文按字/英文按词"是内部术语。

### 7.2 新结构：5 组，一条 44px

```
┌ 导航 ──────┬ 进度 ────────────────┬ 定位 ──────────┬ 筛选/显示 ┬ 动作 ────────┐
│ ◀ 第 35 页 ▶ │ 已审 0 / 2084 字 ▓░░░ │ [下一处未审 ⏎] │ 筛选▾ 显示▾│ [提交 1 处] ⋯ │
│             │ 标点 514 组 ↗        │                │           │              │
└─────────────┴──────────────────────┴────────────────┴───────────┴──────────────┘
```

- **导航**：页号可点（输入跳转）；◀ ▶ 翻页。
- **进度**：`已审 0 / 2084 字` + 细进度条；下面一行 `标点 514 组 ↗` —— **合并了重复的两个计数**，并且它是唯一入口（打开批量裁决面板），tooltip 写"2351 行 · 514 组 · 已判 0 组"。
- **定位**：`下一处未审 ⏎` 蓝色主按钮，距左约 1/3 处（视线最容易落）。
- **筛选 / 显示**：两个菜单按钮。
  - `筛选 ▾`：全部差异 / 只看汉字级 / 只看未审。
  - `显示 ▾`：☑ 待审红字 / 修订标记：全部·简单·无 / ☑ 跟随滚动。
- **动作**：`提交 N 处`（有草稿时变琥珀主按钮，无草稿时禁用并写"没有待提交的改动"）+ `⋯`（撤销上一条草稿 / 放弃全部未提交 / 撤回上次提交 / 可疑行 / 改动记录 / 快捷键帮助）。

### 7.3 重命名表

| 旧 | 新 | 为什么 |
|---|---|---|
| 汉字 0/2084 | **已审 0 / 2084 字** | "汉字"是类别不是进度；分子分母没有说明 |
| 另有标点 2351 行·514 组（小字） | **标点 514 组**（进进度区，tooltip 给行数） | 与按钮重复；行数不是决策单位，组才是 |
| 标点差异 2351 行·514 组（按钮） | **标点 514 组 ↪ 批量判**（唯一入口） | 同上；且必须露出"可以一次判几百行"这件事 |
| 成稿 | **显示 ▾ → 待审红字（取消勾选）** | "成稿"含义模糊，且与"无标记"重叠 |
| 跟随 | **显示 ▾ → 跟随滚动** | 视图开关不配占按钮位 |
| 定向补审 | **⋯ → 可疑行（两路一致但可能都错）** | 内部术语；括号里说清它是什么 |
| 中文按字 / 英文按词 | **删除**（进 `?` 帮助与"筛选"的 tooltip） | 是说明文字，不是操作 |
| 全部差异 ▾ | **筛选 ▾** | 与"显示"成对，语义更准 |
| 撤销 | **⋯ → 撤回上次提交** | 与"字级撤销/草稿撤销"区分；原来那个撤销的其实是已提交的块 |
| 提交 1 处改动 | **提交 1 处** | 短，位置固定在最右 |

### 7.4 删掉的入口都在哪（不许藏死）

| 功能 | 新入口 |
|---|---|
| 成稿（纯文本通读） | 显示 ▾ → 取消"待审红字" |
| 跟随滚动 | 显示 ▾ → 跟随滚动 |
| 定向补审 | ⋯ → 可疑行 |
| 中文按字/英文按词 | `?` 帮助面板 + "筛选" tooltip |
| 标点批量 | 进度区「标点 514 组」 |
| 撤销已提交 | ⋯ → 撤回上次提交 |
| 红字筛选 | 筛选 ▾ |

### 7.5 三档宽度与高度

| 档 | 排布 |
|---|---|
| **≥1320** | 全部一行：导航 + 进度 + 标点 + 进度条 + 下一处 + 筛选 + 显示 + 提交 + ⋯ |
| **1120–1319** | 页号缩成 `35`；进度 `0/2084`；标点按钮只留 `标点 514`；进度条缩短到 80px |
| **<1120** | 两段式：`◀ 35 ▶ · 0/2084 ▓ · [下一处]` + 右侧 `显示▾ 提交 ⋯`；标点、筛选收进 ⋯ 与 显示▾ |
| **高度 ≤ 700（628 预算）** | 工具条压到 **40px**（现有媒体查询已如此）；预检条（有警告时）28px；其余给正文 |

**628 高度预算**：40 工具条 + 28 条件性预检条 + 560 正文区（左树/PDF/正文各自内部滚）= 628。提交在工具条里，所以**不需要底部再放一条**（比上一版省 48px）。

## 8. 键盘

| 焦点 | `↵` | `⌥↵` | `⌘/Ctrl + ↵` | `Esc` | `⌘/Ctrl + Z` |
|---|---|---|---|---|---|
| 正文里没有光标（浏览态） | **下一处未审** | — | 提交全部草稿 | 关面板 | 撤销上一条草稿 |
| 正文编辑中（有光标） | **段内换行** | **收草稿并跳下一处** | 提交全部草稿 | 收草稿并退出编辑 | 字级撤销（浏览器原生） |
| 候选面板里 | 采用第二路 | — | — | 关面板 | — |
| 在筛选/显示菜单里 | 选中 | — | — | 关闭菜单 | — |

- 关键：**`↵` 的含义由"有没有光标在正文里"决定**，这是唯一的歧义来源，也是能同时满足"⏎ 下一处"和"⏎ 换行"的唯一做法。
- 编辑态下的"下一处"迁移到 `⌥↵`，按钮上的提示同步改成 `下一处未审 ⌥↵`（编辑时）/ `⏎`（浏览时）——按钮文字随焦点变，不让用户猜。
- 其余保留：`[` `]` 上一处/下一处（浏览态）。

## 9. 验收（可截图核对）

1. 单击正文任意字 → 光标落点、该行成为当前行、左侧 PDF 同色框高亮；不产生任何写入。
2. 单击红字 → 打开候选面板，光标不落；再点旁边的普通字 → 面板关闭、光标落下。
3. 输入 3 个字 → 行尾出现 `草稿` 角标 + 顶部 `未提交 1`；修订视图"全部标记"下能看到删除线与下划线。
4. 切到"简单标记"：行内标记消失，左侧出现 2px 琥珀竖条与 `▸`；点 `▸` 临时回到全部标记。
5. 切到"无标记"：终稿，无痕；顶部 `未提交 1` 仍在。
6. 取消"待审红字"：红字消失（旧"成稿"）；勾回来红字重现。
7. 改一整句 20 字 → 折叠成 `⟦替换 20 字 · 点击展开⟧`；展开后上行删除线、下行下划线。
8. 删掉一段 → 留下 `¶ 已删除 32 字` 占位；点展开可看原文。
9. 编辑中按 `↵` 换行、按 `⌥↵` 收草稿并跳到下一处；浏览态按 `↵` 跳到下一处。两者截图各一张。
10. 撤销：编辑中 `⌘Z` 只退一个字；离开后 `⋯ → 撤销上一条草稿` 整行还原；`放弃全部未提交` 二次确认后全清。
11. 刷新页面 → 提示恢复 3 处；关应用重开 → 同上。
12. 提交 3 处 → 写库、角标消失、进度 +3；`⋯ → 撤回上次提交` 能把这次撤回。
13. 工具栏：1440 一行放得下（5 组）；1200 页号缩为数字；1000 下为两段式；三档都不出现横向滚动。
14. 628 高度：工具条 40 + 正文 588，body 无滚动条；左树/PDF/正文各自内部滚。
15. 界面里不再出现"汉字 0/2084""定向补审""中文按字/英文按词""成稿"四个词。

## 10. 风险与未验证

- **contenteditable 的跨块边界**：Chrome 下 `display:inline` 的可编辑块在边界处的删除行为不完全一致；需要 Builder 在实现时用"边界不可跨越"的守卫（`beforeinput` 里拦截），并在 Chrome / Edge / Safari 各测一次。
- **字符级 diff 的性能**：一段 20–40 行、每行 30 字，`base_text` 与 `new_text` 一次 diff 是 1200 字规模，单段可忽略；但整页 4–6 段同时渲染时要注意只 diff 有草稿的段（其余直接渲染）。需要实测。
- **折叠阈值 12 字**是按"一行 46 字"估的，实际可能要 10 或 16；真书跑一遍再定。
- **"待审红字"与修订标记同时可见**：一条差异被自由改写后，红字去哪（立刻消失 / 保留到提交）需要一次实测确认——本文定"立刻消失"，因为它已不再是待审项。
- **未验证**：触屏长按进入编辑的分歧（iOS Safari 的 callout），需要真机。
