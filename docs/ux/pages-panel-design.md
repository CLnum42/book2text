# 页面视图右栏：层级与顺序重构（设计规范）

> 状态：设计稿。用户评价："功能引导不够直觉化"。
> 依据：说明书 7.3（页面视图）、workflow 阶段 1–5 与 2.6（界面要求）、真机截图
> `panel-four-headings.png`、`panel-four-sections.png`、`panel-mixed-types.png`、`margin-auto-pages-panel.png`。
> 目标屏幕：**14 寸，右栏可视高约 628px**（内容高 1600px+）。
> **不改 `backend/`、不改开发日志**。静态稿：`pages-panel-mockup.html`；渲染图：`pages-panel-mockup.png`。
> 不在范围内：新增功能、改后端、改版心算法、改页码算法。

---

## 0. 结论（三句话）

1. 右栏现在是一份**按功能分类的清单**，要改成一份**按工作顺序的操作面板**：先把"下一步做什么"顶到眼前，再让人往下调参数。
2. 结构：**顶部选择摘要（固定）+ 四个分区手风琴（一次只开一个，每个标题自带一句状态）+ 底部固定主操作条**。这样 628px 里固定部分 ≤ 280px，任何分区展开后都 ≤ 620px，**全程不需要滚**。
3. 全书级动作用数字和位置明确区分开（放在分区底部的"全书…"行），不再和"所选页"动作混在一列按钮里。

被否掉的替代方案：

- **横向 Tab（四个分区变四个页签）**：省高度，但四个分区的状态全被藏起来，用户要逐个点才知道"哪一步没做"——正好违背"引导直觉化"。
- **单页长滚动 + 锚点导航**：就是现状的加长版，问题 1、2 一点没解决。
- **向导（Wizard，一步一步弹）**：把"随时改一个参数"变成了打断；说明书要求参数随时可调、状态可回看。

## 2. 结构：三段式

```
┌──────────────────────────── 292px ────────────────────────────┐
│ 已选 12 页 · 第 87–98 页                                  ✕   │  28  固定
│ 类型 正文 10 · 前置 2 · 未确认 5        [统一设为正文]         │  26  只在混合时出现
├───────────────────────────────────────────────────────────────┤
│ ✓ 页面类型   12 页已确认 · 全书 0 / 267                    ▾  │  36
│ ▸ 版心       自动 10 · 自定 1 · 不适用 1                      │  36
│ ▸ 页码（可跳过）  右下/左下 · 已填 255 · 异常 12              │  36
│ ▸ 识别设置   双引擎 · 300 DPI · 给候选                        │  36
│ ▸ 高级操作                                                    │  30
│                                                               │
│  （展开的那一个分区体，≤ 340px）                                │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│ [ 识别所选正文 10 页 ]                                  [⋯]   │  56  固定（sticky）
└───────────────────────────────────────────────────────────────┘
```

三条硬规则：

1. **手风琴**：同一时刻只展开一个分区；展开新的自动收起旧的（用户手动点开的意图优先，不做动画，200ms 内完成即可）。折叠状态按项目记在 `localStorage`（现有机制保留，键名换成 `panel.accordion`）。
2. **固定区预算**：顶部 ≤ 54px + 四个头 144px + 高级 30px + 底条 56px + 内边距 24px = **≤ 308px**；给展开体留 **≥ 320px**。任一分区展开后总高 ≤ 620px，**628px 内零滚动**（§5 有实测方法）。
3. **每个分区头必须回答一句**："这一步现在是什么状态"，而不是只印标题。句式只有两种：
   - 状态式：`12 页已确认 · 全书 0 / 267`
   - 配置式：`双引擎 · 300 DPI · 给候选`
   末尾放一个 12px 的状态记号（✓ 完成 / ! 要处理 / · 未开始），**文字在前、记号在后**，色盲也读得懂。

## 3. 四个分区

### 3.0 顺序与命名

| 序 | 名称（旧名） | 一句话职责 | 能跳过？ |
|---|---|---|---|
| 1 | **页面类型**（页面设置） | 这页算不算正文 | 不能 |
| 2 | **版心**（页面准备） | 正文区域在哪 | 不能（页级"不适用"是合法终态） |
| 3 | **页码（可跳过）**（页码设置） | PDF 页 ↔ 印刷页的映射 | **能**（workflow 阶段 4 是旁路） |
| 4 | **识别设置**（识别设置） | 用哪个引擎、什么 DPI | 不能 |

顺序按 workflow 阶段 1→2/3→4→5 排，与现状一致，**不改顺序，只改名字与内容层级**。给 1–4 编号是有意的：它确实是顺序，而且 1、2 是 4 的前置；3 明确标"可跳过"，避免编号造成"必须先做完页码"的误解。

### 3.1 顶部选择摘要（固定，不随内容滚）

| 状态 | 第一行 | 第二行（条件出现） |
|---|---|---|
| 未选择 | `未选择页面` + 一行**下一步**：`267 页未确认 → 先确认页面类型` | 无 |
| 选中 1 页 | `第 87 页 · 正文 · 未确认` | 类型按钮不重复（在分区 1 里） |
| 选中 N 页 | `已选 12 页 · 第 87–98 页` | `类型 正文 10 · 前置 2` + `[统一设为正文]` |
| 选中 N 页且类型一致 | `已选 12 页 · 第 87–98 页` | `类型 正文`（灰字，一行） |

- 第二行只回答"这一批**齐不齐**"，齐就一行灰字，不齐才给动作。
- `✕` 清空选择（现有）。
- 范围超过 12 页时第一行写 `已选 42 页 · 第 3–9、87–120 页`（两段以上只显示首尾，`title` 给全量）；点击范围文字 → 展开成现有「选择范围」输入（P2）。
- **未选择时的"下一步"是全书级引导，只出现一条**，按 §4 的状态表选；它不是状态栏，不重复 `setupbar` 的计数。

### 3.2 页面类型

折叠摘要：`12 页已确认 · 全书 0 / 267`（选中时左半句按选择；未选时只留右半句）。

```
已选 12 页 · 类型：正文 10 · 前置 2          （只在混合时出现，与顶部重复则省略）
┌──────────────┬──────────────┐
│ ● 正文        │ ○ 正文排除    │
├──────────────┼──────────────┤
│ ○ 目录        │ ○ 前置        │
├──────────────┼──────────────┤
│ ○ 后置        │              │
└──────────────┴──────────────┘
ⓘ 只有「正文」进识别与语料；确认只是状态，不拦识别。
[ 确认所选 12 页 ]                       ← 主按钮
3 条建议（把握较大）        [ 查看 ]      ← 折叠区，展开才占位
全书…  确认全部未确认页（267）            ← 次要、带数字、贴底
```

- 类型选择按钮**保持现状**（点一下就改所选，不弹窗），但把"当前类型 / 建议类型"的两种标记放在按钮内（现有 `.ptype` 已实现），不要新增图例。
- `确认所选` 与类型按钮的关系要写清楚：**它是"确认状态"的动作**，不是改类型。未选时禁用并在按钮下给一行 `先在左边点一页`。
- 建议列表默认折叠：一页最多 3–5 条，展开后会把分区撑到 340px 以上，所以它自己是 `<details>`，展开时该分区内部滚动（此时允许分区体滚，不滚整个面板）。

### 3.3 版心（四来源）

折叠摘要：`自动 10 · 自定 1 · 不适用 1`（全书口径，未选时）；选中时：`12 页：自动 10 · 沿用 0 · 自定 1 · 不适用 1`。

展开态（单选）：

```
来源
┌────────────────────┬────────────────────┐
│ ● 每页自动拟合       │ ○ 沿用全局          │
│   用本页检测行拟合    │   7.4 / 6.8 / 92.0 / 93.2 │
├────────────────────┼────────────────────┤
│ ○ 本页自定义         │ ○ 不适用             │
│   拖动边框或填四边    │   整页插图、插页     │
└────────────────────┴────────────────────┘
当前生效  左 7.4% · 上 6.8% — 右 92.0% · 下 93.2%
          来源：本页拟合 · 把握 中 · 12 行检测    [在页面上拖动]
! 这页有 3 行正文落在版心外，可能拟合不准。
把本页设为全局              回到全局
该书…  全部改为每页自动拟合（12 页）    推算默认版心
```

展开态（多选，来源不一致）：

```
来源分布  自动 10 · 沿用 0 · 自定 1 · 不适用 1
把所选 12 页改为：  [自动拟合] [沿用全局] [本页自定义] [不适用]
  ⚠ 会覆盖 1 页的自定义版心（可撤销）
```

要点：

- **四来源用 2×2 卡片**（不是 4 个按钮排一行）：260px 宽放 4 个按钮每个只有 62px，字会被截；2×2 每张 126px，能放"名称 + 一句后果"。
- **当前项不只用颜色**：实心圆点 + 加粗 + 1.5px 边框；灰度下也分得清（沿用上一单的教训）。
- **"当前生效"这一行是新增的关键信息**：四来源回答"怎么来的"，这一行回答"最后用的是哪四边"。`auto` 在行数不足 3 行时沿用全局，这一行必须显示**实际生效值**和兜底原因（"本页有效行 2 行，沿用全局"）。
- 覆盖类操作（批量改来源、把本页设为全局）**必须二次确认并写明影响面**（"覆盖 1 页自定义"），完成后给可撤销提示条——沿用说明书 7.7。
- 全书动作降级为分区底部一行：`全部改为每页自动拟合`、`推算默认版心（兜底）`。它们不常点，不该占主按钮位置。
- `推算默认版心` 只在"没有任何生效版心"时提升为可见按钮，否则收进 `该书…` 展开区。

### 3.4 页码（可跳过）

折叠摘要：`右下/左下 · 已填 255 · 异常 12`；没模板时：`未定位 · 可跳过`。

```
模板   右下（奇数页）/ 左下（偶数页）
已填   255 / 267 页（剩余 12 页待核对）
异常   12 页   无候选 5 · 溢出 3 · 重复 4
[ 定位页码… ]                    ← 主按钮（打开现有弹窗）
[ 核对 12 页异常… ]              ← 有异常才出现，异常数写在按钮上
ⓘ 这一版只做「模板 → 自动填充 → 异常列表」；逐页手动改映射在下一版。
未定位也能导出，预检会提示，manifest 会记录。
```

- **"未定位也能导出"必须写出来**：否则用户以为页码卡住导出（workflow 明确说不拦导出）。
- 没有异常时删掉第二个按钮，不留禁用态。
- 摘要里的"可跳过"三个字保留在分区标题上，这是它区别于其他三步的唯一标记。

### 3.5 识别设置

折叠摘要：`RapidOCR · 200 DPI · 中文`（双引擎时：`双引擎 · 300 DPI · 给候选`）。

```
引擎   ● RapidOCR（默认）   ○ Apple Vision   ○ 双引擎比对
       双引擎 = 第一路识别 + Apple Vision 逐行复核，耗时约 2 倍
DPI    ● 150（更快）  ○ 200（默认）  ○ 300（更清晰）
       200 DPI 单页峰值内存约 2.7 GB
语言   [ 中文（默认） ▾ ]
策略   [ 只标分歧（默认） ▾ ]         ← 仅双引擎时出现
ⓘ 实测：整页 CER 200 DPI 1.08% / 300 DPI 1.31%；第二引擎整页 2.16%，只作分歧线索。
```

- **「开始识别」从这里移走**，到底部固定条（它是动作，不是设置）。
- 引擎 / DPI / 语言是三个互斥组，用**单选组**而不是 `<select>`：三选一的东西展开成一行比下拉少一次点击、多一层可见性（260px 下 `RapidOCR / Apple Vision / 双引擎` 三行竖排；DPI 三行竖排）。
  - 具体：引擎 3 行 × 24px = 72；DPI 3 行；语言保持下拉（选项多、少改）。
- "跳过已识别页"是**动作的参数**，跟着底部按钮走，不放这里（现有 `selection-skip-recognized` 移到底条 `⋯` 或按钮左侧小勾选）。

### 3.6 高级操作

只留第二引擎复核：

```
▸ 高级操作
   复核所选（跳过已复核 ☑）  复核全部未复核页（63）
```

其他三项搬家：`全选（当前筛选）`→ 顶部摘要的 `⋯`；`在审校中打开`、`分派审校…`→ 底部条 `⋯`（这两项是"对当前选择做什么"，与主操作同族）。

---

## 4. 底部固定条（sticky）

高度 56px，两条信息：**主按钮 = 对当前选择最重要的一件事**；`⋯` = 其余动作。

| 状态 | 主按钮 | 说明 |
|---|---|---|
| 未选择，有未识别正文页 | `识别全部未识别页（204）` | 全书动作，但它是此时的"下一步"，允许当主按钮 |
| 未选择，全部识别完 | 禁用 `没有待识别的页` | 禁用 + 一行原因，不显示假按钮 |
| 选中 N 页，其中 M 页是正文且未识别 | `识别所选正文 M 页` | **只算正文**；按钮下方一行 `另 2 页不是正文，会跳过` |
| 选中，已全部识别 | `重新识别所选 M 页` | 红色系次要按钮？不：保持蓝色主按钮，但需二次确认（会替换自动结果） |
| 选中，含手工改过的块 | 同上 + 提示 `其中 3 块人工改过，重新识别不会自动覆盖` | 说明 R2 规则，避免误解 |

`⋯` 菜单固定三项：`在审校中打开（所选）` / `分派审校…` / `全选当前筛选结果（267）`。

**为什么主按钮可以是全书动作**：用户没选页时，唯一有意义的动作就是"把没做的做完"。规格 7.3 要求右栏在未选时给"建议的下一步"，这正是它。

## 5. 14 寸（628px）不滚动的做法

| 手段 | 具体 | 省下 |
|---|---|---|
| 手风琴，一次只开一个 | 四个分区体不同时存在 | 视口里最多 340px |
| 固定区压缩 | 头 36px、高级 30px、顶部 ≤54px、底条 56px | 345 → **≤308px** |
| 删常驻说明 | 8 段 hint → 8 个 ⓘ + 4 句"后果句" | ≈240px |
| 删 tipbox | 移进空状态 | 60px |
| 删重复计数 | `setup-summary-detail` 删除 | 40px |
| 建议 / 进阶项做成嵌套折叠 | 页面类型的"建议"、版心的"该书…" | 40–120px |

**高度预算表（628px）**

| 区块 | 高 | 累计 |
|---|---|---|
| 顶部摘要（两行，含混合类型行） | 54 | 54 |
| 页面类型头 | 36 | 90 |
| 版心头 | 36 | 126 |
| 页码头 | 36 | 162 |
| 识别设置头 | 36 | 198 |
| 高级操作头 | 30 | 228 |
| 内边距（上下各 12） | 24 | 252 |
| 底条 | 56 | **308** |
| **剩余给展开体** | **320** | 628 |

各分区体实测预估（按 §3 排布）：页面类型 ≈200（建议折叠时）/ 版心 ≈240 / 页码 ≈150 / 识别设置 ≈210——**全部 ≤320，即任一分区展开时都不需要滚**。

**测量方法（Builder 验收用）**：DevTools 设备模式设 `1440×758`（与截图同尺寸），把面板视口设为 628px，逐个展开四个分区，读 `.panel` 的 `scrollHeight ≤ clientHeight`；超了就是没达标。

**退路**：若某分区（如页面类型 + 建议全展开）确实超过 320px，只允许**该分区体内部滚动**（`overflow:auto` 加顶部渐隐），不允许整栏滚动——因为整栏滚动会把底条之外的分区头滚出视野，用户又要重新找位置。

## 8. 验收清单（可截图核对）

1. 未选 / 单选 / 多选一致类型 / 多选混合类型，四种状态下顶栏文字各不相同，且与选择一致。

3. 主按钮在任何状态下都在视口内（滚到面板底部也可见），且文案里的页数与左侧选择一致。

10. 未选时只出现**一条**"下一步"引导，不重复 `setupbar` 的计数。

## 9. 未验证 / 风险

- **628px 是估算的视口高**（按 14 寸屏减顶栏、筛选条、底栏推算）。规范用的是相对预算（固定 ≤308、展开体 ≤320），换屏后仍成立，但需要在真机 1440×758 上量一次。
- **版本冲突**：Builder 正在改版心（页面级自动拟合、四来源），本文与那批改动的边界是"版心的算法与数据不动，只重排它的界面表达"；若他的四来源命名不同（`auto/inherit/custom/none` 已存在），以本文的中文名为准。
- **未验证**：`<details>` 手风琴 + `sticky` 底条在 1180px 断点以上的组合是否有滚动容器冲突（`.panel` 现在是 `overflow:auto`，sticky 需要它作为滚动容器，通常可用，但要实测）。
- **未验证**：混合类型时"统一设为正文"是否会意外把"正文排除"的页改成正文（语义上应该可以），需要按后端实际行为确认后再定文案。
