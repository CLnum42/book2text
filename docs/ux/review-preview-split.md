## 0. 结论（先看这七条）

1. **一页一个任务。** 审校页只回答「这一处两路不一样，留哪个」；预览页只回答「成品长这样，哪里还要改」。预览页**不画任何差异标记**，审校页**不画成品段落**。
2. **左图只标差异字，不填色。** 现状是「每条差异行画一个黄底行框，行内再画红底色块」（`reading-view.js:3793`、`app.css:2509-2545`）——两层填充压住字，用户当然看不出差在哪。新规则：**任何标记都不覆盖字身**，用下划线 / 双线 / 竖线 / 虚线四种形状，颜色只做辅助。
3. **对应关系靠「页内编号 + 焦点环 + 2.5× 原图」三件套**，不靠用户在两栏之间找相同文字。左图左轨 `#1…#8` 与右侧卡片头 `第 11 页 · #3` 同号；同一差异在右栏用**共享网格**把 A/B 两行的差异字对齐到同一列，再用一条短竖线连起来。
4. **右侧一屏只展开一条。** 其余压成一行摘要（`#2 替换 1 字 士→土`）。密度问题不是字号，是「同时要读几段 40 字」——从 6 段降到 1 段。
5. **Jev 只做二档**（`可疑` / `未打分`）+ 一个排序开关。不造「页级平均可疑度」，不造三档阈值——模块里只有 0.05 一个实测阈值（`jev_priority.DEFAULT_THRESHOLD`），多出来的档位是编的。
6. **v3 的三条要复审，不能整套照搬**：`±6 字` 保留；「判完不关面板」改成「判完卡不换位」；**`空格=采用` 取消**，改 `A`——见 §6。
7. **预览页的编辑只能走「段级覆盖」**，不能悄悄回写行。证据：`segments` 是导出时从 `block_line.text` 现推的（`export/segments.py:134`），没有段表、没有保存段的路由；一行段落跨 10 行时，「改成品」无法唯一映射回某一行。这一条是给 PM / Architect 的硬约束，不是排版偏好。

## 1. 现状：四个具体问题（问题 / 依据 / 建议 / 优先级）

### Q1 左图上看不出哪几个字不一样 —— P0

- **问题**：样张 `docs/screenshots/reading-page-image-blur-before-after.png` 里，差异行的**整行**套了一个红色虚线框，行内差异字又套了色块；用户看到的是「这一行有问题」，不是「这个字有问题」。
- **依据**：`reading-view.js:3791-3793` 给**每一条差异行**都画 `reading-diff-box--line`，用的是行框；`app.css:2509-2517` 的行框填充 `rgba(234,179,8,.13/.26)`；字层 `app.css:2503-2507` 再填 `rgba(220,38,38,.10)`。两层填充都在字身上。一个 30 字的行里差 1 个字，被涂成 30 个字宽。
- **建议**：删掉「行层常驻」；只画差异字（§2.4）。行位置由左轨编号 + 当前项焦点环承担。
- **优先级**：P0（这正是用户这次提的原话）。

### Q2 右侧太密、主次不清 —— P0

- **问题**：右栏同时铺开多条「整行 + 整行候选」，每条 40 字 ×2，读的人要自己做 diff；当前条与待判条没有层级差。
- **依据**：`openReadingPanel()` 把 `entry.candidate` 整行铺开；80.9% 的判断是「保留原文」，却要为每条读 80 字（`docs/pm/review-ux-audit.md` §0）。拆页后右栏变宽了，但「一屏几条」没变，密度只会更糟。
- **建议**：一屏只展开 1 条（A/B 两行、±6 字），其余一行摘要；「看整行」按需展开（§2.5）。
- **优先级**：P0。

### Q3 差异的「形状」没有语义 —— P1

- **问题**：替换、标点差、这一路多字、另一路多字，四种情况都画成红框/红底，只靠颜色深浅区分；灰度截图里几乎一样。
- **依据**：`reading-view.js:3790-3798` 只用 `kind === "punct"` 分出一个 `--punct` 类，其余同款；`app.css:2520` 仅把标点改成 dotted。插入/删除没有独立形状。
- **建议**：四种形状写死（实线/虚线/双线/竖线），见 §2.4.1；颜色只做第二通道。
- **优先级**：P1。

### Q4 页码与「还有多少」的口径在不同控件里打架 —— P1

- **问题**：工具条写全书进度，左树写页，右侧面板写「本页 3/7」；三个数没有共同的分母提示。
- **依据**：v3 §1.2 已列三重口径；本次拆页后右栏改为「本页」后，风险更高。
- **建议**：每个数字都带范围词——`全书待判 85 处` / `本页 6 处` / `第 11 页`；不再出现裸数字（§2.2）。
- **优先级**：P1。

## 2. 审校页

### 2.1 唯一目的与边界

**目的：把这一页上所有「两路不一致」的判断做完。**

| 必须在审校页做 | 只能在预览页做 | 两边都不做 |
|---|---|---|
| 判一处差异（保留 / 采用 / 自己改） | 读整段成品、改成品、导出 | 识别、版心、页面确认 |
| 看原图核对某几个字 | 看段落合并 / 断词还原 / 标点统一的结果 | 结构编辑（合并块、拆块） |
| 跳页、看全书还剩多少 | 处理「上游又变了」的冲突 | — |

如果一件事两边都能做，说明边界没想清。这里没有：**「改一行文本」只发生在审校页**（它会让 `diff_ack` 失效）；**「改成品」只发生在预览页**。预览页不提供「回到行」的入口。

**分组：回 → 页。** 单位是页，因为左图一次只显示一页。没有章节数据的书退化为页列表，并写一句「目录未确认，按页浏览」——不造分组（v3 已定，仍成立）。

- 数字口径：首行 `待判 151` = `queue_items.totals.unacked`；下两行拆开写 `汉字 85 处`（逐条判）与 `标点 66 行 / 32 组`（批量判）。**不把 151 说成「要逐条判 151 次」**。
- 回目行 `49 / 88` = 该回未判 / 总数，来自 `review_tree.chapters` + `pages[].unacked`。点回目只折叠，不跳页。

### 2.4 左图：只标差异字（核心）

#### 2.4.1 形状语言（灰度可读）

| 语义 | 形状 | 颜色 | 画在哪 | 灰度下 |
|---|---|---|---|---|
| 两路替换 | **3px 实线下划线** | `--diff-chars` #b42318 | 字框底边下方 3px | 实线 |
| 只差标点 | **3px 虚线下划线** | `--diff-punct` #b45309 | 同上 | 虚线 |
| 另一路多一个字（插入） | **3px 竖线（caret）** | `--diff-insert` #0f766e | 插入点，行高 | 竖线 |
| 这一路多一个字（删除） | **3px 双线下划线** | `--diff-chars` | 同上 | 双线 |
| 当前项 | **2px 蓝框（只框差异字，外扩 3px）** + 左轨编号实心 | `--accent` | 差异字外围 | 蓝框 + 实心号 |
| 已判 | 同形状**降为 1px、42% 不透明** | `--ok` #16a34a | 同上 | 更细更淡 |

**为什么不是背景色**：任何 `background` 都会改变字与纸的对比度；扫描件本身对比度就低（用户截图里的页面是灰底黑字），再叠一层 10–34% 的红/黄，字就糊了。下划线在字身外，零遮挡。

**为什么不用色块描边一圈**：一行 30 字，只差 1 个字，描边会把 1 个字变成一个小方块——在缩到 500px 宽的页面上，方块边线与汉字笔画同粗，反而更难认。下划线的「线」只有一条，眼睛能顺着它找到字。

#### 2.4.2 字符 → 框的映射

数据：`block_line.word_boxes`（逐字/逐词框，归一化，与行框同口径）+ `reading_marks` 的 `current/candidate` + `computeCharSpans`。

1. 先算 `spans = computeCharSpans(current, candidate)`（现有函数，`app.js:3574` 起）。
2. 把每个 span 的字符下标映射到 `word_boxes` 下标：拼接长度等于行文本长度时按偏移，否则按词位置（`reading-view.js:readingDiffUnits` 已有的两条分支，**直接复用，不另写**）。
3. 每个命中的字框画一条下划线；`insert` 没有字框，画 caret；`delete` 的字框还在，画双线。
4. **拿不到 `word_boxes`（空数组）或映射失败**：不估坐标。整行画一条**虚线**（`border-bottom: 3px dashed var(--faint)`），左轨编号后加 `~`，右侧卡片头写 `无字框 · 按整行定位`。这是诚实降级，不是视觉缺陷。
5. 只在**当前页**画；翻页即重画。当前项变化不重算 spans（缓存 key 用 `block_id:line_index:current:candidate`）。

#### 2.4.3 叠加与多差异

- **同一行多处差异**（一个 entry 覆盖整行、多个 span）：每个 span 各自一条线，**同一条线不合并**——中间相同的字留空，眼睛才知道「这两处都变了」。
- **同一行同时有汉字差和标点差**（分属两个 entry）：分两条泳道。汉字线下移 2px，标点线下移 5px。行距约 16px（515px 宽页面），两条都在字框下方，不撞字、不互相压。
- **同一字既算汉字差又算标点差**（极少）：汉字泳道优先，标点线并到汉字线右端 6px 的延伸段，左轨编号只出一个。不新增形状。
- **相邻两行的标记**：标点泳道最高到字框底边 +6px；行间空白 <8px 时标点线降到 +3px（与汉字泳道同高，靠虚线区分），宁可贴字也不越到下一行。
- **缩放**：标记随页面等比缩放（用页面像素坐标算，不用 `%` + `px` 混算）；`zoom < 60%` 时下划线降到 1.5px，否则会糊成一条粗线。

#### 2.4.4 当前项与「一眼对上」

四个通道，任何一条单独成立：

1. **同号**：左轨 `#3` ↔ 卡片头 `第 11 页 · #3`。编号是**页内、按书页顺序**的，Jev 排序不会改号。
2. **焦点环**：当前项的差异字外扩 3px 蓝框；左轨编号变实心蓝；同一页其他差异保持细线。
3. **悬停互亮**：悬停卡片 → 对应标记加 1px 蓝晕（不填充）；悬停标记 → 卡片描边变蓝。悬停只是加分项，前两条不依赖鼠标。
4. **卡片里的 2.5× 原图**：见 §2.4.5。

左轨位置：页面左侧**页面外**的 22px 竖轨，编号圆点在对应行的 y 上，右侧一根 10px 细线伸到纸边（纸边是空白，不压字）。为什么放页面外：扫描件的左边距里有插图和竖排书名（样张第 11 页可见），放纸内会撞图。

#### 2.4.5 原图放大贴在卡片里（不是浮在页面上）

- 位置：**当前展开卡的 A/B 上方**，一条 104px 高的原图裁剪，横宽 = 卡片宽 × 2.5（源图 1243px 宽、约 1:1，不虚）。
- 内容：以当前差异字为中心，**不画任何标记**（看原始笔画）；右下角 `原图 2.5×`。
- 为什么不做浮动放大镜：1440 下 PDF 列两侧只剩 52px，浮窗必然压住页面上的字；628 下 PDF 只有 348px 宽，更没地方。贴进卡片后，「看原图」和「做判断」在同一处，眼睛不用来回跳。
- 整页看清仍用 `⤢`（100% 浮层）；628 下卡片里的 2.5× 就是默认的清晰度兜底。
- 它解决的是「下划线告诉你差在哪，2.5× 告诉你这个字到底是什么」——两者缺一，用户仍要去猜。

#### 2.4.6 不做（这一页）

- 不画块框、不画版心（属于页面确认；要看得去「显示 ▾」显式打开）。
- 不画「行层常驻框」——这是 Q1 的根因。
- 不做全页色块高亮、不做 minimap。
- 页眉/页脚/页码行不标差异（队列已排除；`header_cleanup.is_page_number_noise` 同一判据）。

### 2.5 右侧：本页差异（重排）

**作用域：当前页。** 理由：右栏必须和左图空间对齐（第 3 条差异在页面上半，列表里也在上半）；跨页的「还有哪里」由目录和「下一处」负责。

```
本页 8 处 · 待判 6        排序：书页顺序 ▾   [仅待判 ✓]
┌────────────────────────────────────────────────────┐
│ #1  替换 1 字            第 11 页                   │
│  A  …看看一月， 士 隐已先得病，夫人封氏…            │
│  B  …看看一月， 土 隐已先得病，夫人封氏…            │
│  [保留原文 ⏎]  [采用候选 A]  [自己改 E]   ⌘Z 撤销   │
└────────────────────────────────────────────────────┘
│ #2  替换 1 字  —→一                                 │
│ #3  标点  ；→，                         已保留 ✓   │
│ #4  另一路多 1 字  —                                │
│ …                                                   │
另有 2 处已判 · 全部 →
```

- **卡片头**：`#n` + 差异类型（`替换 1 字` / `标点 ；→，` / `另一路多 1 字` / `这一路多 1 字`）+ 已判状态。不写「第二路」「第 N 行」。
- **A/B 两行用同一个 CSS Grid**（四列：`A/B 标签 | 左上下文 | 差异 | 右上下文`，`max-content` 列 + 整体居中），两行共享列宽 → **差异字永远上下对齐**；差异格下方/上方各伸 5px 竖线，在行间连起来。这是「一眼对上」的核心，比给两个整行涂色可靠。上下文向差异格贴齐（左列右对齐、右列左对齐），所以整组是紧凑的一块，不会散在 540px 的两端。
- 上下文 **±6 字**（v3 已确认，保留）；两端截断补 `…`。整行 >60 字时默认仍只给 ±6；`看整行` 展开到整行（同一张卡内，A/B 仍对齐）。
- 差异字：700 字重 + 同形状下划线（实线/虚线/双线）；A/B **同色**——这是 A/B，不是对错。
- **空位占位**：插入时 A 侧显示一个虚线空心小格（宽 18px，无文字），删除时 B 侧同款。**不写「空」字**，空格会被误读成真空格。
- **筛选**：`仅待判` 默认开；关掉后已判卡以 42% 淡化显示在底部，按书页顺序。
- **排序**：有分数时默认 `可疑优先`，无分数时 `书页顺序`；按项目记住上次选择。`书页顺序` 与左图上下一致，`可疑优先` 时靠编号与 A/B 对齐。切换只改列表顺序，**不改编号**。
- **一屏只展开一条**：点摘要行即展开它、收起上一条。判完一条：旧卡收起为摘要，下一条在原位展开（`scrollListToAnchor`，锚点 = 列表视口 220px 处，`behavior:auto`）。**不要 smooth**。
- **卡片动作**：`保留原文` 主按钮（80.9% 的默认，`⏎`）；`采用候选` 次按钮（`A`）；`自己改` 文字按钮（`E`，光标落在第一个差异字并选中该段）；`⌘Z` 撤销上一条判决。

### 2.6 Jev 怎么显示

- **粒度**：Jev 是**行级**分数（`block_line.jev_score`，越低越可疑），不是页级。**目录里不显示 Jev**——把行级分数压成页级平均是造数。
- **二档，不是三档**：`可疑`（`prob_1 ≤ 0.05`，模块里唯一实测阈值）与「无标记」（其余/未打分）。卡片头显示 `可疑 0.03`（数字来自真实分数，四舍五入到两位）；未打分不显示空档位。
- **排序控件**：列表头 `排序：可疑优先 ▾`（有分数时默认）/ `书页顺序`；无分数时只剩后者并注明原因。工具条另有一个 `只看可疑` 开关（跨页筛「下一处」），默认关。
- **未打分时**：排序控件只剩一项，旁边一行 10.5px 灰字 `Jev 未打分 · 296 行待打分` + 入口 `打分…`（复用现有 `jev-run`）。不显示禁用下拉里看不见的项。
- **已打分时**：列表头一行 `Jev 可疑 12 处 · 已打分 296 行`；`恢复书页顺序` 就在同一行，不做成 banner（现有 `jev-banner` 占 36px 高，拆页后没这个预算）。

> **数据缺口**：`/review/marks` 的 items 只有 `current/candidate/ack/bbox/pattern_key`（`reading_marks._build_items`，`reading_marks.py:101-159`），**没有 `jev_score`**；分数只在 `/review/next-lines` 里用于排序（`routes_review.py:452-480`）。卡片头要显示 `可疑 0.03`，需要 `_build_items` 合并 `jev_priority.line_scores()` 的结果——**不是新接口，是同一个响应加一个字段**。Architect 不同意加字段时，退化为：只保留排序/筛选，卡片不显示分数（仍然真实，只是少一个信息）。

### 2.7 键盘（复审后的键位）

| 键 | 空闲/选中卡 | 编辑中 |
|---|---|---|
| `⏎` | 保留原文并下一条 | 段内换行（不抢） |
| `A` | 采用候选并下一条 | 输入 a |
| `E` | 编辑当前条（光标落在差异字） | — |
| `↑` / `↓` | 上/下一条（只移动，不判决） | — |
| `Esc` | 收起当前卡 | 完成编辑，留在本行 |
| `⌘/Ctrl+Z` | 撤销上一条判决 | 撤销输入 |
| `?` | 快捷键帮助 | — |

- **取消 `空格=采用`**：拆页后右栏是常驻列表，没有「面板已打开」这个可判定的状态；空格又天然用于滚动。守卫只能做成「永远拦截」，代价是滚动失效 + 误改风险。改用 `A`（adopt），是明确的、不会误触的键。

- 判完一条 → 写草稿 → 旧卡收起 → 下一条在原位展开 → 左图换环、左轨换实心；四件事在同一帧完成。写失败不前进，卡片上显示 `未保存 · 重试`。

## 3. 预览页

### 3.1 唯一目的与边界

**目的：看整本书组装后的成品，并改成品。**

- 右栏是**干净文本**：段落已合并、跨页已接上、断词已还原、标点已统一。**没有红字、没有下划线、没有编号。**
- 左栏是书籍目录（回 → 段），中栏是 PDF 原文，右栏是成品。
- 未审校的状态只在**顶部一条**说一次（`审校未完成：85 处差异未判 → 去审校`），**不下沉到每一段**——否则预览页又变成审校页。

### 3.2 布局

│  看官：你道…  │  │ 当前段的 10 行 │ 青色描边     │   一日，正当嗟悼之际……           │

│  …            │  └─────────────┘              │  ─────────────────────────────   │

| 场景 | 目录 | PDF | 文本 |
|---|---|---|---|
| 1440×900 | 240 | 自适应（页高 776） | 600 |
| 1280×628 | 200 | 页高 500 | 560 |
| 1000×628 | 抽屉 | 380 | 全宽 |
| <980 | 抽屉 | 上 42vh | 下全宽 |

### 3.3 目录（最左）

- 回目行：`第一回 · p.1–13 · 55 段`；当前回展开。
- 回目下是**段行**（成品段落的第一句前 12 字），不是页码行——因为这一页的任务是按「段」读和改。段行右侧给 `p.1`（该段起始页）。
- 点段行 → 右栏滚到该段、中栏翻到该段首页。
- 没有回目数据时退化为「按段浏览」，不造假分组。
- 目录底部：`146 段 · 已手改 1 段`（数字来自 `segments.length` 与覆盖表；没有覆盖表之前不显示「已手改」）。

### 3.4 成品文本

- 16px / 1.95，行宽 ≤600，首行缩进 2em，段间距 12px。这是「书的样子」，不是「编辑器的样子」。
- 段页范围不常驻：悬停时在左沟显示 `p.1–2`，移开即隐。
- 悬停时段尾出现铅笔按钮 `✎ 改`；点段任意位置也可进入编辑。
- 段落三种状态：
  - **正常**：无装饰。
  - **已手改**：左沟 `已手改` 10.5px 青标签（不画竖条，避免和审校页的「手改」混淆）；`⋯` 里有 `还原成本段原文`。
  - **上游冲突**（§3.6）：段首一条 28px 琥珀条 `这一段的上游刚变过 · 你的修改还在` + `对比 / 保留我的 / 采用新的`。
- **跟随**：右栏滚动时，中栏自动翻到「视口顶部那一段的首页」（IntersectionObserver，默认开，不设开关）。这是 v3「跟随是默认行为」的延续。

### 3.5 编辑：进入、退出、保存

**就地编辑，不用侧栏。** 侧栏会把同一段复制一份到旁边，读者的眼睛在两个版本之间来回；「改成品」需要的是「就在这段上改」。

| 动作 | 行为 |
|---|---|
| 进入 | 点段落正文 / 悬停点 `✎` / 段聚焦时 `⏎` |
| 视觉 | 段落外扩 6px 蓝色描边（不改变字号/行宽，避免跳动）；底部出现编辑条 |
| 退出 | `Esc`（完成） / 点另一段（先完成当前段） / `完成` 按钮 |
| 保存 | 停止输入 500ms 自动保存；`完成` 只是立即冲刷一次，不引入「草稿/提交」两态 |
| 状态 | 顶栏 `保存中… / 已保存 ✓ 14:32 / 保存失败 ⚠ 重试`；编辑条同步显一个 |
| 失败 | 段落保持编辑态，内容不清空；顶栏红字 + `重试` |
| 切换页 | 有未完成的保存 → 先冲刷；失败则**不切页**，停在原地报错 |
| 撤销 | `⌘Z` 在段内撤销输入；失焦后再按 = 撤销上一次保存（可回到「还原原文」） |

- **不做「保存」与「提交」两个按钮**：用户要的是「改完就是成品」，不是「先存草稿再提交」。自动保存 + 可见状态，才符合「状态必须真实」。
- 段落正在编辑时，**中栏 PDF 框出这一段对应的行**（青色 2px 描边，不填色），并与「这一段的页范围」一起显示。用户改的是一个词，但能立刻看到它在原图哪一行。

### 3.6 编辑语义与持久化（给 PM / Architect 的硬约束）

**审校页的「改这一行」和预览页的「改成品」必须是两种语义，不能合流：**

| | 审校页改行 | 预览页改成品 |
|---|---|---|
| 对象 | `block_line.text`（一行） | 组装后的段（多行，可能跨页） |
| 作用 | 会改变 `diff_ack` 的有效性（现有行为） | **不回写行** |
| 存储 | 现有行编辑接口 | 段级覆盖（需要新表/路由，现有确实没有） |
| 失效 | 上游识别变化时按行失效 | 上游变化时进入「冲突」，**不静默覆盖** |

**为什么不能回写行**（证据，不是偏好）：

1. `Segment` 是导出时现推的（`export/segments.py:134`，`preview_segments_json` `export/project.py:709`）；数据库里没有段表（`core/storage/migrations/` 无 segment 表）。
2. 一段可能由 10 行、两个块、两页拼成（样张第 1 页第 3 段就是 10 行）。用户改的是段落里的一个词，**无法唯一判定改的是哪一行**；强行按字符偏移映射，会把编辑落到相邻行。
3. 若把成品编辑回写成行，会立刻让 `diff_ack` 失效、让审校进度回退——用户在预览页改一个标点，审校页又冒出 3 处待判。这是语义污染。

**覆盖表的最小形状**（供 Architect 参考，字段名不是界面承诺）：

```
segment_override(
  project_id, segment_id, base_signature, text, edited_at
)
```

- `base_signature` = 该段所有上游行（`block_ids` + `line_index` + `text`）的哈希。
- 读取：组装完成后，若 `segment_override.base_signature` 与当前上游一致 → 用覆盖文本；不一致 → 用新组装文本，并标记「冲突」。
- **不静默丢弃覆盖**：冲突时用户必须选一次（`保留我的` / `采用新的`）。选择后覆盖表更新或删除。
- 导出：在 `_prepare` 产出 segments 之后、序列化之前应用覆盖，导出的就是用户看到的成品。**导出与预览同一份文本**（现有原则）。
- 若本轮不做覆盖表：预览页编辑**不能上线**，只做只读预览 + 导出。不要做一个「保存后刷新就没了」的假编辑。

### 3.7 导出入口

- 顶栏 `导出…`（主按钮）打开现有导出对话框；导出前若有未决差异，对话框第一屏说明 `85 处未判`（现有预检），并可 `去审校`。
- 导出的是**当前成品**（含覆盖），不是「审校后的猜测」。导出对话框里的 `未审校的段` 数字仍然来自 `review` 汇总，不在这里重算。

## 4. 两页之间怎么切换

### 4.1 入口

- 顶栏三个页签：`页面 / 审校 / 预览`。`导出` 不再是页签，降为按钮（它本来就是一个对话框）。
- 审校判完最后一条 → 收尾卡 `去预览`（主按钮）。
- 预览页状态条 `85 处未判 → 去审校`（跳到第一处未判，不是第一页）。

### 4.2 状态保留

| 状态 | 切走再切回 | 说明 |
|---|---|---|
| 当前页 / 当前差异 | **保留** | 存在视图状态里，不靠 URL |
| 目录展开与筛选 | 保留 | 回目展开、`待判/全部` |
| PDF 缩放 / 卡片原图 | 保留 | 每页独立，不互相影响 |
| 右栏滚动位置 | 保留 | 列表滚到当前卡锚点 |
| 预览页滚动与当前段 | 保留 | 回到原段，不回到书首 |
| 正在编辑的段 | **保存后保留文本**，光标不保留 | 不静默丢弃；失败则不切 |
| 审校页没有「打开中的面板」 | — | 当前卡就是状态，切回来仍在 |

- 数据签名变化（识别跑完、判了一条、导出缓存变）时，**只重取受影响的部分**：审校页重取本页 marks + 目录计数；预览页重取 segments（现有缓存签名）。不要整页 reload。
- 两页共用顶栏的保存状态与任务胶囊；各自持有自己的滚动/选中状态。

### 4.3 切换时的守卫

1. 有未冲刷的段落编辑 → 先保存；成功才切。
2. 保存失败 → 停在预览页，顶栏红字，`重试`；不弹窗。
3. 审校页有未提交草稿（现有 `submit-drafts` 机制）→ 切页不阻断，顶栏 `未保存 N 处` 继续显示。

## 6. v3 已确认结论的复审

| v3 结论 | 现在是否成立 | 现在怎么做 | 为什么变 |

1. **左图零遮挡**：审校页 DOM 里，覆盖在 `.rv-paper img` 之上、且 `background` 非透明的节点数 = 0；差异标记的 `height` 都是 0 或竖条（不是覆盖块）。可用 `getComputedStyle` 扫。
