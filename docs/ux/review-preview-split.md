# 审校页 / 预览页：拆页后的 UI 与交互（v3）

> 作者：Designer。日期 2026-11-05。状态：设计稿，**不改产品代码**。
> 依据：`docs/spec-v1.0.md` §7、`docs/pm/review-preview-split.md`（`c17631d`）、`docs/pm/review-ux-audit.md`、`docs/ux/review-screen-ux-v3.md`、用户 2026-11-05 原话、Chief 的代码判定（段文本来源 / `submit-drafts` 写路径 / `ack=edited`）。
> 数据基线（样张用的真项目）：`b2t_S79EH0《红楼梦第一卷_正文前40页_图像版》`——40 页、3 回、247 处差异、待判 151（汉字 85 + 标点 66 行 / 32 组）、已判 96、第 11 页 8 处（待判 6）。
> **v2 修订**：左栏改为全书字符级队列 + 标点汇总入口（PM 口径）；预览页改为**按行改**，撤回 v1 的「段级覆盖表」；`可疑` 分从 `/review/next-lines` 取；预览页不设提交按钮。
> **v3 修订（用户 2026-11-05 选 B）**：标点**不叫「统一」、不做全局替换**；改为「少数派归并 + 人工确认」——判据是全书分布集中度，逐条确认，不集中（接近对半）的整类不给入口。新增 §3.8；§3.1 / §3.2 / §5 / §7 / §8 / §9 / §10 同步。

## 0. 结论（先看这七条）

1. **一页一个任务。** 审校页只回答「这一处两路不一样，留哪个」；预览页只回答「成品长这样，哪里还要改」。预览页**不画任何差异标记**，审校页**不画成品段落**。
2. **左图只标差异字，不填色。** 现状是「每条差异行画一个黄底行框，行内再画红底色块」（`reading-view.js:3793`、`app.css:2509-2545`）——两层填充压住字，用户当然看不出差在哪。新规则：**任何标记都不覆盖字身**，用实线 / 虚线 / 双线 / 竖线四种形状，颜色只做辅助。
3. **对应关系靠「页内编号 + 焦点环 + 2.5× 原图」**。左轨 `#1…#8`、队列行 `p.11·1`、右侧卡片头 `#1 · 第 11 页` 同号；A/B 两行共享网格把差异字对齐到同一列，再用一条短竖线连起来。
4. **右侧一屏只展开一条。** 其余压成一行摘要（`#2 …数应当如此，—于是接二连三…`，差异字带形状线）。密度问题不是字号，是「同时要读几段 40 字」——从 6 段降到 1 段。
5. **左栏 = 全书队列，中右 = 当前页。** 左栏逐条列**汉字级**差异（85 条）并给一个**标点汇总入口**（66 行 / 32 组）；中右只呈现当前页。顶栏 `待判 151` 来自 `queue_items()`，**不数左栏行数**——标点不占行。
6. **预览页按行改，不建段级覆盖表。** 段文本从 `block.text` 拼（`segments.py:311-313`），不是行记录；唯一同时写块文本与行记录的是 `submit-drafts`（`routes_review.py:656-666` → `sync_line_text`）。**改一行 = 确认这一行**，有未决差异时写 `ack=edited`。v1 的覆盖表撤回（v1 引 `segments.py:134` 说「段文本从行拼」是错的，那行只是 `segment_id` 的定义）。
7. **Jev 默认按文流，开关写「可疑优先（同档按阅读顺序）」。** 不写「按可疑度排序」：代码 `_tier` 返回 `(tier, order)`（`routes_review.py:461-474`），档内是阅读顺序，不是分数。分数从 `/review/next-lines` 的 items 取，不从 marks 取。
8. **标点不叫「统一」，叫「少数派归并 + 人工确认」。** 判据是**全书分布集中度**（≥90% 算集中），只把少数派列成候选，每条人确认一次；分布接近对半的整类不给入口，只显示一行「这本书两种写法都在用，未做归并」。入口在**预览页状态条**，不在审校页——审校页判「两路不一致」，这里判「这本书自己不一致」（§3.8）。原 v2 的「成品已统一标点」是错的，删除。

## 1. 现状：四个具体问题（问题 / 依据 / 建议 / 优先级）

### Q1 左图上看不出哪几个字不一样 —— P0

- **问题**：样张 `docs/screenshots/reading-page-image-blur-before-after.png` 里，差异行的**整行**套了一个红色虚线框，行内差异字又套了色块；用户看到的是「这一行有问题」，不是「这个字有问题」。
- **依据**：`reading-view.js:3791-3793` 给**每一条差异行**都画 `reading-diff-box--line`，用的是行框；`app.css:2509-2517` 的行框填充 `rgba(234,179,8,.13/.26)`；字层 `app.css:2503-2507` 再填 `rgba(220,38,38,.10)`。两层填充都在字身上。一个 30 字的行里差 1 个字，被涂成 30 个字宽。
- **建议**：删掉「行层常驻」；只画差异字（§2.4）。行位置由左轨编号 + 当前项焦点环承担。
- **优先级**：P0（这正是用户这次提的原话）。

### Q2 右侧太密、主次不清 —— P0

- **问题**：右栏同时铺开多条「整行 + 整行候选」，每条 40 字 ×2，读的人要自己做 diff；当前条与待判条没有层级差。
- **依据**：`openReadingPanel()` 把 `entry.candidate` 整行铺开；80.9% 的判断是「保留原文」，却要为每条读 80 字（`docs/pm/review-ux-audit.md` §0）。拆页后右栏变宽了，但「一屏几条」没变，密度只会更糟。
- **建议**：一屏只展开 1 条（A/B 两行、±6 字），其余一行摘要；「看整行」按需展开（§2.5）。
- **优先级**：P0。

### Q3 差异的「形状」没有语义 —— P1

- **问题**：替换、标点差、这一路多字、另一路多字，四种情况都画成红框/红底，只靠颜色深浅区分；灰度截图里几乎一样。
- **依据**：`reading-view.js:3790-3798` 只用 `kind === "punct"` 分出一个 `--punct` 类，其余同款；`app.css:2520` 仅把标点改成 dotted。插入/删除没有独立形状。
- **建议**：四种形状写死（实线/虚线/双线/竖线），见 §2.4.1；颜色只做第二通道。
- **优先级**：P1。

### Q4 页码与「还有多少」的口径在不同控件里打架 —— P1

- **问题**：工具条写全书进度，左树写页，右侧面板写「本页 3/7」；三个数没有共同的分母提示。
- **依据**：v3 §1.2 已列三重口径；本次拆页后右栏改为「本页」后，风险更高。
- **建议**：每个数字都带范围词——`待判 151` / `本页 6 处` / `第 11 页`；左栏 `151` 与顶栏 `151` 同源。
- **优先级**：P1。

## 2. 审校页

### 2.1 唯一目的与边界

**目的：把这一页上所有「两路不一致」的判断做完。**

| 必须在审校页做 | 只能在预览页做 | 两边都不做 |
|---|---|---|
| 判一处差异（保留 / 采纳 / 自己改） | 读整段成品、改成品、导出 | 识别、版心、页面确认 |
| 看原图核对某几个字 | 看段落合并 / 断词还原的结果 | 结构编辑（合并块、拆块） |
| 判「两路不一致」的标点（66 行 / 32 组） | 判「这本书自己不一致」的标点（全书标点差异，§3.8） | 在导出时统一标点 |
| 跳页、看全书还剩多少 | 处理「上游又变了」的冲突 | — |

如果一件事两边都能做，说明边界没想清。「改一行文本」在审校页和预览页**都能做**，但语义相同、写路径相同（§3.6）：**改一行 = 确认这一行**。这不是边界漏洞，是 PM 定的「按谁负责发现来分」：审校页改的是机器指得出的疑点，预览页改的是机器指不出的错。

### 2.3 差异队列（最左，全书）

**结构：回 → 条目。条目是行级差异，不是页。** 页在条目行里以 `p.11·1` 出现，不再单独占行。

```

[待判] [全部]

   p.1·2  悲[哀]。
   p.1·3  …远而来，生得[骨]格…
   p.2·3  …叙着[堕]落之乡…
   p.4·4  城，城中[阊]门，最是…
   …
   p.11·1 …看看一月，[士]隐已先得…   ← 当前条：蓝底 + 左 3px 蓝条
   p.11·2 …数应当如此，[—]于是接…
   p.11·5 …偏值近年水[旱]不收…
```

> 上面 `[ ]` 只表示差异字的位置；界面画的是下划线（实线/虚线/双线）或插入竖线，不是括号。

- **条目内容**：`p.{页}·{页内序号}` + **差异处上下文**（前后各 6 字，差异字带 3px 实线/虚线/双线，插入处 3px 竖线）。不显示孤立的 `士→土`：12px 下 士/土、旱/早 分不清；差异对留给右栏卡片（14.5px + 2.5× 原图）。上下文让用户按**句子**认条目，而不是按两个形近字猜。
- 序号是**页内、含标点与已判条目一起编**的，所以 `p.11` 只出现 1/2/5/7/8 这几个号——它和右栏卡片头、左图左轨是同一个号。
- **排序只改队列顺序，不改序号**：Jev 开关切到「可疑优先」时，条目换位置但 `p.11·1` 仍是 `p.11·1`。
- **回目行只给字符级条数**（第一回 28、第二回 15、第三回 42；合计 85）。标点不进回目：它在底部单独一条全书汇总，点进批量面板。这样 `28 + 15 + 42 = 85`，与 `汉字 85 条` 对得上；`151 = 85 + 66` 只在顶栏与队列头出现。
- **顶栏 `待判 151` 来自 `queue_items().totals.unacked`**，不数左栏行数（左栏只有 85 条 + 1 个标点入口，另有版心外一行、不进 151）。标点 chip 的 66 是行数、32 是组数，点下去打开的面板也按 32 组列。
- **默认滚动到当前条**（锚在可视区 40%），当前回自动展开；其余回折叠。回目行 sticky，滚到哪都知道自己在哪一回。
- `待判 / 全部` 过滤只影响队列行；`全部` 时已判条目淡化显示，不改变当前条。
- **`可疑` 分数从 `/review/next-lines` 的 items 取**（Architect 会把 `jev_score` 加在那里），显示在条目行右侧：`可疑 0.03`；未打分不占位。
- 队列底部：标点汇总一条 + Jev 状态一行 + **版心外一行** + 图例两行 + 字框覆盖率。覆盖率 <100% 时写 `字框 96%（41 行按整行定位）`，那些行在左图上按整行虚线兜底（§2.4.2）。
- **版心外条目不进队列**：样张 5 条（`queue_items().outside`）不在 151 里、不进完成度；底部只留 `版心外 5 条（不进审校与完成度） · 查看 →`，点开去页面面板的「版心外」筛选（现有 `app.js:2932/3108`，不新增接口）。它往往是版心判错的信号，所以不能全藏掉；进了目录就成了分母里的假条目。其他类型条目同样不进目录：它们不进正文流（`export/project.py:326`），写 known-limitations，不占界面。

### 2.4 左图：只标差异字（核心）

#### 2.4.1 形状语言（灰度可读）

| 语义 | 形状 | 颜色 | 画在哪 | 灰度下 |
|---|---|---|---|---|
| 两路替换 | **3px 实线下划线** | `--diff-chars` #b42318 | 字框底边下方 3px | 实线 |
| 只差标点 | **3px 虚线下划线** | `--diff-punct` #b45309 | 同上 | 虚线 |
| 另一路多一个字（插入） | **3px 竖线（caret）** | `--diff-insert` #0f766e | 插入点，行高 | 竖线 |
| 这一路多一个字（删除） | **3px 双线下划线** | `--diff-chars` | 同上 | 双线 |
| 当前项 | **2px 蓝框（只框差异字，外扩 3px）** + 左轨编号实心 | `--accent` | 差异字外围 | 蓝框 + 实心号 |
| 已判 | 同形状**降为 1.5px、42% 不透明** | `--ok` #16a34a | 同上 | 更细更淡 |

**为什么不是背景色**：任何 `background` 都会改变字与纸的对比度；扫描件本身对比度就低（用户截图里的页面是灰底黑字），再叠一层 10–34% 的红/黄，字就糊了。下划线在字身外，零遮挡。

**为什么不用色块描边一圈**：一行 30 字，只差 1 个字，描边会把 1 个字变成一个小方块——在缩到 500px 宽的页面上，方块边线与汉字笔画同粗，反而更难认。下划线的「线」只有一条，眼睛能顺着它找到字。

#### 2.4.2 字符 → 框的映射

数据：`block_line.word_boxes`（逐字/逐词框，归一化，与行框同口径）+ `reading_marks` 的 `current/candidate` + `computeCharSpans`。

1. 先算 `spans = computeCharSpans(current, candidate)`（现有函数，`app.js:3574` 起）。
2. 把每个 span 的字符下标映射到 `word_boxes` 下标：拼接长度等于行文本长度时按偏移，否则按词位置（`reading-view.js:readingDiffUnits` 已有的两条分支，**直接复用，不另写**）。
3. 每个命中的字框画一条下划线；`insert` 没有字框，画 caret；`delete` 的字框还在，画双线。
4. **拿不到 `word_boxes`（空数组）或映射失败**：不估坐标。整行画一条**虚线**（`3px dashed var(--faint)`），左轨编号后加 `~`，右侧卡片头写 `无字框 · 按整行定位`。这是诚实降级，不是视觉缺陷。
5. 只在**当前页**画；翻页即重画。当前项变化不重算 spans（缓存 key 用 `block_id:line_index:current:candidate`）。

#### 2.4.3 叠加与多差异

- **同一行多处差异**（一个 entry 覆盖整行、多个 span）：每个 span 各自一条线，**同一条线不合并**——中间相同的字留空，眼睛才知道「这两处都变了」。
- **同一行同时有汉字差和标点差**（分属两个 entry）：分两条泳道。汉字泳道 = 字框底边 +3px，标点泳道 = +6px。行距约 16–21px（515px 宽页面），两条都在字框下方，不撞字、不互相压。
- **同一字既算汉字差又算标点差**（极少）：汉字泳道优先，标点线并到汉字线右端 6px 的延伸段，左轨编号只出一个。不新增形状。
- **相邻两行的标记**：标点泳道最高到字框底边 +6px；行间空白 <8px 时标点线降到 +3px（与汉字泳道同高，靠虚线区分），宁可贴字也不越到下一行。
- **缩放**：标记随页面等比缩放（用页面像素坐标算，不用 `%` + `px` 混算）；`zoom < 60%` 时下划线降到 2px，否则会糊成一条粗线。

#### 2.4.4 当前项与「一眼对上」

四个通道，任何一条单独成立：

1. **同号**：左轨 `#3` ↔ 队列行 `p.11·3` ↔ 卡片头 `#3 · 第 11 页`。编号是页内、按书页顺序的，Jev 排序不改号。
2. **焦点环**：当前项的差异字外扩 3px 蓝框；左轨编号变实心蓝；同一页其他差异保持细线。
3. **悬停互亮**：悬停卡片 → 对应标记加 1px 蓝晕（不填充）；悬停标记 → 卡片描边变蓝；悬停队列行同理。悬停只是加分项，前两条不依赖鼠标。
4. **卡片里的 2.5× 原图**：见 §2.4.5。

左轨位置：页面左侧**页面外**的 22px 竖轨，编号圆点在对应行的 y 上，右侧一根细线伸到纸边（纸边是空白，不压字）。为什么放页面外：扫描件的左边距里有插图和竖排书名（样张第 11 页可见），放纸内会撞图。

#### 2.4.5 原图放大贴在卡片里（不是浮在页面上）

- **展开卡的头**：`#n` + 差异类型（`替换 1 字` / `标点 ；→，` / `另一路多 1 字` / `这一路多 1 字`）+ 已判状态。不写「第二路」「第 N 行」。有 Jev 分数时，头部加 `可疑 0.03`（数据来自 `next-lines`）。

- **空位占位**：插入时 A 侧显示一个虚线空心小格（宽 18px，无文字），删除时 B 侧同款。**不写「空」字**，空格会被误读成真空格。

- **排序**：右栏**没有**排序控件。顺序由左栏队列决定（书页顺序 / 可疑优先），右栏只按同一顺序排本页条目；切换排序不改右栏的页内编号。

### 2.6 Jev 怎么显示

- **粒度**：Jev 是**行级**分数（`block_line.jev_score`，越低越可疑），不是页级。**队列里按条目显示**，不压成页级平均。
- **二档，不是三档**：`可疑`（`prob_1 ≤ 0.05`，模块里唯一实测阈值）与「无标记」（其余/未打分）。分数从 `/review/next-lines` 的 items 取（Architect 加字段），显示 `可疑 0.03` 四舍五入到两位；未打分不显示空档位。
- **排序**：默认 `书页顺序`；开关文案 **「可疑优先（同档按阅读顺序）」**。数字提示：`40 页实测：前 50 条命中率 68%，原顺序 25%`（来源 `docs/qa/2026-11-05-jev-acceptance.md` §③）。**不出现「按可疑度排序」**。
- **等分档时**：`_tier` 是 `(tier, order)`（`routes_review.py:461-474`），同档按文流，不按分数。若将来定「判前 N 条就停」，再改 `(tier, score, order)`；纯分数升序的前 50 是 76%，本轮不做、不进界面。
- **未打分时**：队列底一行 `Jev 未打分 · 296 行可打分` + `开始打分…`；排序开关只剩「书页顺序」并注明原因。不显示禁用下拉里看不见的项。
- **已打分时**：队列底一行 `Jev 可疑 12 处 · 296 行已打分` + `恢复书页顺序`（当前是可疑优先时）。不做 banner（现有 `jev-banner` 占 36px，拆页后没这个预算）。
- **手改后分数必须失效**：写行文本的同一批把该行 `jev_score` 置空（Architect 建议）；否则改过的行还挂着旧 `0.03`，用户会拿它当没改过的分数。界面不做「猜它过期了」的标记——直接清掉。

> **68% / 25% 锁源**：`docs/qa/2026-11-05-jev-acceptance.md` §③（基线 25.2%，四舍五入 25%）。76% 是「纯分数升序」的反事实，本轮不做，不进界面也不进验收。

### 3.5 编辑：点字 → 整行 → 就地改

**单位是行，不是段。** 用户点的是字，改的是这个字所在的源行；跨行只能走结构操作。

| 动作 | 行为 |
|---|---|
| 进入 | 点成品里的任意字 → 选中它所在的 `line_span`；整段进入编辑态，行边界显形（§3.4） |
| 视觉 | 当前行 2px 蓝实线下划线 + 4% 蓝底；编辑条出现；**不重排文字**（边框不占布局） |
| 边界 | 当前行的起点/终点就是蓝线的起点/终点；如果行跨视觉换行，蓝线跟着文本断成两段 |
| 编辑 | 当前行可改；其余行只读但保持可读。光标落在点到的那个字附近 |
| 退出 | `Esc` / 点另一段 / `完成` |
| 保存 | **即写即存**：停止输入 500ms 或失焦即写；`完成` 只冲刷一次，退出编辑。**没有「保存」和「提交」两个按钮** |
| 状态 | 顶栏 `保存中… / 已保存 ✓ 14:32 / 保存失败 ⚠ 重试`；编辑条同步显一个 |
| 失败 | 保持编辑态，内容不清空；顶栏红字 + `重试` |
| 切换页 | 有未完成的保存 → 先冲刷；失败则**不切页**，停在原地报错 |
| 撤销 | `⌘Z` 撤销这一次行编辑（回到这一行原来的文本） |

**首次进入的提示**（PM 给的话，直接上屏；帮助里同一段）：

> 「成品里点哪个字，改的就是它所在的那一行。要并段 / 拆段，用行首的『并入上一段』和光标处的『拆成两段』。合并段落时自动补的空格、英文断词还原时去掉的连字符是规则拼出来的、不属于任何一行，这里只读。」

- **并段 / 拆段**：行首（块的第一行）悬停出 `并入上一段`；光标处出 `拆成两段`。两者都走现有结构接口（`merge-prev` / `split`），不在文字里塞换行。跨行删除/插入**不能**用退格直接做——退格到行首即停，提示用结构按钮。
- **派生字符只读**：`line_span` 覆盖不到的字符（合并补的空格、断词还原去掉的连字符）不进入任何一行，编辑时标为只读（点上去不落光标）。Architect 实测合成样例 43 字 / span 覆盖 41 / 派生 2。
- **中栏联动**：整段的 10 行用 1px 青框标出，当前行用 2px 青框标出；改一个字，原图上的哪一行立刻可见。
- **不做**：整段重打、段级覆盖、把成品另存一份。预览 = 导出同一份文本。

### 3.6 写路径与语义（这是本轮的核心约束）

**改一行 = 确认这一行。** 两款页面共用同一条写路径，不允许预览页走另一条：

| | 审校页改行 | 预览页改行 |
|---|---|---|
| 对象 | `block_line`（一行） | `block_line`（一行）——用户点的是字，落到 `line_span` |
| 写路径 | `submit-drafts`（`sync_line_text` 同时写 `block.text` 与行记录） | **同一条** `submit-drafts` |
| 裁决 | 有未决差异：`kept` / `adopted` / `edited`；无差异：只改文本，不写 ack | 同左 |
| 生效 | 立即；导出读 `block.text` | 立即；导出读 `block.text` |

**为什么不能建段级覆盖表**（v1 撤回，Chief 已用代码判定）：

1. 段文本从 `block.text` 拼（`segments.py:311-313` 的 `if not text: text = block.text`），不是行记录；把成品另存一份就会与导出分叉，成为第二个「成品定义」。
2. `submit-drafts` 是唯一同时写块文本和行记录的路径（`routes_review.py:656-666` → `sync_line_text`）；`PATCH /blocks` 只写块文本，会让审校页读到旧行文本——预览页**不许**用它改字。
3. 段级覆盖在「上游又变了」时无解：覆盖层要自己判断冲突，等于再造一个版本系统。行级写回让上游变化直接生效，没有第二份真相。

**`ack=edited`（PM 已定，需 Architect 落地）**：

- `diff_ack` 三值并列：`kept` / `adopted` / `edited`。有 `aux_text` 的行，手改后写 `edited` + `diff_ack_text=新行文本`；没有 `aux_text` 只改文本、不写 ack。
- 不冒充 `adopted`：否则「采纳候选 N 条」虚高。不留 `null`：现状审校页「两路都不对」发 `null`（`reading-view.js:2784`），改完下一轮又回队列。
- 不用迁移（`diff_ack` 列没有 CHECK）；要改 `DIFF_ACKS`（`editing.py:732`）、事件 action、统计卡（`review_status.py:459-480`）、界面三态。
- 顺带修：`kept` + `new_line_text` 现在是**静默丢弃**（`editing.py:877/904`），接口应直接 400。

**删掉草稿层**（PM 已定）：即写即存。草稿是「没写库但用户以为改了」的第三种状态，会让两页数字不一致。代价是没有整段会话级撤销，可接受；行级 `⌘Z` 保留。

### 3.7 导出入口

- 顶栏 `导出…`（主按钮）打开现有导出对话框；导出前若有未决差异，对话框第一屏说明 `85 处未判`（现有预检 `export-panel.js:231`），并可 `去审校`。
- **导出不设闸**：`POST /export` 直接跑（`routes_exports.py:146-151`），前端 `runExport` 不禁用、不确认（`export-panel.js:450`）。未审状态由预检与 manifest 的 `unreviewed_segments` / `uncertain_segments` 如实记录（`manifest.py:118-119`）。**不显示「预览完成」**——预览页没有完成态，也不造第二个完成定义。
- 导出的是**当前成品**，与右栏看到的同一份文本（`block.text` + 段组装规则），不另存副本。导出对话框里的 `未审校的段` 数字仍来自 `review` 汇总，不在这里重算。

### 3.8 全书标点差异：少数派归并 + 人工确认

**它回答的问题**：这本书**自己**的标点用法在哪儿前后不一致，且不一致到能判断是识别错。

与审校页那个「标点」不是一件事（这是本节存在的前提）：

| | 审校页 `标点 66 行 / 32 组` | 预览页 `全书标点差异 6 处` |
|---|---|---|
| 判什么 | 两路识别结果不一致 | 这本书内部用法不一致 |
| 依据 | 另一引擎的候选 | 全书分布 |
| 动作 | 判留哪一路 | 逐条改成全书多数写法，或不动 |
| 单位 | 行 / 组 | 处（一处 = 同行内一处标点；成对符号算 1 处） |
| 位置 | 审校页工具条 | 预览页状态条右端 |

**不做「统一」**：不设全局替换、不设「一键全改」、不在导出时替换。用户研究译文与情感语词，标点本身是他要比对的材料；同一本书的印刷体是一致的，输出里出现两种写法，多数情况是 OCR 认错了其中一种——所以判据只能是「少数派」，不能是「我们觉得哪种好看」。

#### 3.8.1 判据（参数化，界面不写死）

```
按「标点类」统计全书各写法的次数（后端口径，前端不重复统计）
share = 多数写法次数 / 该类总次数
集中（share ≥ CONCENTRATION_MIN）→ 少数写法的每一处都进候选，逐条确认
不集中（share < CONCENTRATION_MIN）→ 整类不给入口，只显示分布
    share ≤ BALANCED_MAX → 「这本书两种写法都在用，未做归并」
    否则                 → 「分布不够集中（NN%），未做归并」
```

| 参数 | 当前值 | 含义 | 谁改 |
|---|---|---|---|
| `CONCENTRATION_MIN` | **0.90** | 集中度达标才算「少数派」 | 配置，跑几本书后调 |
| `BALANCED_MAX` | **0.60** | 低于它才敢说「两种都在用」 | 配置，同上 |

- 0.90 是起点值，不是永恒值；**两个值都进配置**，界面文案里的百分比由当前数据算（`52/59 → 88%`），不写死。
- 计数口径：成对标点（`“”` `‘’` `「」` `『』`）**1 对 = 1 处**；不成对的（`——` `……` `、`）**1 字符 = 1 处**。类名用用户语言：双引号 / 单引号 / 破折号 / 省略号 / 顿号。
- 78% 这种「不够集中但又不是对半」的类：只显示两个数与百分比，**不下结论说是 OCR 错**——那是数据没给出的事实。

**不进候选的四类**：

1. **跨行的引号对**（起止不在同一源行）→ 一行内改不了，在「未做归并」区单独一条 `跨行 3 处（请在正文里手动改）`。
2. **有未决差异的行**（两路不一致且 `diff_ack` 为空）→ 改它等于替审校裁决；那一行提示 `该行还有未判差异，先去审校`。
3. **版心外 / 页眉页脚 / 页码行** → 不进正文流，不参与。
4. **总数低于 2 次的类** → 没有「多数」可言。

#### 3.8.2 入口：预览页状态条右端（常驻）

```
[!] 审校未完成：85 处差异未判  去审校 →   │   全书标点差异 6 处（疑似识别不一致）  查看 →
```

- 状态条改成**常驻双端条**（36px）：左端审校状态，右端标点入口，中间 1px 竖分隔线。
- 左端 0 处时 `审校已完成 ✓`（绿）；右端 0 处时 `全书标点 0 处`（muted，**仍可点开**看各类分布与未归并原因）。
- 右端**不继承警示色**：`查看 →` 用强调色，否则会被读成同一条警告的一部分。
- **为什么常驻**：这是导出前唯一还缺的人工闸，而且它的判据（全书分布）与审校是否完成无关。v2 的「没有未判就省 36px」会让它在该出现的时候正好消失。
- **为什么不在审校页**：见上表。也不要塞进上传/导出对话框——那是「事后才知道」。
- **为什么不用「统一」二字**：那三个字暗示"按规则批量替换"，与用户选的做法相反；界面上一旦出现，用户会以为自己的风格被系统改掉了。
- `<1240` 宽：括号说明去掉，只留 `全书标点差异 6 处 →`，完整文案进 `title`。

#### 3.8.5 写路径与留痕（给 Architect）

- 逐条归并 = **改一行文本**，沿用 §3.6 的同一条路径（`submit-drafts`，同时写 `block.text` 与 `block_line`）；该行没有未决差异，所以不写 `ack`。
- **不许直接复用现有 `apply_lines`**（`orthography.py:633`）：它只写 `block_line.text/aux_text/diff_status`、不写 `block.text`，而导出与预览读的是 `block.text` —— 直接用就是「显示 ≠ 导出」。要用就得补上块文本的写入，或者走 `submit-drafts`。
- 现有 `orthography` 是**规则批量替换**（括号/半角/引号配平，一次一批、可整体撤销），与本节的「人逐条确认」是两件事，不要拿它当这个面板的后端。
- 事件日志记一条 `punct_merge`（或 `edited` + 备注），带 `line_id / class / from_chars / to_chars / majority_form / majority_count / total_count`；有这几个数，「依据」事后才能复现。
- 分布统计由后端算并缓存，接口返回 `{class, forms:[{text, count}], majority, share, candidates?}`；**前端不做集中度判定**，否则两处口径会漂。
- 撤销 = 把该行文本写回改前值，同样走行级写路径，不改结构。

## 4. 两页之间怎么切换

### 4.1 入口

- 顶栏三个页签：`页面 / 审校 / 预览`。`导出` 不再是页签，降为按钮（它本来就是一个对话框）。
- 全局步骤条：第 6 步从「文件导出」改名 **「预览与导出」**，视图 = `#view-preview`，导出按钮在预览页顶栏；状态用 `plain`（不计完成，计数仍可写「已导出 N 次」）。不加第 7 步（D-090）。
- 审校判完最后一条 → 收尾卡 `去预览`（主按钮）。
- 预览页状态条 `85 处未判 → 去审校`（跳到第一处未判，不是第一页）。

### 4.2 状态保留

| 状态 | 切走再切回 | 说明 |
|---|---|---|
| 当前页 / 当前差异 | **保留** | 存在视图状态里，不靠 URL |
| 队列展开与筛选 | 保留 | 当前回、`待判/全部`、滚动位置 |
| PDF 缩放 / 卡片原图 | 保留 | 每页独立，不互相影响 |
| 右栏滚动位置 | 保留 | 列表滚到当前卡锚点 |
| 预览页滚动与当前段 | 保留 | 回到原段，不回到书首 |
| 正在编辑的行 | **保存后保留文本**，光标不保留 | 不静默丢弃；失败则不切 |
| 审校页没有「打开中的面板」 | — | 当前卡就是状态，切回来仍在 |

- 数据签名变化（识别跑完、判了一条、导出缓存变）时，**只重取受影响的部分**：审校页重取本页 marks + 队列计数；预览页重取 segments（现有缓存签名）。不要整页 reload。
- 两页共用顶栏的保存状态与任务胶囊；各自持有自己的滚动/选中状态。

### 4.3 切换时的守卫

1. 有未冲刷的行编辑 → 先保存；成功才切。
2. 保存失败 → 停在预览页，顶栏红字，`重试`；不弹窗。
3. 审校页有未提交草稿（现有 `submit-drafts` 机制）→ 切页不阻断，顶栏 `未保存 N 处` 继续显示。
