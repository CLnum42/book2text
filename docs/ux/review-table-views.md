# 审校表格 / 三档视图：可点原型与测量

> 作者：Designer。日期 2026-11-05。状态：**可点原型**，不接后端、不写库；不改产品代码。
> 交付两个 HTML（同一批真数据、同一套判定动作）：
> - `review-table-prototype.html` —— 表格版：左队列 / 中 PDF（可切纯表格）/ 右「上下文 + 当前行 + 两个按钮 + 输入框」。
> - `review-three-views-prototype.html` —— 三档版：单字 / 单行 / 多行，同一差异字固定在同一锚点。
> 数据：`fixtures/pdf/sample-20p-300dpi.pdf` 第 1、2 页（第二十七回开头与结尾）跑两路真引擎（RapidOCR / Apple Vision），得到 6 处真实差异；另取第 5 页一行三处（`<`/`＜`、`>`/`＞`、`"` 插入）做「一行多处」的编号示例。行图/字图从 300 DPI 页图裁，单字框来自 OCR 逐字框。

## 0. 三句话

1. **一行的多处差异今天还不存在。** 现在的 `LineDivergence` 是整行比对（`line_index / level / current / candidate / ack`，无字级 offset），一条 = 一行。原型里的「一处」是前端用 `current/candidate` 逐字 diff 再按「相邻性」切出来的：数据够、不用新接口，但它是**新概念**，落地时队列条数和进度分母都会变。原型把两个数都显示出来：`已判 N/9 处` + `行 N/7`。
2. **三档默认单行。** 单字只在字形难分时用（洒/酒、晴/睛、入/人），多行在要看语义时用；档位按项目记住上次选择。切档用 `V` 循环，不用 `1/2/3`——`1/2` 已经是「采用当前 / 采用候选」。
3. **少的是阅读与滚动，不是点击。** 今天键盘判一条也是 1 次动作（Enter），三档/表格也是 1 次（1 或 2）。这三个视图省的是「读 80 字 + 滚一屏 + 左右找同一行」，不是点击次数。这一点必须先说清，否则验收口径会错。

## 1. 两个可点原型

| | 表格版 | 三档版 |
|---|---|---|
| 打开 | `docs/ux/review-table-prototype.html` | `docs/ux/review-three-views-prototype.html` |
| 队列 | 左栏，行级（一行一条，多处在行内编号） | 左栏，处级（一行多处拆成多行） |
| 图片 | 中栏整页 + 当前行 2× 裁切；可切「纯表格」 | 单字 / 单行 / 多行三档，同一差异字固定在同一坐标 |
| 右侧 | 上下文三行 + 当前行 + 两个按钮 + 输入 | 三档槽位（上一行/当前行/下一行）+ 两个按钮 + 输入 |
| 适合 | 要对照整行、要一眼看前后文 | 要判字形（单字）、要看语义（多行） |
| 共同 | 1/2 采用、Tab 输入、Enter 确认、`⌘Z` 撤销、前端假状态、`说明 / 测量` 抽屉 |

两版都**真的能点**：按钮、输入框、确认、上下文展开、切档、队列跳转；点完队列打勾、进度变化、自动下一处。键盘 `1` / `2` / `Tab` / `Enter` / `↑↓` / `V` / `⌘Z` 都接了。

## 2. 三档视图的规格

### 2.1 三档分别给什么

| 档 | 图（裁切） | 右侧文字 | 判什么 | 典型场景 |
|---|---|---|---|---|
| 单字 | 只框这个差异字（字框外全部遮掉） | 只有两个判定按钮 | 字形 | 洒/酒、晴/睛、入/人、己/已/巳 |
| 单行 | 整行（上下遮掉，行内左右按锚点裁） | 完整当前行（差异处编号） | 字形 + 这一行的上下文 | **默认**，大多数 |
| 多行 | 上一行 + 当前行 + 下一行（3 行） | 三行，当前行高亮 | 语义 | 断句、跨行、指代不清 |

- **图片不是后端裁的**：同一张 300 DPI 页图，`<img>` 按倍率缩放 + 负位移做取景窗；`word_boxes` 给字框，`marks[].bbox` 给行框。不用新接口，也不用新图。
- **遮罩不是半透明**：用不透明的 `#e9ebef` 把取景框外盖住，视觉上就是「只给这一处」。这比蒙层更接近用户说的「图片只给这个差异字/这一行」。
- 页脚有一个**整页缩略图**，蓝框标出当前取景位置；它回答「这一处在整页哪里」，不参与判定。

### 2.2 锚点：三档不跳

- 三档都把**这个差异字的中心**放在图片区的同一点（原型：`(228, 100)`，即 456×200 取景窗的中心）。
- 右侧「当前行」固定在同一个槽位（`top:92px`），上一行/下一行只在多行档出现，不挤动当前行。
- 换档只改**倍率与遮罩范围**，不改锚点；眼睛不用重新找。
- 原型里 `锚点 (228, 100) · 漂移 0px` 是实时读数，不是文案。实测（无头 Chrome 读 DOM）：三档的差异字中心都是 `(228,100)`，**0px 漂移**。

### 2.3 插入/删除的退化

- 一个版本有字、另一个没有（`∅→‘` 那类）在单字档没法并排。单字按钮置灰，悬停说明「插入/删除不能并排，只能单行」。
- 如果当前正停在单字，翻到这种差异会自动切到单行，并提示「这一处是插入/删除，单字没法并排，已切到单行」。
- 这条是硬规则：**不许在单字档放一个空按钮假装能并排**。

### 2.4 键盘

| 键 | 作用 |
|---|---|
| `1` / `2` | 采用当前 / 采用候选（和用户上一轮的要求一致） |
| `V` | 循环切档：单字 → 单行 → 多行 |
| `Tab` | 到输入框 |
| `Enter` | 输入框有字则确认；否则不动作 |
| `↑` / `↓` | 上一处 / 下一处 |
| `E` | 聚焦输入框 |
| `⌘/Ctrl+Z` | 撤销上一处判决 |

**为什么不是 `1/2/3` 切档**：`1/2` 已经是采用左/右（用户上一轮原话）。`1/2/3` 切档会撞键，只能二选一；这里保采用、用 `V` 循环。若用户想要直达，可另加 `⌥1/2/3`，但不占主键。

### 2.5 三个问题的回答

1. **默认哪档？单行。** 单行同时给「这一行的字」和「差异在哪」；单字是字形难分时才需要，默认单字会让人频繁往上切；多行是语义需要时才切。档位按项目记在 `localStorage`。
2. **怎么切？** `V` 循环 + 两处分段控件（顶栏、判定栏）；记忆上次。不做「按差异类型自动切」——自动切会让人不知道自己在哪一档；插入/删除是唯一例外，自动退到单行并说明原因。
3. **锚点一致？** 同一差异字固定在同一点 + 当前行固定槽位；原型实测 0px；缩略图给整页位置，切档不丢上下文。

## 3. 表格版与三档版怎么选

- **表格版**把「上下文」放在左边、「当前行 + 判定」放在右边；图片是辅助（整页 + 行裁切，可关掉）。适合**读整行、看前后文**，也适合没有字框的老项目（行图不依赖 `word_boxes`）。
- **三档版**把「图片」作为主角，右侧文字随档位变；适合**判字形**和**快速扫**。单字/多行依赖字框与行框，字框缺失时单字退到单行。
- 两者可以合成一个：表格行 + 图片区的三档切换。但先让用户挑默认形态——这是产品决定，不是实现细节。

## 4. 测量（手数，不是眼动仪/秒表）

### 4.1 单条

| 指标 | 今天那一屏 | 表格版 | 单字 | 单行（默认） | 多行 |
|---|---|---|---|---|---|
| 判决动作 | 1（Enter 保留并前进） | 1（或 0，用键） | 1（1 / 按钮） | 1（2 / 按钮） | 1（2 / 按钮） |
| 必读字数 | 约 80（A/B 各一整行） | 2–6 + 当前行 30 | **2**（两个字形） | **30 + 2** | **90 + 2**（三行） |
| 视线跨区 | 2（右→左图→右） | 0–1 | 0–1 | 0–1 | 1（上下行） |
| 滚动 | 约 0.5 次/条 | 0 | 0 | 0 | 0 |
| 切档重找 | — | — | 0 | 0 | 0 |

### 4.2 整页/整本的量

- **Architect 的 899 条实测**（394 页项目）：今天相邻两条差异之间中位 **122 字 / 6 行**、均值 220 字 / 9.8 行；表格三行约 **65 字**。所以「读多少」这一项是 **122 → 65**（默认单行），单字把它压到 2 字但只适用于字形类。
- **点击省不下来**：今天 Enter 判一条也是 1 次动作。三档/表格的 1/2 同样 1 次；用鼠标点按钮是 1 次。**不要对外说「点击减半」**。
- **本原型样张**：6 处真差异（第 27 回 p.1 四处、p.2 两处）+ 第 5 页一行三处（3 处）= **9 处 / 7 行**。这是一个小样本，不给「快多少倍」的结论；只用来验证交互与锚点。
- 三档的**档位收益**：单字把 65 字压到 2 字，但只在字形类；多行把 65 字升到 90 字，换来语义。默认单行是折中。

### 4.3 未实测

- 没有眼动仪、没有计时；点击/按键/视线跨区都是按交互路径和布局手数。
- 样张是 `sample-20p` 的**干净栅格化 PDF**，不是真实扫描（无倾斜/噪点/透印），OCR 结果偏乐观；这 6 处差异是引擎真输出，不是手写。
- 628 高、窄屏、真实保存/失败态没有在本原型里做；落地时按决议稿的 `edited` 三态和 `submit-drafts` 走。
- `word_boxes` 在两个项目实测 100%（456/456、5991/5991），但老项目可能为 0；单字档没有字框时必须退到单行。

## 5. 「处」的口径与分母（落地前必须定）

- **今天**：`LineDivergence` 一条 = 一行；队列 760 条 = 760 行（Chief 的数字），没有字级 offset。
- **原型**：前端用 `difflib`/`computeCharSpans` 对 `current/candidate` 逐字比对，得到连续差异段；**相邻的段合并**，不相邻的段拆成多处（第 5 页一行三处就是这么来的）。一处 = 一个连续差异段。
- **影响**：队列条数、进度分母、Jev 分数（行级）与「处」的对应都要重算；一条行级差异可能拆成 1–3 处，队列可能变多也可能变少。**不许把行数当处数**。
- **界面口径**：同时显示 `已判 N/9 处` 与 `行 N/7`；队列的每一行就是一处，点下去就判这一处。分母里不出现判不到的条目（插入/删除也能判，至少能在单行档判）。
- **Jev**：分数是行级，显示在这一行的条目上（`可疑 0.03`）；样张项目未打分，原型写 `Jev 未打分`，不编 0.03。分数在行文本改动后要清（Architect 已提）。

## 6. 实现落点（给 Builder）

1. **不新增接口**：队列顺序/分数 `/review/next-lines`（`include_scores=1` 可选），`current/candidate` `/review/marks?page=`，字框 `word_boxes`，行框 `marks[].bbox`；同一批 `(block_id,line_index)` join。
2. **字级 diff**：复用 `computeCharSpans`；按 `aStart/aEnd` 把一段连续差异合成一处；插入/删除单独标。
3. **字框 → 裁切**：`word_boxes` 拼接长度 = 行文本长度时按偏移；不等长按词位置；找不到就退单行。
4. **图片**：一张 `size=zoom` 页图，`<img>` 绝对定位；`left = stageW/2 - anchorX*scale`，`top = stageH/2 - anchorY*scale`；遮罩用四个不透明 div 围出洞（半透明在无头截图里会丢，opaque 也更像「只给这一处」）。
5. **锚点自检**：切档后读 `.target` 的 `getBoundingClientRect()`，与 stage 中心比，`|Δ| ≤ 1px` 才算通过。
6. **插入/删除**：单字档禁用；当前档是单字时自动切单行并 toast；不渲染空按钮。
7. **键盘**：`1/2` 采用、`V` 切档、`Tab` 输入、`Enter` 确认、`↑↓` 换一处、`⌘Z` 撤销；输入框聚焦时不抢 1/2。
8. **状态**：原型是前端假状态；落地接 `submit-drafts`，有 `aux_text` 写 `edited`，失败不前进、不静默丢文本。
9. **数字**：队列/顶栏都从同一份 points/rows 算；`处` 与 `行` 分开展示；Jev 未打分时写 `可疑 —` / `Jev 未打分`，不造数。

## 7. 验收（能机检的）

1. **锚点 0px**：单字/单行/多行切换后，差异字中心与 stage 中心的偏差 ≤1px（原型实测 0）。
2. **切档不换条**：按 `V` 三次回到原档，当前处、进度、队列位置不变。
3. **插入退化**：插入/删除处，单字按钮 disabled；从单字翻到该处时视图自动变单行，且提示出现。
4. **一屏一处**：每次只有一处被选中；队列只有一条 `.on`。
5. **数字对得上**：`已判 N/9` = 队列打勾数 = 实际判决数；`行 N/7` = 全部处都判完的行数；不拿行数当处数。
6. **键盘闭环**：20 条只用 `1/2/V/Tab/Enter/↑↓/⌘Z`，指针移动 0 次。
7. **图片真裁**：单字取景窗里只有这个字（字框外被遮），单行只有这一行，多行只有这三行。
8. **无提交按钮**：只有「确认」用于输入框；按钮 1/2 不加二次确认（确认只属于手写）。
