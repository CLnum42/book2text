## 2. 现在最拖慢用户的三件事

1. **1140 处差异的循环，每处 1–3 个动作，且每采纳一次就丢一次位置**（≈5818 动作，占全书 77%）。
   不是"差异看不清"（上一单已经解决），而是"看完一处 → 到下一处"这一段没有设计：没有下一处命令、采纳后整页重渲染、`<ol>` 被清空重建（`renderReviewBlocks` line 8324）、代码里没有任何 scrollTop 保存/恢复。
2. **794 次"补状态"点击排在 1140 处真差异之前**（版面确认 394 + 自动通过 152×3，≈1638 动作）。
   更糟的是**顺序被状态依赖卡住**：采用建议会重置版面确认 → 必须先建议、再确认版面、再自动通过；否则自动通过会被「版面未确认」拒绝（`review_status.AUTO_PASS_LAYOUT`）。这个依赖只写在 ⓘ 提示里。
3. **同一件事在 3–4 个地方各说一遍，每页都要重新读一遍**（394 页 × 3–4 次视线 ≈ 1400 次）。
   第 370 页上"两路分歧 13 行"出现在：顶部 80 字横幅（`app.js` 6361）、页头「两路分歧 13 行」、块头 chip「≠ 12 处」、差异条头「两路差异 1 行」。页头同时平铺 5 个按钮（全库采用建议… / 第二引擎复核 / 框选新增块 / 重新识别 / 自动通过本页），主次全无。

## 4. P0 重新设计

### P0-1 收尾面板：一处回答"这本书还差什么"

**问题**：6 个状态散在 5 个位置；两个状态只能逐页补；用户每次开工都要先找一遍"现在到哪一步"。

**入口**：页面视图底部主操作条右侧的 `⋯` 旁加一个 `收尾 3/6` 芯片（有未完成项时高亮为 `!`）；审校视图页头同位置也放一个。点击 → 右侧滑出 480px 抽屉（不是模态，不挡网格）。

```
┌ 收尾 ·《红楼梦》第三卷 ──────────────────────── ✕ ┐
│ ✓ 页面类型    394 / 394 已确认                      │
│ ✓ 版心        394 / 394 已定（拟合 355 · 回退默认 39）│
│ ! 版面确认    12 / 394            [确认全部正文页版面] │
│ ! 页码        未定位（可跳过）      [定位页码…]        │
│ ! 审校        152 页可直接通过 · 228 页要人看          │
│                                  [把 152 页标为自动通过]│
│ ✓ 第二引擎    394 / 394 已复核                      │
│ ─────────────────────────────────────────────── │
│ 还有 228 页需要人看       [从第 1 页开始审校 →]        │
│ 或现在导出，预检会记录 228 页未经人工确认  [导出…]      │
└──────────────────────────────────────────────────┘
```

规则：

- **每行 = 一个已有数字 + 一个已有动作**，不新增数据源（数字来自 `workflow` 汇总与 `summary`）。
- 状态记号在前（✓ / ! / ·），颜色只是第二次强化。
- 批量动作执行时抽屉内显示真实进度：`正在标记 128 / 152…`，带 `[停止]`；停止后已标的保留（逐页可撤销）。
- 批量自动通过在**前端循环**现有单页接口即可，不改后端；若 394 次请求太慢，再请 Builder 加批量接口（同一套 `auto_pass_page`，逐页判定）。
- 依赖顺序写进面板：`版面确认` 行未完成时，`审校` 行的"自动通过"按钮给 `title` 说明「先确认版面，否则自动通过会被拒绝」——这正是现在藏在 ⓘ 里的那句话。
- 为空的行（都做完了）**不显示**，不留禁用按钮。

**代价变化**：版面确认 1182 → 3；自动通过 456 → 4；状态查找（每阶段 2 次视线 × 6）→ 0（一处看全）。

### P0-2 差异队列：把"下一处"变成一次按键

**问题**：1140 处差异，每处 2 点击 + 1.5 滚动 + 一次重新定位；采纳后位置丢失。

**形态**：审校右栏顶部固定一条**队列条**（高 44px，跨块跨页都算）：

```
第 370 页 · 13 处差异 · 版面未确认                        [⋯]
┌────────────────────────────────────────────────────────┐
│ 第 3 / 13 处   汉字级 · 第 4 块 第 7 行                    │
│ …群花之蕊，冰馂之[殼→殼]，沁芳之…                          │
│ [采纳第二路 ⏎]  [保留原文 ␣]  [回上一处 ⌫]        ●●○ ○○… │
└────────────────────────────────────────────────────────┘
```

- 队列 = 本页所有块的 `divergence.marks` 按块序 + 行序排开（**不再受每块 8 行上限限制**，因为一次只显示当前那处）。
- 三条命令：`Enter` = 采纳第二路并进下一处；`Space` = 保留原文并进下一处；`Backspace` = 回上一处（已决定的可重开）。
- **采纳后局部更新**：只改该块文本、移除这一条标记、重算本块计数；不调用整页重载、不动滚动位置。
- 走完 13 处：队列条变成 `本页 13 处已看完（采纳 3 · 保留 10）` + `[确认本页并下一页 ⌘↵]`。
- **"保留原文"不写库**：它只在本页生效；离开本页未确认，队列重置（页面仍是待处理）。这是诚实的状态——不要为它造一个"已忽略"的假状态。
- 编辑框仍是最终事实来源：改字照常，改完该行差异自然消失（现算）。
- 队列之外保留原列表（想按块浏览的人不受影响）。队列条可以收起。

**键位补充**（说明书 7.5 已列的优先，新增两条）：

| 键 | 动作 | 状态 |
|---|---|---|
| `⌘/Ctrl + ↵` | 确认本页并下一页 | 已实现 ✓ |
| `Enter` | 采纳第二路 + 下一处 | 新增（P0） |
| `Space` | 保留原文 + 下一处 | 新增（P0） |
| `Backspace` | 回上一处 | 新增（P0） |
| `Alt + PageUp/Down` | 上一页 / 下一页 | 7.5 已列，未实现 |
| `⌘/Ctrl + Shift + U` | 标记 / 取消不确定 | 7.5 已列，未实现 |
| `⌘/Ctrl + Shift + E` | 排除 / 纳入当前块 | 7.5 已列，未实现 |
| `?` | 快捷键帮助 | 7.5 已列，未实现 |

**代价变化**：每处 2 点击 + 1.5 滚动 + 1 视线 → 1 按键 + 1 视线；5818 → 1368。

### P0-3 审校页头收敛：一页一行结论、一个主动作

**问题**：#6 + #7。每页要读 3–4 处同一事实，扫 5 个按钮。

```
第 370 页 · 正文 · 13 处差异（汉字 12 · 标点 1） · 版面未确认 · 漏行 1   [差异 13 ▾] [⋯]
                                              └ 一行结论，每一项可点跳对应处
[待处理 3][版心内 3][版心外 1][全部 4]        ← 保留（现有）
（中部：队列条 + 块列表）
[ 确认本页并下一页 ⌘↵ ]              采纳 2 · 保留 0 · 还剩 11 处   ← 唯一的页级主按钮
```

## 8. 未验证 / 风险

- **所有页数都是估算**：228 页有分歧、每页 5 行、152 页可自动通过，来自样张与任务 61 的记录，不是 394 页实测。Builder 跑完第二引擎后可用真实 `divergence` 汇总裁一次，把 §1 的表换成真数。
- **批量自动通过的耗时未验证**：前端逐页 POST 394 次，若每页 30–80ms，总计 12–30 秒，可接受；若后端每页要做全量判定（建议 / 漏行 / 差异）可能到 1–2 分钟——需要改成后台任务才合格。
- **采纳后局部更新的正确性**：假定"该行文本 = 候选后等级必然变 identical"。等级还取决于归一化（标点、空格），若候选行仍与其它行有归一化差异，本地移除会短暂不准——页面确认时以服务端为准即可，但要实测一次。
- **未在真实 394 页项目上跑过**：本文的代价表按代码与样张推算；建议 Builder 在真书上用秒表记 3 页的循环时间，校对第 1 节。
