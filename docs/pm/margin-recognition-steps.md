## 0. 结论

| 项 | 结论 |
|---|---|
| **A 顺序** | **调换：页面确认 → 文字识别 → 版心确认 → 目录 → 审校 → 预览 → 导出。** 不拆「版面检测」步，也不在版心步跑全量检测。页级拟合加「OCR 行回退」一处即可。 |
| **B 信息** | 两步各只留 **一行结论 + 一个主按钮 + 一个异常列表**；引擎 / DPI / 语言 / 双引擎策略 / 分歧率 / 把握度 / 复核计数全部折叠或移步，逐条写了去向。 |
| **C 空状态** | 没框就不画框、不说「已拟合」。新顺序下正常路径不会出现空版心；跳步进入时显示「等识别」，一个按钮「去文字识别」。 |
| **P0 数据安全** | 版心从「未定」变「已定」会让导出**第一次真正启用**过滤：267 页样书里 **26 页、30 个章/节标题块**中心在框外，会被静默排除，而现有 audit 报 0 页异常。**必须先定「文字列内的标题不因版心被删」，否则版心不能默认通过。** |

**前提修正：** 本文修正 `docs/pm/pipeline-decision.md` 里「版心在识别之前」的顺序。
当时的前提是「版心要提前定」；实测证明整页识别**不读版心**，检测行对版心也不是必需的。

## 1. 根因与数据

### 1.1 两个真项目：一页检测行都没有

| 项 | 《鹿鼎记》`b2t_XPAT9E` | 《导读巴赫金》`b2t_8AFV96` |
|---|---|---|
| 总页 / 正文 / 非正文 | 512 / **475** / **37**（front 33、toc 2、back 2） | 267 / **267** / 0 |
| `page_confirmed` | 512（页面确认已完成） | 0 |
| `page_layout_line` / `layout_run` | **0 / 0** | **0 / 0** |
| `page.margin_box` 非空 | **0** | **0** |
| 项目默认版心 | 有 `[0.0967,0.0821,0.8938,0.9544]` | 无 |
| `block_line` | 43 行（只识别过 1 页） | 335 行（识别过 14 页） |
| 任务表里的 layout 任务 | **0 条**（只有 1 条 ocr） | **0 条**（只有 2 条 ocr） |
| 页面工作流行 | 1 页 `ocr1_done`、511 页 `page_unconfirmed` | 空 |

用户按顺序走到版心步，拟合输入是 **0 行**；界面却写着「版心已自动拟合」。

### 1.2 依赖关系：谁真的需要谁

| 产物 / 动作 | 需要检测行？ | 需要 OCR 行？ | 需要版心？ |
|---|---|---|---|
| 版心拟合 | **是（唯一消费者）** | 否（代码没读，几何等价） | 否 |
| 整页识别（RapidOCR / Vision） | **否** | — | **否（整页识别，不裁图）** |
| 页码候选 | 否 | 是 | 是 |
| 审校队列（版心内）/ 导出过滤 | 否 | 是 | 是 |

代码事实：

1. `core/project/margin_box.py`：`_latest_layout_boxes()` 只读 `page_layout_line`；
   **`fit_page_margin()`（997 行）和 `page_margin_audit()`（1107 行）都只用它**。
2. 同一个文件的 `suggest_margin_box()`（576 行起）**早就会回退 `block_line`**，
   还读块类型、排除 `SKIP_BLOCK_TYPES`。**逐页拟合这条路径没接上。**
   → 这是「识别完了版心还是空的」的直接原因：不是没数据，是拟合函数没读 OCR 行。
3. `docs/workflow.md` 1.6：整页识别，不按检测行裁图。版心只在审校口径与导出里生效。

### 1.3 检测 vs 拟合的成本（用生产任务表，不用老文档的 4.8 秒）

| 项 | 数值 | 来源 |
|---|---|---|
| 单页版面检测 | **0.62 秒**均值（0.47–1.16，14 页） | 开发日志任务 58 |
| 同上，生产 394 次运行 | **0.78 秒/页**（306.6 秒 / 394 页） | `layout_run.elapsed_seconds` |
| 267 页整本检测 | **2.8–3.5 分钟** | 计算 |
| 475 页整本检测 | **4.9–6.2 分钟** | 计算 |
| 主引擎识别 | **1.22 秒/页**（267 页 326 秒） | `job` 表 `b2t_BRRBR0` |
| 第二引擎复核 | **1.3 秒/页**（20 页 26 秒） | `job` 表 `b2t_WVM18R` |
| 整本识别（主 + 复核） | 267 页 **约 11 分钟**；475 页 **约 20 分钟** | 计算 |
| 检测行 vs OCR 行 | 335 对 335，匹配 100%，四边偏差 **0.0000** | 开发日志任务 58 |
| 检测行的额外信息 | 只有 bbox / 置信度 / 顺序，**没有块类型** | L-71 |
| OCR 行的额外信息 | 有文本，**还有块类型**（可先排书眉/页码） | `suggest_margin_box` |

**结论：** 检测要花掉整本识别等待的 **25–55%**，产出的几何和 OCR 行一模一样，还少了块类型。

### 1.4 用 OCR 行拟合，实测（267 页样书）

只读复算：把每页 `block_line` 的 bbox 喂给 `fit_page_margin_box()`，不写库。

| 指标 | 结果 |
|---|---|
| 有文字行的页 | 258 / 267 |
| 拟合成功 `fit` | **253 页（94.8%）** |
| 兜底 `bbox`（行太少） | **5 页**（p1、p2、p18、p19、p252：标题页 / 窄行页） |
| 没有文字行 | **9 页**（45、67、109、131、155、195、211、229、239，连 block 都没有） |
| 正文长行跑到框外 | **0 页** |
| 258 页纯拟合耗时 | **15.3 ms**（不含读库） |

→ 版心步可以从「等 5 分钟检测」变成「识别完 0.1 秒出现」，默认通过站得住。
但「长行不越界」不等于「没丢内容」——见 1.6。

### 1.5 四个已确认的 bug（都有代码位置）

1. **谎报 A（文案）**：`static/app.js:3343`，只要版心步选中 1 页就写死
   「版心已自动拟合；拖动四边调整，不改也算已定」，不看这一页有没有框。
2. **谎报 B（计数）**：`ensureMarginFitted()` 用 `data.updated` 当进度（550 行），
   而 `fit_all_pages()` 把「拟合不出来」的页也算进 `updated`。
   → 巴赫金 267 页**一条框都没有**，界面显示「自动拟合完成：267 页」。
   接口同时返回 `fitted / fallback / undetermined`，前端没用。
   （`marginFitTried` 会把试过的页记死，同一会话里 OCR 后重进版心也不会重拟合。）
3. **检测按钮必然 400（512 页那本）**：`marginUndeterminedPages()` 返回全部
   `auto` 且无框的页，包含 37 个非正文页；`startLayoutDetection({pages, prepare:true})`
   全发给后端，`create_layout_job()` 遇到非正文页直接抛
   「第 N 页不是「正文」类型，不参与页面准备」。错误写进页面区顶部 `#pages-error`，
   不在按钮旁 → 用户看到「点了没反应」。
   证据：两个项目的 job 表里**没有** layout 任务。
4. **完成口径包含非正文页**：`finish_summary.margin` 分母是全部页（512），
   `stepProgress('margin')` 要求 `undetermined == 0`。37 个非正文页永远没有框
   → **版心步永远变不了绿**，哪怕 475 页正文全拟合完。

### 1.6 P0：版心一「已定」，导出就开始丢字（实测）

`margin_rules.classify_page()`：块中心在框外 → 移出正文，**没有块类型例外**。
拟合框天然只包连续正文长行；章首/节标题在正文块上方、间距更大，收不进来。

| 项 | 数值 |
|---|---|
| 中心在拟合框外的块（267 页样书） | 286 个 |
| 其中书眉 / 页码 / 纯数字 / 上下 6% 边带 | 256 个（正确排除） |
| **剩下的内容块（章标题、节标题、译后记、索引）** | **30 个块 / 26 页 / 约 195 字** |
| 现有 `page_margin_audit` 报的异常页 | **0 页**（它只数「正文长行」） |

例子：p4「我们今天 / 为什么需要导读书？」、p20「为什么是巴赫金？」、
p88「超语言学」、p110「对话主义」、p156「时空体」、p240「索引」。

这是最危险的一类「看起来优化了其实没有」：界面说 0 页异常、默认通过，导出悄悄少 30 个标题。
章标题还是双语对齐的唯一锚点（见 `ia-restructure.md`）。

**建议规则（需 Chief 拍板）：**

> **版心只用来排除「列外 / 上下边带」的家具，不用来删文字列里的字。**
> 块的 x 范围与版心 x 范围有重叠、且中心不在上下 8% 边带里 → 即使中心在框外也保留，
> 只计入「异常页」。书眉（顶带）、页码（列外）仍然排除；`heading/title` 类型无条件保留。

验收见 V4。这一轮不做，版心**不能**默认通过，只能标「建议检查」——那就回到繁琐。

## 2. A：步骤顺序

### 2.1 三个选择

| 方案 | 步骤数 | 每本书额外等待 | 版心步进来时 | 代价 | 结论 |
|---|---|---|---|---|---|
| ① 拆「版面检测」一步 | 8 | +2.8–3.5 / +4.9–6.2 分钟 | 有框 | 多一步；用户无法判断「检测行对不对」，这一步的确认只能空点 | **否** |
| ② 版心步内就地检测 + 拟合 | 7 | 同上 | 先等检测 | 进一个「调框」的步骤先等 3–6 分钟；要进度/取消/失败；等两次 | 兜底 |
| ③ **识别在前，版心用 OCR 行拟合** | 7 | **0** | 无框但**如实说** | 改两步顺序 + 文案；要用户接受 | **推荐** |

### 2.2 推荐 ③ 的理由

1. **顺着依赖走**：整页识别不读版心，版心读 OCR 行。
2. **不丢质量**：OCR 行与检测行同模型同 DPI（0.0000 偏差），还带块类型，拟合更干净。
3. **省一次等待**：4.9–6.2 分钟/本（475 页），而且是盯着进度条干等的那一段。
4. **消灭一整类 bug**：空入口、检测按钮、检测失败都不存在了。
5. **有文本时更好判断**：用户在版心步能读字，判断「这行算不算正文」比看空白页图容易。

### 2.3 代价与风险

- 用户已经看过七步顺序，要在版心步顶部写一句：「识别是整页的，版心只决定哪些字算正文；
  所以先识别，版心才有行可拟合。」
- 代码改动小：步骤顺序 + `stepProgress` 依赖 + 文案；现在用户其实已经能从第 3 步直接点识别，
  没有硬依赖阻止。
- **同一切片必须补 `fit_page_margin` 的 `block_line` 回退**，否则换了顺序版心还是空的。
- 某页 OCR 失败 → 没有行 → 版心未定；这页本来就要重识别，归入「等识别」，不算异常。
- 版心仍必须在**审校之前**（审校/导出口径依赖它），所以是「识别 ↔ 版心」对调。

### 2.4 若坚持「版心在前」

用 ②，但必须同时做到：只对正文页发检测；按钮旁内联进度与失败原因；检测完自动拟合并默认通过；
异常页只列「行在框外 / 兜底 / 无文字」。能用，只是每本书多等一次，且用户多理解一个概念。

## 3. B：两步各显示什么

原则：**这一步用户要做的唯一一件事 + 会挡住他的事 + 要等多久。** 其余折叠或移步，
移走的必须有入口。

### 3.1 版心确认：回答「这一页的正文范围对不对」

| 元素 | 处置 | 去向 / 依据 |
|---|---|---|
| 页图 + 版心框 + 四级缩放 + 四边拖动 | **必留** | 这一步唯一存在的理由 |
| 一行结论「475 页正文 · 474 页自动 · 1 页要你看」 | **必留** | 全局状态，不滚动可见 |
| 异常页列表（行在框外 / 兜底 / 文字列内标题在框外 / 无文字） | **必留（新增）** | 用户唯一要处理的入口；点一行跳页 |
| 当前页一句「自动拟合 · 24 行」 | **必留，压一行** | 删掉「把握：较稳/偏少/不足」 |
| 拖动后「撤销上次拖动」 | **必留** | 拖动必然需要回退 |
| 四边百分比 | **折叠** | 拖的时候显示在框上 |
| 默认版心 +「采用为默认版心」 | **折叠到 ⋯** | 低频；`inherit` 已在迁移 0017 转 auto |
| 四种 mode 的解释 / 重置为自动 / 改为整页 | **折叠到 ⋯** | 单页高级动作 |
| 「检测这一页的正文行」 | **折叠到 ⋯** | 兜底能力，不许删；正常路径用不到 |
| 「检测这些页的正文行…（N 页还没有检测行）」 | **删除** | 换成异常列表里的「等识别 / 检测这一页」 |
| 「把握：较稳 / 偏少 / 不足（N 条长行）」 | **删除** | 黑话；只在「行太少」时说一句「框可能不准」 |
| 版心外的书眉/页脚/页码 + 结构工具整块 | **移走** | 去导出预检 / 结构工具；与「框对不对」无关 |
| 逐页「下一页 ›」 | **降为次要** | 快捷键保留 |

**默认动作：没有按钮。** 进了这一步、框都在，就算已定（用户拍板「不调就默认确认」）。
只有异常页需要人；异常页为 0 时是 0 操作。异常页判定**必须和导出同一口径**：

1. 正文长行任一边越出框；
2. 兜底框 `bbox` 页；
3. 文字列内、中心在框外的内容块（1.6 的标题）；
4. 无文字页：识别成功且 0 行 → 「无文字，跳过」；识别失败 → 「等识别」，不算异常。

### 3.2 文字识别：回答「开始了吗、跑完没有、哪几页失败」

| 元素 | 处置 | 去向 / 依据 |
|---|---|---|
| 主按钮「识别全部未识别页（N）」/「识别所选」 | **必留** | 唯一起点 |
| 一行进度「已识别 1 / 475 · 失败 0 · 约剩 20 分钟」 | **必留（新增 ETA）** | 475 页 × 约 2.5 秒（主 + 复核） |
| 页内进度条「正在第 N 页」+ 暂停/取消 | **必留** | 不依赖右下角任务抽屉 |
| 页状态色（未识别/识别中/已识别/失败） | **必留** | 缩略图上，不要文字标签 |
| 失败页列表 +「重试失败页」 | **必留** | 阻断项 |
| 一句「识别完去版心确认；差异在审校逐条看」 | **必留** | 用户不知道下一步 |
| 引擎 / DPI / 语言 / 双引擎策略 | **折叠到「识别设置」** | 默认 RapidOCR + Vision 复核 / 200 DPI / 中文 |
| 「按版心判定正文」开关 | **移走** | 属于导出 / 版心 |
| 第二引擎「已复核 X/Y · 已跑完」 | **删除**，只在跑时给一句副标题 | 质量手段，不是用户动作 |
| 比过 N 行 / 汉字级 / 标点级 / 分歧率 / 空文本 N 行 | **移到审校概览 / 导出质量报告** | 在这里看到也不能做任何事 |
| 复核所选 / 复核全部未复核页 | **折叠到「高级」** | 主任务是识别；复核自动跑 |
| 「本步要做的 3 件事」「前置：版心 255/267」 | **删除** | 识别不需要版心；子步骤是内部实现 |

**完成判定：** 正文页主引擎全覆盖、失败 0 → 绿；第二引擎只做副标题，不阻塞。
（若 D-074 保持「第二引擎默认关」，识别步完全不显示第二引擎，但审校队列会没有差异条目——
这是另一个待拍板项，不在本文范围。）

### 3.3 628px 高度 / <1120 宽度

- 两步首屏都必须：**主按钮 + 一行结论 + 一行进度**不滚动可见。
- 版心右栏 628px：结论 2 行 + 异常列表最多 3 行 +「高级」折叠；更多异常滚动。
- <1120 宽：右栏可折到下方抽屉，但不能遮挡页面四边；四级缩放保留，版心步默认 100% 单页。
- 任何被折叠/移走的项，在「高级」或别的步都有入口；不允许只删不放入口。

## 4. C：新项目长什么样

### 4.1 推荐顺序下的状态

| 状态 | 版心确认 | 文字识别 |
|---|---|---|
| **新项目（0 行 / 0 框）** | 顶部一行「还没识别，版心要等识别完成再自动生成」；只画页面、不画框；唯一按钮「去文字识别」；步骤条未开始（不是绿） | 「0 / 475 已识别」+ 主按钮「识别全部正文页（475）· 约 20 分钟」；设置全折叠 |
| **识别中** | 一行「正在识别第 123 页；已完成的 122 页可以先生成版心」 | 「122 / 475 · 正在第 123 页 · 约剩 15 分钟」+ 暂停/取消；缩略图逐页变色 |
| **识别完成** | 框出现；「475 页正文 · 474 页自动 · 1 页要你看」；异常列表；0 按钮（默认通过） | 「475 / 475 · 失败 0」+「下一步：版心确认」 |

### 4.2 文案红线

- 没有框时**禁止**出现：「已自动拟合」「已定」「不改也算已定」「完成」。
- 没有行时**禁止**把「检测」当主按钮（推荐顺序下它不该出现）。
- 任何「完成 / 绿色」必须有可核对的数字（N/N、失败 0）。

## 7. 明确不做

| 不做 | 为什么 |
|---|---|
| 拆「版面检测」成独立一步 | 用户无法判断检测行「对不对」，确认只能空点；每本书加 3–6 分钟等待 |
| 版心步自动起检测任务 | 进一个「调框」的步骤被迫等；违反「不静默做事」 |
| 把版心挪到审校之后 | 审校/导出口径依赖版心 |
| 逐页确认版心 | 用户明确要「不调就默认确认」；会把 475 次点击加回来 |
| 在识别步展示差异明细 / 复核进度 | 属于审校；两步混在一起就是「信息多」的来源 |
| 删功能不给入口 | 每个折叠/移走的项在 §3 都有去向 |

## 9. 状态模型（给 Builder / Designer 对齐）

版心步的每一页只能落在下面四种之一。界面的「未定」只对应第 4 种；前三种都不该出现
「页页三选」。

| 状态 | 判定 | 界面 | 是否进分母 | 动作 |
|---|---|---|---|---|
| 已定 · 自动 | 有文字行，`fit` | 已定 | 是 | 无 |
| 已定 · 兜底 | 有文字行但长行 < 3，`bbox` | **已定，但进异常列表**（叫「兜底」，不许叫「自动拟合」） | 是 | 建议看一眼，不强制 |
| 无文字，跳过 | 识别成功、0 行 | 「无文字，跳过」 | **否** | 无 |
| 等识别 | 未识别 / 识别失败 | 「等识别」（不算未定，但**步不能变绿**） | 否 | 「去重识别」（回第 2 步） |
| 未定 | 有行、`fit` 与 `bbox` 都不成立 | 「未定」 | 是 | 自定义 / 不适用 |

**完成判定：** `识别完成（失败 0）` 且每个正文页都落在「已定」或「无文字」→ 绿。
所以第 4 种「未定」在真实书里应该接近 0；`等识别` 由第 2 步负责清零。

**后端要分开的三样（刀 1 一起做）：**

- `ocr_status`：recognized / failed / unrecognized（已有 `page_recognition_states`）；
- `has_text_lines`：这一页有没有 `block_line`（可由行数导出，不必新列）；
- `margin_box_method`：fit / bbox / NULL（已有）。

**明确不做：** ④ 帧的「每页三选（重试 / 自定义 / 不适用）」和「全部标为不适用」批量。
9 页无文字是**自动跳过**，不是让用户逐个决定；5 页兜底是**已定**，不是未定。
把这两种塞进 ④ 会让用户以为有 14 页要处理，实际是 0 页。
