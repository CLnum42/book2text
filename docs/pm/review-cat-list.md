# 审校页 CAT 式列表：四个口径与两页边界

> 作者：PM。日期：2026-11-05。状态：方案稿，待用户看图拍板；本轮只出静态图，不做产品代码。
> 依据：用户 CAT 列表构想（Chief 转述）；`docs/pm/review-three-views.md`、`review-preview-split.md`；
> 真项目读数（`b2t_YV1P2Y` 1676 条 / 923 条汉字差异；`b2t_YR5EJ0` 1182 行 / 1965 段）。

---

## 0. 结论

1. **列表负责"扫"，上下文负责"判"**——这个形状对：它把"一条一条翻"变成"先扫一遍、挑着判"。
2. **性能是能不做的前提**：1747 行必须虚拟滚动；取景窗共用**每页一张**页图（`background-position`），
   不是每行一个请求。判据：打开后 DOM 行数 ≤20、可见页图片请求 ≤3。
3. **"已编辑 / 已确认"是真三态，但只有两态写库**：已编辑 = 行级草稿（不写库、不进进度、上下文区不更新）；
   已确认 = 写库 + `diff_ack`（kept / adopted / edited 三值）。**点候选 = 采用并确认（1 次操作）**；
   只有手改需要 `Enter` 确认。这样 89% 的路径还是一次操作，草稿只出现在输入未完成时。
4. **候选只有两个，不做下拉。** `marks` 只给 `current`（当前采用文本）与 `candidate`（第二引擎）；
   第三引擎默认关、不在数据里；也没有"历史改法"。两个按钮 + 手改输入就够，下拉是空壳。
5. **列表行里显示的文字必须是"当前采用文本"**（导出用的那份），不是主引擎原文。采纳候选后行内红字应消失、
   状态变已确认；主引擎原文只放进展开的历史。否则"我在列表里看到的"和"导出的"不是同一份。
6. **5 行可以，但不能说"5 行 = 一段"。** 按条加权，只有 **24.1%** 的差异所在段 ≤5 行，76% 会被截断。
   5 行是取景高度，必须配"段续"标记 + 展开整段；别拿"中位段 4 行"当理由（那是按块算，不是按条）。

## 1. Q1 性能：1747 行怎么画

- **虚拟滚动是硬要求**：只渲染可见的 12–15 行 + 少量缓冲；滚出去的行回收。1747 个 DOM 行 × 每行一个取景窗，
  首屏必卡。
- **一张页图，多个取景窗**：同一页的 N 行共用一张 `size=zoom` 页图，行裁切用 `background-position` /
  `transform` 位移；**不是每行一个裁剪接口**（也不该新增裁剪接口）。
- **可视页才加载**：滚动到第 900 行时，只加载当前可见的那 1–3 页。
- 机检：打开样张，`document.querySelectorAll('.row').length ≤ 20`；Network 里 `image` 请求数
  ≤ 当前可见页数（≤3）；滚到第 900 行再数一次。

## 2. Q2 三态：未审校 / 已编辑 / 已确认

| 状态 | 含义 | 写库吗 | 进进度吗 | 上下文区更新吗 |
|---|---|---|---|---|
| 未审校 | 没有任何动作 | 否 | 否 | 否 |
| 已编辑（待确认） | 手改或试改，还没确认 | **否**（行级草稿，存 localStorage） | 否 | 否 |
| 已确认 | 判完（保留 / 采用 / 手改确认） | **是**：文本 + `diff_ack` | 是 | 是 |

- **点候选 / 按 1/2 = 采用并确认**，一次操作。这样"换了候选但没确认"这个暧昧状态不存在，
  用户不用猜"我点了它到底生效没有"。
- **手改 = 输入后 `Enter` 确认**；输入了没按 Enter、或焦点离开，状态是"已编辑"，列表里明确写「待确认」。
- **已确认之后还能改**：再改 → 回到"已编辑" → 再确认（覆盖上一次裁决，事件表可撤销）。
- **待提交是页面内存态**（不进 localStorage）：刷新 / 关窗口会丢，靠 `beforeunload` + 三键离开提示拦一次；
  页头常驻「N 处未提交」。
- 顶栏两个数分开写：`已确认 N / 总数` 与 `待确认 M`。**分母只算已确认**，与队列口径一致。

两页现在**同一套保存语义**（2026-11-05 用户定）：草稿 → 确认 → 写库，都有"待提交"状态与离开提示。
区别只在计数：审校页的确认会减队列（一行一次裁决），预览导出页的确认只改成品、不进队列。
写库路径是同一条（`submit-drafts`）。

## 3. Q3 下拉：只有两个候选，不做下拉

- `marks` 的字段就是 `current` + `candidate`（`blocks.py:634` 的 `LineDivergence`）。
- 第三引擎（仲裁）默认关，且不在 `marks` 里；没有"历史改法"的存储。
- 所以下拉里最多是「当前 / 第二引擎 / 手改…」三项，其中「手改」本来就是输入框——**下拉没有信息增量**。
  两个按钮（当前 / 候选）+ 输入框，是同一件事的更快形态。
- 例外：将来接第三引擎，或做"同一行改过的历史版本"时，再升级成候选列表；那时是数据变了，不是 UI 变了。

## 4. Q4 为什么 5 行

- **数据不支持"5 行 ≈ 一段"**：按条加权，差异所在段 ≤3 行 10.7%、≤5 行 24.1%、≤7 行 37.6%。
  也就是说 76% 的条目，5 行会截断段落。
- 5 行能给的是 **≈110 字**的连续上下文（21.9 字/行 × 5），足够判断"这个字放回句子里顺不顺"；
  它**不是**段落单位。
- 所以：**5 行作为默认取景高度可以接受**（用户明确说 5 行够），但必须加两件：
  1. 上下文区上下边缘有「⋯ 段续」标记，告诉用户前面/后面还有；
  2. 一键「展开整段」（到块边界），展开后列表让位、上下文区变高。
- 如果只做 5 行不做标记，用户会把截断当成段首/段尾，判错。

## 5. 列表和预览导出页的关系（2026-11-05 用户定：预览并入导出）

- **列表接走的是"在已标出的疑点里先扫一遍、挑着判"**，不是"通读成品"。
- **预览导出页负责成品本身**：组装、通读、改、提交、预检、导出。它也负责"机器没标出来的错"——
  两路一致但都错（约 2.5%）、段落合并、断词、标点归并误伤。这些东西在列表里**没有行**。
- 判据：列表里不存在"没有 mark 的行"；预览导出页里允许改"没有任何 mark 的行"。两条同时成立，边界就清楚。
- 列表下方那 5 行"已确认正文"是**局部上下文**，不是成品：只显示当前行邻域、只显示确认过的文本、
  不能滚动通读、不组装、不导出。成品只有预览导出页一处。
- 审校页**不渲染整本书流**：`renderReading` 一族整块退役，不留"以后可能用得上"的入口。

## 7. 不做

- 不做每行一个裁剪请求 / 每行一个 `<img>`。
- 不做只有两项的"候选下拉"（用两个按钮）。
- 不把"处"做成队列单位：列表行仍是**一行一条**，行内多处用 ①② 分段选择，混选落成 `edited`（同三视图口径）。
- 不在列表里显示主引擎原文当"当前文本"（会与导出的文本不一致）。

## 8. v2 修订（2026-11-05 用户看原型后的四条）

### 8.1 单行图：放大的是"字形"，不是"行高"

- 目标：差异字的字形高度 **20–24px**（判「入/人、己/已/巳」要看到笔画）。
- 只加行高不够：CJK 全角下**字宽≈字高**，22 字的整行在 22px 字高下要 **≈484px 宽**（p90 行 28 字要 616px），
  列表左侧没有这么宽。
- 所以：**图裁到"差异段 ±8 字"（约 17 字 ≈ 374px）**，两端渐隐 + 省略号；**完整行在右边文字列**，不在图里。
- 行高 **56–64px**（默认 64），一屏 **6–7 行**；紧凑档 40px（字 ≈14px，只定位不辨形）不作默认。
- 机检：64px 行里差异段字形高度 ≥20px（按裁切宽度与列宽的缩放比算，或量渲染图的字框）；图列宽 ≥340px
  （17 字 × 22px ÷ (20/22)）。

### 8.2 两个按钮 = 两个版本；第三个动作是"改这一行"

- 按钮 1 **「保留当前」**（`kept`）：文字是**当前采用文本**。**不要叫"主引擎"**——`block_line.text` 会随编辑同步，
  入库后行级主引擎原文不再单独保留；未改过的行两者相同，改过的行"主引擎原文"只在事件里，不作为候选。
- 按钮 2 **「采用候选」**（`adopted`）：第二引擎文本。
- 第三个动作：**点行内文字直接编辑 → `Enter` 提交**（`edited`）。三个动作一一对应三个 ack。
- 一侧为空时按钮显示「（无）」+「多出 / 少了 N 字」，**不画空格**。

### 8.3 行内编辑：单位是行，提交前看得到改了什么

- 编辑的是**这一行的文本**，不是"一处"；`Enter` 提交、`Esc` 取消；IME 合成中（`isComposing`）不提交；
  行内不能打换行（要拆段走结构操作）。
- 高亮：进入编辑后，原差异红字换成**"本次改动"的下划线**（相对编辑前的行文本）；提交前保留，
  提交后行离开队列、痕迹消失。原差异已经在两个按钮上，不要两层高亮。
- 与预览导出页**逐字一致**：行内编辑、`Enter` 提交、`Esc` 取消、待提交视觉、会话内痕迹。

### 8.4 下方上下文：fit width + 5 行高

- 图片按**整页宽 fit**（`width:100%`，横向不裁），纵向只取 **5 行高**，中心对齐差异行；上下加「⋯ 段续」。
- 5 行是取景高度，不是段落单位（只有 24.1% 的差异所在段 ≤5 行，见 §4）。
- 机检：1280 宽、目录展开时，上下文区图片宽度 = 容器宽度，右边缘没有字被裁掉。

### 8.5 多选：先进入"多选模式"再选行

- 点底部「多选」进入选择模式：此时**点行 = 选中 / 取消**（不再进入编辑）；面板列选中行，标「待提交 / 跳过」。
- 只提交选中里的待提交行；按钮写实际数（选中 5 行 · 3 处待提交 → 「提交选中的 3 处」）；
  选中里待提交为 0 时按钮禁用（不给"提交 0 处"）。
- 退出模式 / 提交后回到"点行 = 编辑"。Designer 的多选面板按这个入口就成立——之前"选 5 行"缺的是
  进入模式的那个手势。

### 8.6 数字

`1747 / 3031 / 20.5` 继续标「待核」，见 §6；图上用真实项目读数时带项目 ID。


## 9. v3 修订（2026-11-05 用户看 v2 后的五条）

### 9.1 上下文：默认 3 行 + 展开 ±3 + 看整段

- 数据：±1 行覆盖差异所在句 **90.3%**、±2 97.7%、±3 99.8%（Architect 实测）；76% 的段 >5 行，
  所以"看完整段"本来就不该做默认。
- 默认 **3 行**（差异行 ±1）；行尾「展开 ±3」（7 行）、再「看整段」（该段全部行，下方区可滚动）。
- 高度按 **3×行高 + 上下余量**算足，**fit width、横向不裁**（v2 只露两行是高度没算够）。

### 9.2 序号是"位置"，不是 ID

- 写 **`第 38 / 1623`**（当前视图的队列总数），不写 `#2134`。
- **`2134` 不能当分母**：它是 `block_line.diff_status='differs'` 的**历史快照**（`b2t_YV1P2Y` 实测 2134），
  含 458 条后来被人工改到一致的行、53 条不进队列的（版心外 47 + 其他类型 6）。当前队列是 **1623**。
- 分母必须与列表行数同源；切换排序（阅读顺序 / 可疑度）时**总数不变、位置变**。

### 9.3 状态 gutter

- 图与文字之间固定 **72px** 竖列，放状态词 + 圆点；每行状态在同一竖直位置，用于"扫一眼数橙色"。
- 状态词统一为 **未审 / 待提交 / 已确认**（"已提交"是动作，"已确认"是状态；两页同一套词，别出现"已编辑"）。

### 9.4 红色要分两种

- **机器差异**：红字 + 细下划线（现状）。
- **人工改动**：红字 + 浅红底（或波浪线），数据来源是**本次编辑前后**的 session diff；提交后保留但**降饱和**，
  变成"痕迹"而不是"警告"。
- 边界：库里没有行级 OCR 原文（`block_line.text` 会随编辑同步），所以**跨刷新重建不了"人改的是哪几个字"**；
  刷新后只剩 `diff_ack`（判过 / 改过）。持久的人改区间要加"行级改动区间/时间"列，v1 不做。
- 提交后该行离开队列，红字 / 底色随行消失；撤销后重新出现时按新 session 重新算。

### 9.5 左右居中：各自中线 + 等宽，不是"同一个屏幕 x"

- 左图裁窗以差异字为中心（已有）；右文把差异字放中线，左端省略号截断、右端同理。
- 两块**等宽**，所以视线在两块之间平移的距离固定；**并排布局做不到"两块共用一个屏幕 x"**，验收别按那个写。
- 截断窗口 = `max(两侧各 12 字, 差异段全长 + 两侧各 8 字)`（差异段最长 33 字，12+12 盖不住）。
- **截断与行内编辑冲突**：进入编辑必须把该行**展开成完整行**（不截断），否则只能改看得见的部分；
  提交后回到截断态。这条写进交互，不然实现会做成"只能改露出来的字"。

### 9.6 参数与数

行高 64、一屏 7 行、gutter 72、两侧各 12 字都是设计参数；分母用本项目当前队列 **1623**，不是 2134。
