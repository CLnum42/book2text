# 40 条计时：正文审校的验收方案

> 作者：PM。日期 2026-10-28。状态：可执行方案，等 Chief 排时间与副本。
> 目的：把「一条多久」「碎片化能不能省 30%」「还有没有静默跳过」从假设变成实测。
> 本方案不写代码；需要的两个前置（计时脚手架、两个项目副本）写在第 6 节。

---

## 0. 结论先行

1. **分两个阶段。** 阶段 1 验 P0-a（判决即前进 + 修 Enter）：**5 分钟、不需要对照臂**，只验协议；
   阶段 2 验 P0-b（面板碎片化）：**旧臂强制一次 20 条（10–15 分钟）**，新臂随日常使用顺带采集，不单独排期。
   用户必付成本是 **5 分钟 + 一次 10–15 分钟**（2026-10-28 Chief 拍板）。
2. **计时必须由程序打点，不掐秒表。** 要的三个时刻是"下一条就位""本条判决""再下一条就位"，
   人工观测误差比要测的效应还大。
3. **主指标是中位单条总耗时（判 + 前进），不是平均值**；40 条里会有几个长尾（走神、回看页图），
   平均值会被它们拉走。
4. **噪声组和真错组分别设线**：碎片化的目标是让 80.9% 的噪声更快，**不能让 11.3% 的真错变慢**。
   只有总耗时达标、真错变慢，这个改动就是拿错了换对的。
5. **P0-a 的"省多少分钟"从此不可测。** 旧的"关面板 → 点工具条 → 重找"循环在 P0-a 合入那一刻就消失了，
   没有旧臂可对照。以后只能报"动作数 3→1、工具条往返 0"这个结构事实，**不得报分钟数**。
   这一条写进文档，防止半年后有人拿它当实测引用。

## 1. 选样：40 条怎么来的

**来源**：`gold_standard/红楼梦第一卷_正文前40页_图像版.pdf` 的 40 页金标准（唯一有真值的语料）。
标注直接用 `/tmp/b2t-heuristic-eval/analysis.json` 的 `rows`（231 条可定位，含 `page / index / level / cls`，
cls ∈ A / B / C_both_wrong / C_both_ok）。

| 组 | 条数 | 从哪取 | 分层 |
|---|---|---|---|
| 噪声 | 20 | `cls = A`（187 条） | 按金标准实际比例：汉字级 99 / 标点级 88 → **11 汉字 + 9 标点** |
| 真错 | 20 | `cls ∈ {B, C_both_wrong}`（42 条） | 同上：汉字级 15 / 标点级 27 → **10 汉字 + 10 标点** |

**硬性要求（每条都要满足）：**
- 排除：跨页段（`continues`）、第二路空文本、版心外、`format_only`（没有可看的差别）；
- 映射：`(page, index)` → `block_id + line_index` 必须靠 `block_line` 查，且文本与金标准一致率 ≥98%；
  对不上的行**换掉而不是硬凑**，换了几条要写进清单；
- 固化：清单写入 `docs/pm/timing-set-v1.json`，字段
  `item_key / page_no / line_index / level / cls / 差异字数 / 集(A|B)`；任何人重跑都用这同一份；
- 分两集：**A 集 10 噪声 + 10 真错（正式用）**，B 集同样（**备用**），**seed 固定**，集内顺序打乱。

**两集怎么用（2026-10-28 改）**：旧臂跑 A 集 20 条；4.3 的可选补测**重跑同一批 A 集**（同 item_key，
这样才能配对）。B 集不是第二轮，是**替补**——映射对不上、条目被排除时按序替换，保证正式集永远是 20 条。
两集的分层比例一致，所以替换不破坏分层。

## 2. 计时怎么打点（这是方案的核心，不是附带）

三个时刻，全部由程序写：

| 字段 | 什么时刻 | 说明 |
|---|---|---|
| `current_at` | 这一条成为当前条、面板就位的那一帧 | `openReadingPanel` / 新面板就位后 |
| `decided_at` | 判决落草稿的那一帧（保留 / 采纳 / 改完） | 写 ack 或草稿的动作 |
| `next_current_at` | 下一条成为当前条的那一帧 | 阶段 1 之前这里是"用户自己点工具条"之后 |

由此得到两个可分开报的数：

- **t_judge = decided_at − current_at**（读 + 判断）
- **t_advance = next_current_at − decided_at**（前进 / 重新定位）
- **t_item = t_judge + t_advance**（用户真实体验的一条成本）

**还要记**：`action`（kept / adopted / edited）、`ui`（old / new）、`session_id`、`silent_skip`（见 3.1）。

落地方式（Builder 的一个小切片，约 20 行）：写 `event` 表或项目目录下 `timing.jsonl`，
一行一条；**不含原文**，只有 item_key 与时间戳，可以进仓库的派生统计。
产品上线后这个计时器就是 ETA 的数据源，不是一次性脚手架。

## 3. 阶段 1：验 P0-a（5 分钟，无对照）

P0-a = 判决即前进 + `Enter/ Space / E / Esc` + 修掉"面板开着 Enter 跳过"。

**样本**：用 A 集 20 条，只跑一遍新 UI（P0-a 已合入的构建）。

阶段 1 **不只是计时**，它同时是 P0-a 的行为验收——两个 bug 在这里当场验：
面板开着按 `Enter` 必须落 ack 且不跳走；点红字进入后按 `Enter` 必须去**这一条之后**的下一处。
这两条不过，后面的耗时数据没有意义。

**通过线（三条全过）：**

| # | 指标 | 通过线 | 怎么算 |
|---|---|---|---|
| 1.1 | **静默跳过** | **0 次** | 有 `goto_next` 但当前条没有 `decided_at` 即记一次 |
| 1.2 | 每条前进耗时 `t_advance` | **中位 ≤0.4 s** | 从判决到下一面板就位 |
| 1.3 | 每条指针动作 | **≤1 次，工具条往返 0 次** | 日志里的 click 事件按条聚合 |

**不过怎么办**：1.1 >0 → 不发版（这是丢判断，不是体验问题）；1.2 不达标 → 说明"就地换内容"
仍有滚动/重绘卡顿，先查性能再谈 P0-b。

## 4. 阶段 2：验 P0-b（旧臂强制 + 新臂顺带采集）

### 4.0 这一版和上一版的差别（Chief 2026-10-28 拍板）

| 项 | 上一版 | 这一版 |
|---|---|---|
| 旧臂 | 强制 | **强制（唯一不可逆时间窗）** |
| 新臂 | 强制第二次 20 条 | **不排期，随日常使用采集** |
| 用户成本 | 4 段 × 10–15 分钟，跨两天 | **5 分钟 + 一次 10–15 分钟** |

三个必须写清的后果：

1. **两臂都跑在 P0-a 之后**，所以两臂之差**只剩"面板"一个变量**。P0-a 的收益由阶段 1 的协议门槛
   单独验，不进这个对比——这也让面板的效果更干净，不被"前进"冒领。
2. **P0-a 的分钟收益不可测**（见 §0 第 5 条）。这是拍板的代价，不是遗漏。
3. **新臂是日常使用，条目与旧臂不同 → 严格配对不存在。** 见 4.3。

### 4.1 旧臂（强制，10–15 分钟，只跑一次）

- **时机**：**P0-a 合入之后、P0-b 合入之前**。这个窗口一过就永远没有对照臂了。
- **样本**：固化清单的 **A 集 20 条（10 噪声 + 10 真错）**，一次跑完。
- **环境**：项目副本 1（从与后续新臂相同的原始 `.db` 复制）；同一台机器、窗口、缩放、时段。
- **纪律**：不看表、不赶时间、不回头改、不切窗口；判完就判完。
- **归档**：跑完立刻把 `timing.jsonl` 复制为 `old-arm-v1.jsonl` 存好（只含 item_key 与时间戳，不含原文）；
  副本项目删除或留档均可，但**归档文件不能丢**。

### 4.2 新臂（顺带采集，不排期）

- **来源**：P0-b 合入后，用户日常审校产生的真实 `timing.jsonl`。产品里本来就会一直写，不需要额外动作。
- **门槛**：累计 **≥60 条**（其中 ≥20 噪声、≥20 真错）才做第一轮比较；之后每 +60 条更新一次。
- **混杂必须写进报告**（这些是组间比较的代价）：
  - 不同书、不同页、不同难度 → **跨书不合并，按层报**；
  - 疲劳与熟练度随时间变化 → 报采集的起止日期，不假装时间无关；
  - 新臂没有"每条都看页图"的强制，行为可能自然改变 → 结论只写"在这批条目上"。
- **结论措辞**：新臂顺带采集的结果只能叫**方向性证据**，不得写"省 X%"。

### 4.3 可选补测（5 分钟，不强制，唯一能给精确百分比的路径）

如果组间方向不明确、或差异 <15%：让用户在新版本上**重跑同一批 20 条**（同 item_key、同顺序），
拿到真正的配对数据 → Wilcoxon 符号秩检验。这是唯一能写"省 ≥30%"的依据。

> **Wilcoxon 保留**：它只在"同一条目两臂都判过"时成立。日常采集的新臂条目与旧臂不同，
> 拿来做配对是错的——这一点不许含糊。

### 4.4 通过线

| # | 指标 | 通过线 | 统计方法 |
|---|---|---|---|
| 2.1 | **主指标**：分层中位 `t_item`（旧臂 20 vs 新臂 ≥60） | **≤0.70 → 有资格说"省 30%"**；≤0.85 → "有改善但不到 30%"；>0.85 → "没改善" | 组间：Mann-Whitney U + bootstrap 中位 CI。**不拿 p<0.05 当通过线**（n 不等、非配对，功效不够），只报效应量与区间 |
| 2.2 | 噪声组中位 `t_item` | ≤0.65 | 同上 |
| 2.3 | 真错组中位 `t_item` | ≤1.10（不许明显变慢） | 同上 |
| 2.4 | 真错误判（B/C1 判成"保留"） | 旧臂 ≤2/20，且新臂不高于旧臂 | 计数 |
| 2.5 | 静默跳过 | **0 次** | 有 `goto_next` 无 `decided_at` 即计一次 |
| 2.6 | 主观（3 题 5 分制） | 眼累 / 知道还剩多久 / 敢不敢去倒水，均 ≥4 | 参考，不作否决 |

### 4.5 结论怎么读（预先写死，不许事后解释）

| 情况 | 结论 |
|---|---|
| 2.1 ≤0.70 且 2.2 ≤0.65 且 2.3 ≤1.10 | 面板保留，按 Designer 稿实现 |
| 0.70 < 2.1 ≤ 0.85 | 面板有效但不够 30%：按差异长度分档（**1–2 字折叠，≥3 字默认整行**） |
| 2.1 >0.85 | 面板无实质收益：回到"整行 + 差异字加粗"的中间态，只保留 P0-a |
| 2.3 >1.10（真错变慢） | 无论总中位多好，一律分档 |
| 4.3 补测后 Wilcoxon p<0.05 且中位 ≤0.70 | 才可以对外写"省 ≥30%" |
| 2.5 >0 | 无论耗时多好，不发版 |

## 5. 谁跑、跑几次、数据放哪

- **执行人：用户本人**。PM 主持流程、读数、写报告；Chief 排旧臂的时间窗与副本；
  Extractor 不参与人工；Builder 只按任务书写 `timing.jsonl`，不参与读数。
- **用户成本（必付）**：阶段 1 约 **5 分钟**；旧臂一次 **10–15 分钟**。
  可选补测 **5 分钟**，只在 4.3 条件触发时。
- **数据**：
  - `timing.jsonl` 原始文件在项目目录（产品一直写，只写不读）；
  - 旧臂归档 `old-arm-v1.jsonl`；
  - `docs/pm/` 只放派生统计（中位、CI、条目数、分层表），**不含原文、不含差异文本**。
- **报告**：一页。表 1 阶段 1 的三条协议指标；表 2 旧臂/新臂按层的中位与 CI；一句结论 + 一句局限。

## 7. 局限（先写清楚，免得数字被当真）

1. **旧臂 n=20、新臂 n≥60 的组间比较只能看方向**：效应 <15% 分不出来；不宣称精确百分比。
2. **单用户**：结论是"这位用户在这批条目上更快"，不是"所有人都更快"。
3. **金标准是 200 DPI 第一卷**：旧臂条目形态可能与真书第三卷（竖排、繁体、书眉多）不同；
   新臂又是真书 → 两臂不同源，这是本方案最大的方法学代价（见 4.2 的分层要求）。
4. **新旧臂不是同一天**：疲劳、熟练度、甚至软件的其他改动都会混进来；报告必须写采集日期区间。
5. **P0-a 的收益没有实测值**（动作数 3→1 是结构事实）。
6. **旧臂的"20 分钟/573 条"本身可疑**（2.1 s/条，比中文书 8–12 s 快 4–6 倍）。
   这次同时会把它证伪或证实——**在那之前，那两个工时都不要写进任何界面**。
