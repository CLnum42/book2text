# 审校页三视图分档：默认、切换与锚点

> 作者：PM。日期：2026-11-05。状态：方案稿，待用户确认；本轮不写产品代码。
> 依据：用户三视图构想（Chief 转述）；`docs/pm/review-table-view.md`（上一版表格口径）；
> 真项目读数 `b2t_YV1P2Y`（923 条汉字级差异，队列内 899）。
> 一句话：三档不是三个页面，是**同一行的三种取景**；视图只改"看多少"，不改"判什么"。

---

## 0. 结论

1. **默认单行。** 单行对 100% 的条目可用；单字只对 **83.3%**（单段差异）可用，用它做默认会让 16.7% 的条目
   每条都要先切一次。多行留给"要看语义"的少数。记住上次选择，但**可用性优先于记忆**。
2. **切换用键盘，但键位不是 1/2/3**——`1`/`2` 已经给了判定（保留当前 / 采用候选）。
   用 **`V` 循环（Shift+V 反向）**，页头同时给可点的分段控件。**不做"按差异类型自动切"**：
   切档会让版面在条目之间变，锚点与手的记忆全乱。
3. **锚点一致 = 以"差异段中心"为锚，切档时锚点钉在图片区的同一点**（宽 50%、高 40%），
   判定按钮与页头也不动。机检：三档来回切，锚点屏幕位移 ≤2px。
4. **"一处差异"有两个口径，先定义再数。** 现有 mark 是"一行一条"（899 条 = 899 行）；
   用户说的"处"是"一段连续不同的字"。按后者算，这本书 **16.7% 的行有多段**，队列会从 899 涨到约 **1075（+20%）**。
   **本轮不把"处"做成队列单位**：裁决是行级的，改成"处"要改存储和分母。用户的"分开审"用另一种方式满足（§4）。
5. **插入 / 删除在单字档不能并排**：一侧没有字，两个按钮上下堆叠，图仍只给差异段（不画空格）。

## 1. 三档的定义与可用条件

| 档 | 图片区 | 文本区 | 可用条件 | 覆盖率（923 条汉字级） |
|---|---|---|---|---|
| 单字 | 只给**差异段**放大（2.5×） | 两个判定按钮（+ Tab 出输入框） | 该行只有**一段**改动（含单侧为空） | **769 / 923 = 83.3%** |
| 单行 | 差异**整行**放大（1.5×） | 当前行（高亮差异段）+ 判定 | 全部 | 100% |
| 多行 | 前一行 + 差异行 + 后一行（1×） | 当前行 + 判定 | 全部 | 100% |

细分（同一批读数）：

| 类型 | 条数 | 占比 | 单字档 |
|---|---|---|---|
| 单段、两侧各 1 字（替换） | 585 | 63.4% | ✅ 最典型 |
| 单段、一侧为空（插入 / 删除） | 128 | 13.9% | ✅ 但按钮上下堆叠，不并排 |
| 单段、多字或替换不等长 | 56 | 6.1% | ✅ 图里是 2 个字以上 |
| 多段（2 段以上） | 154 | 16.7% | ❌ 一屏放不下多处，用单行档 + ①② 编号 |

**可用性规则**：记住的档在当前条目不可用时（如多段行 + 单字档），**这一条**降到单行并在页头写一句
「这一条有 2 处改动，单字视图放不下」；**不改**记住的偏好，下一条恢复。

## 2. 默认哪一档：单行

- 单行同时给出"这一行是什么"和"差异在哪"，是唯一对全部条目都成立的档。
- 单字只在**看不准字形**时才有额外价值（入 / 人、己 / 已 / 巳、士 / 土）。这是人的判断，不是数据的属性；
  按类型自动切会把 16.7% 的多段行排除在外，还要用户学一条规则。
- 多行只在"这个字放回句子里对不对"时才需要（约 11% 的两路都错条目里更常见），作为可选。

---

## 3. 怎么切：`V` 循环，不做自动

**键位冲突必须先解决**：上一版表格定了 `1`=保留当前、`2`=采用候选，用户这轮又提"1/2/3 切视图"。
同一组键不能有两个意思——按下去到底切视图还是判一条，用户会猜错。
另外 `Z` 已被跨页延续面板占用（`continuation-review.js:374`，那里是"撤回"），所以视图键用 `V`（当前没有任何绑定）。
模态面板打开时 `1`/`2` 归面板，表格不响应（沿用 `stopImmediatePropagation`）。

| 键 | 动作 |
|---|---|
| `1` | 用当前整行（kept） |
| `2` | 用候选整行（adopted） |
| `Tab` | 进输入框（单字档里输入框默认隐藏，Tab 才出） |
| `Enter` | 确认输入（edited） |
| `V` / `Shift+V` | 循环切视图（单行 → 单字 → 多行 → 单行） |
| `Esc` | 退出输入 / 关闭面板 |

- 页头给可点的分段控件（单字 / 单行 / 多行），当前档高亮；`V` 与点它是同一个动作。
- **记住上次选择**（按项目存 localStorage）；只在"记住的档不可用"时按 §1 降级。
- **不按差异类型自动切**：理由见结论 2。

## 4. "一处差异"的口径与"分开审"

### 4.1 两个口径，两个数

| 口径 | 定义 | 这本书的数 |
|---|---|---|
| mark（现有） | 一行最多一条，`block_divergence` 整行比对 | 899 条 = 899 行，**0 行有多条** |
| 处（用户说的） | 一段**连续不同**的字；前后不相邻就算两处 | 923 条汉字级里 **154 行（16.7%）有多段**，总共多出 181 段 → 队列约 **899 → 1075（+20%）** |

**不把"处"做成队列单位**，三个理由：

1. 裁决是**行级**的：`block_line.diff_ack` 一行一个值（`editing.py:833`）。拆"处"要么加一张按处的裁决表，
   要么让一行出现两个 ack——两条路都比这轮的范围大。
2. 分母会变：899 → ~1075，刚定下来的进度、完成度、Jev 选行全要重算。
3. 用户要的是"分开看/分开定"，不一定非要"分开计数"。

### 4.2 用户的"分开审"怎么满足（不新增存储）

同一行有多段时，表格里用 `①②` 标出，**逐段选择**，最后合成一行文本写库：

- 全部选当前 → `kept`；全部选候选 → `adopted`；
- 混选（A 段当前、B 段候选）→ 合成后的行文本作为 `edited`。
- 这不需要新表、不改分母；只是把"编辑框"换成"逐段拼装"。

代价要写清：混选会让"采纳候选"的统计少算（记成 edited）。这是诚实的——那一行本来就没人给过完整答案。

## 5. 锚点一致（切档不跳）

**锚点** = 差异段中心（`word_boxes` 里那几个字的框中心；没有字框时退行框中心）。

| 切档时固定不动 | 怎么保证 |
|---|---|
| 图片区的锚点 | 差异段中心始终落在图片区 `(50% 宽, 40% 高)`；缩放围绕它 |
| 判定按钮 | 固定在右栏底部同一位置，不随视图高度变 |
| 页头（第几条 / 页码 / 行号） | 固定在表格顶部 |
| 队列行 | 不滚动、不重排；当前行保持原位 |

机检：同一条目在 单行→单字→多行 之间来回切 3 次，锚点屏幕坐标位移 **≤2px**，按钮与页头 **≤2px**。
没有字框的条目（实测两个项目 100% 有，但别的书可能没有）退行框中心，并在页头标「无字框·按整行定位」。

## 6. 测量（沿用上一版协议，补两项）

四个量不变（必读字数 / 人工比对字数 / 操作数 / 视线切换）。补两项：

| 量 | 定义 | 通过线 |
|---|---|---|
| 切档次数 / 10 条 | 用户主动按 `V` 或点分段控件的次数 | ≤2（默认单行应让多数条目不用切） |
| 切档后重新定位时间 | 切档到能继续判的时间（看锚点是否跳） | ≤0.5s，且无滚动 |

**必读字数按档算**：

- 单行 = 当前行 21.9 字（平均）+ 两个片段 2.9 字 ≈ **24.8**
- 单字 = 两个片段 2.9 字 + 图（字不算阅读字数）≈ **2.9**
- 多行 = 当前行 21.9 + 前后行约 44 + 片段 2.9 ≈ **68.8**（所以多行不该是默认）

## 7. 不做

- 不把"处"做成队列单位 / 不新增按处裁决的存储（§4.1）。
- 不做"按差异类型自动切视图"（§3）。
- 不在单字档里塞整行（那它就是单行档了）；整行只在单行 / 多行档出现。
- 不为三档新增后端接口：图的取景用同一张 `size=zoom` 页图 + CSS 变换，字框来自 `word_boxes`。
