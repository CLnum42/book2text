# 审校页表格视图：产品口径、规格与测量

> 作者：PM。日期：2026-11-05。状态：方案稿，待用户确认；本轮不写产品代码。
> 依据：用户 2026-11-05 表格构想（Chief 转述）；`docs/pm/review-preview-split.md`；
> 真项目读数 `b2t_YV1P2Y`（394 页 / 1676 条差异）与样张项目 `b2t_5DDDAP`（sample-20p / 20 页 / 41 条）。
> 代码基线 `main@e4cfc14`。

---

## 0. 结论

1. **表格一行 = 队列一条 = 一行文本。** 今天的差异数据结构是"每行最多一条 mark"：实测 1676 条差异
   （含版心外与其他类型；队列内 1623）落在 1676 行上，不会出现用户担心的"同一行重复出现"。
   但**一行内可能有 2 处以上改动**（实测 87.9% 1 处、10.9% 2 处、1.2% ≥3 处），
   所以两个按钮必须写清"**用整行**"，不能写"用这个字"——按钮的动作是整行替换。
2. **右栏不要再重复显示"当前整行"。** 用户原话要求右栏顶部放一份当前行；按实测字数算，重复之后
   必读字数从 24.8 涨到 46.7，**反超今天的 44.2**，优化归零。当前行只出现一次（左栏高亮那行）。
3. **默认带 PDF；不给 PDF 的版本作为"专注模式"给他选。** 理由都在数里：约 11% 的条目两路都错、必须人写；
   33% 的改动片段有一侧是空的（插入 / 删除）；形近字（士 / 土、旱 / 早）在 12px 下两张按钮长得一样，
   只能看原图。
4. **上下文默认 ±1 行 + 段边界标记，可一键展开到 ±3。** 实测 **27.6%** 的差异行在段首或段末
   （首行 251/1676、末行 211/1676），固定"前一行后一行"会跨到另一段，必须显示分隔，不能假装连贯。
5. **输入框默认只装差异片段，不装整行。** 片段中位数 1 字（p90 也是 1，最长 33）。两路都错时，用户改 1 个字，
   而不是在 22 字的整行里找那一个位置；需要整行重写时再点"改整行"。

## 1. 三个问题的答案（都带数）

### 1.1 PDF：两版都做，默认带

| | 带 PDF（三栏） | 不带 PDF（两栏，专注模式） |
|---|---|---|
| 布局 | 队列 · PDF（自动滚到差异行，可缩成行图）· 表格 | 队列 · 表格 |
| 强项 | 判字、形近字、两路都错、插入/删除 | 纯键盘快判；屏幕窄时 |
| 弱项 | 占宽度，页图缩太小就失去意义 | 无原图可对 |

数据依据：

- **两路都错 ≈11%**（`docs/pm/review-cost.md` §1.1：C1 26/231；PM 审计估 ~100 条/本）——这些必须人写，
  没有原图就不知道写什么。
- **33% 的改动片段有一侧为空**（全库 1910 个改动片段：两侧都有 1279、左侧空 440、右侧空 191）——
  按钮上是"（无）"，光标点在哪、多出来的是标点还是字，要图判。
- 形近字：样张项目 85 条汉字差异里一大半是士/土、旱/早这类（Designer 2026-11-05 实测）。

**建议**：默认带 PDF；"专注模式"只作为开关，进入时提示"两路都错的条目在这里改不了，需要看原图"。

### 1.2 单位：一行一条，片段编号，按钮采纳整行

- **数据事实**：`block_divergence` 对每一行最多产生一条 mark（`blocks.py:741`），所以"一处差异"和"一行"今天是 1:1；
  用户担心的"同一行出现多次"不存在。
- **一行内多处改动**：用字符级比对实测，87.9% 的行只有 1 段改动，10.9% 有 2 段，1.2% 有 3 段以上。
- **决定**：表格一行代表一条队列项；行内多段改动用 `①②` 标出，但**两个按钮采纳的是整行**——
  `ack_diff_line(adopted)` 写的是整行文本（`editing.py:833`），不是单个片段。按钮文案必须是
  「用当前整行」/「用候选整行」；只有 1 段改动时才可简写成片段本身（此时片段 = 整行的全部改动）。
- **要混合（左路的 A 处 + 右路的 B 处）**：只能走输入框 → `edited`。三个动作正好对上三个 ack：
  `1`=kept、`2`=adopted、输入后确认=edited。

### 1.3 上下文：±1 + 段边界 + 可展开

- 27.6% 的差异行在段边：首行 251、末行 211（共 1676 条）。固定两行会在这些地方跨段，
  用户在"前一行"里读到的是上一段的末尾，很容易误判。
- 716/1926 个块只有 ≤2 行——短段里 ±1 已经到头，展开也没用。
- **决定**：默认 ±1 行（按要求，不用高亮），段边界画分隔线并标「上一段 / 下一段」；
  右上角「展开上下文」→ ±3 行（不出本段）。展开状态在本次会话内记住。

## 2. 表格规格（给 Designer）

### 2.1 布局（带 PDF 版）

```
┌ 队列目录 ┬──────── PDF（当前页，自动滚到差异行）────────┬──────── 表格 ────────┐
│ 回目     │                                              │ #12  p.11 · 第 4 行   │
│  p.11 3  │            [ 页面，差异行高亮 ]              │ ── 上一段 ──          │
│  p.12 1  │                                              │ 前一行（灰，不高亮）  │
│          │                                              │ 当前行（高亮，唯一）  │
│          │                                              │ 后一行（灰，不高亮）  │
│          │                                              │ ── 下一段 ──          │
│          │                                              │ [展开 ±3]             │
│          │                                              │ ┌──────────────────┐  │
│          │                                              │ │ 1 饯     2 钱     │  │
│          │                                              │ └──────────────────┘  │
│          │                                              │ 输入片段：[___] 确认  │
│          │                                              │ (改整行)              │
└──────────┴──────────────────────────────────────────────┴───────────────────────┘
```

**当前行只出现一次**（左栏高亮那行）。右栏不重复。理由见 §0 第 2 条：重复一次多读 21.9 字，
优化从 -44% 变成 +6%。

### 2.2 三个动作与按键

| 动作 | 键 | 写入 | 备注 |
|---|---|---|---|
| 用当前整行 | `1` | `diff_ack='kept'`，不改文本 | 等同"保留原文" |
| 用候选整行 | `2` | `diff_ack='adopted'` + 整行替换 | 不是只换片段 |
| 手改 | `Tab` 进输入框 → `Enter` | `diff_ack='edited'` + 拼接后的整行 | 若输入等于当前行 → 记 kept；等于候选 → 记 adopted |

- `Esc` = 离开输入框（不保存）；输入框有内容时 `Esc` 要确认一次再丢。
- 判完自动跳下一条（不关表格、不滚屏）。
- **这套键位替代上一轮「空格 = 采用 / A = 采用」的讨论**：用户这轮明确要 `1` / `2`，`1` 对应"保留当前"更顺手。
- 输入框默认**预选**当前片段，光标在片段上；输入即替换该片段，其余文字不动。
- 「改整行」把输入框换成整行（预填当前整行），用于整行乱码。

### 2.3 边界情况（必须实现，样张里能看到）

| 情况 | 怎么显示 |
|---|---|
| 片段一侧为空（33%） | 按钮显示「（无）」；旁边小字「多出：，」/「少了：的」 |
| 片段很长（最长 33 字） | 按钮截断 12 字 + `…`，悬停看全文；输入框仍装全片段 |
| 一行多段改动（12%） | 行内 `①②`，按钮变成"用当前整行 / 用候选整行"，并在按钮上方并排显示两整行（此时才允许重复显示整行） |
| 段首 / 段末（27.6%） | 分隔线 + 「上一段 / 下一段」，前/后行仍显示（它是有用的边界信息） |
| 已判条目 | 不再出现在队列；从右栏"已判"里可回看（审计） |

### 2.4 样张数据

- 用 `b2t_5DDDAP`（sample-20p）第 1–3 页的真实行：第 1 页「第二十七回」那页有
  `花神退位，须要饯行 / 钱行`（L4，段末，正好测段边界），第 2 页有 `红楼梦` 对 `红楼梦/`（空片段）与
  `黛玉` 被行拆成「黛」「玉道」的例子（正好测前后行断词）。
- 事实：这个项目 41 条里 25 条汉字已判、16 条标点未判（`chars_unacked=0`）。样张要把已判的汉字行
  **按未判状态渲染**（前端假状态），并在说明里标注"样张状态是假的，文字是真的"。
- 不要动用户库里的项目；要清 ack 就在 `/tmp` 副本上做。
- **表格只服务汉字级逐条**：`next-lines` 只返回汉字级；标点仍走审校页左栏的汇总入口 / 预览页的 560 面板，
  两种单位（一处汉字差异 vs 一处标点归并）不要混进同一张表。

## 3. 测量协议（"判一条要几次点击/几次视线移动"）

### 3.1 四个量（同一批 10 条，三种入口各跑一遍）

| 量 | 定义 | 怎么取 |
|---|---|---|
| 必读字数 | 判这一条**必须**读的字数：当前整行 + 两个片段按钮的字数（上下文不算必读） | 从真实数据逐条相加，中位数 |
| 人工比对字数 | 需要人自己找"哪里不一样"的字数：今天 = 整行 A + 整行 B；表格 = 两个片段（机器已对齐） | 逐条相加，中位数 |
| 操作数 | 从"这一条出现在屏幕上"到"判完并出现下一条"的点击 + 按键数 | 脚本走查，现场数 |
| 视线切换 | 按设计，眼睛必须落到的区域切换次数（PDF / 当前行 / 片段按钮 / 输入框） | 按设计数，**不称实测** |
| 主动滚动 | 用户自己滚动的次数 / 10 条 | 脚本走查 |

### 3.2 今天的基线（`b2t_YV1P2Y` 实测）

- 当前行均值 **21.9 字**，候选行均值 **22.3 字** → 必读 **44.2 字**，人工比对 **44.2 字**。
- 操作数 **3–4 次**（点红字 → 读 → 点裁决 → 找下一条；`review-ux-audit.md`：判完不前进）。
- 视线切换 **4 次**（PDF → A → B → 按钮）。
- 主动滚动：待实测（本次脚本里一并数）。

### 3.3 通过线

| 指标 | 今天的值 | 表格目标 | 通过线 |
|---|---|---|---|
| 必读字数（中位） | 44.2 | 24.8 | **≤26** |
| 人工比对字数（中位） | 44.2 | 2.9 | **≤4** |
| 操作数（中位） | 3–4 | 1 | **≤2** |
| 视线切换 | 4 | 2 | **≤2** |
| 主动滚动 / 10 条 | 待测 | 0 | **≤1** |
| 判对（10 条小样本） | — | — | **≥8/10**，未实测，只作回归 |

时间不设通过线：今天没有可信的单条计时（只有 5 秒/条的假设），先把"字数 / 操作 / 视线"盯住。

## 4. 风险

1. **压缩阅读量的代价是判错。** 只看片段不看上下文，容易把"行断在词中间"当成错字。缓解：±1 上下文常驻、PDF 可看、断词处（如「黛/玉」）画虚线接续。
2. **表格失去段落感。** 用户判的是字，不是段落；但 27.6% 在段边，边界必须可见，否则会把上一段的字当成本段。
3. **无 PDF 版对 11% 的条目是硬伤。** 所以它是"专注模式"，不是默认。
4. **样张的"快"可能来自假状态**（不用等后端、不用翻页）。测量要在说明里写清哪些是假状态。

## 5. 不做

- 不做"一行内多个片段分别裁决"：数据只有 per-line 的 ack，分开裁决会造出第三种语义；要混合就走 `edited`。
- 不在右栏重复整个当前行（除非多片段行需要并排对照，那时是"两整行"对照，不是重复同一行）。
- 不加新接口：表格读的还是 `next-lines` / `marks?page` / `pages/{n}/blocks`。
