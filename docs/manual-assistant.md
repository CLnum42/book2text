# 助手手册（Book2Text）

> 面向**助手**：打开负责人发来的**任务包**、审校、把**结果包**发回去。
>
> 协作流程已经可用（说明书 Phase 5，macOS 上实测跑通）。**Windows 上还没验证过**
> ——Windows 的助手现在只能等（见 [`known-limitations.md`](known-limitations.md) L-31）。

## 1. 打开（macOS）

1. 打开 `dist/Book2Text.app`。**未签名**，第一次会被系统拦：
   右键（或按住 Control 点）→「打开」→ 再点「打开」。
2. 浏览器会自动打开界面。没打开的话，把终端里那行
   `http://127.0.0.1:8765/?token=…` 整条复制到浏览器（**要带 `?token=`**）。
3. 第一次运行会让你填**名字**——填你自己的名字，之后每处改动都记在你名下
   （负责人看事件表就知道这一处是谁改的）。

## 2. 打开负责人发来的任务包

1. 负责人会给你一个 `.b2tpkg` 文件（微信 / 邮件 / 网盘都行，通常几十 MB）。
2. 界面「项目库」里点 **「打开任务包（助手）」**，选那个文件。
3. 应用会在你的项目库里建出一个**审校任务项目**（名字形如
   `书名 · 审校任务（第 87–136 页）`），顶部横幅写着：任务范围、来自谁、截止日期与说明。
4. 双击某一页开始审校。

**任务包里有什么：** 分派给你的页面（可编辑）＋ 前后各 1 页**只读上下文**
（用来判断跨页段落，瓷砖上标着「只读上下文」，改不了），以及这些页的识别结果。

**这个模式里没有的功能**（说明书就是这么规定的，不是坏了）：识别 / 重新识别、
改页面类型与纳入、页眉页脚批量工具、导出 TXT / JSONL。你只能审校块，
以及导出**审校结果包**。

## 3. 审校（你要做的全部）

双击某一页打开审校视图：左边是原图，右边是识别出来的块。

- **改文本**：直接改，停手自动保存（右上角有「已保存 ✓」）。
- **确认**：这一块没问题 → 点「✓ 确认」；拿不准 → 点「? 不确定」（负责人会重点看）。
- **排除**：不属于正文的（页眉、页码、广告页残留）→ 点「排除」。
- **合并 / 拆分**：被错误分成两块的用「⋯ 更多 → 与上一块合并」；
  一块里混了两段用「在光标处拆分」（先把光标放到要切的地方）。
- **补漏检**：图上有文字但没被识别出来 → 「✚ 框选新增块」→ 拖框 → 写文字 → 创建。
- **改完这一页**：**⌘/Ctrl + Enter** 确认本页并自动跳到下一处未完成。
- **改错了**：**⌘/Ctrl + Z** 撤销。

### 三条规矩（很重要）

1. **不认识的字、看不清的字，不要去猜、不要去"改通顺"**——这会让文本偏离原书。
   拿不准就标「不确定」，或者按原样保留，交回给负责人判断。
2. **不要改「识别原文」**：块里「看原文」显示的是 OCR 当时的输出，它是留档用的。
3. **改结构要谨慎**：合并 / 拆分 / 新增都会影响导出的段落切分；
   不确定的地方标「不确定」比动手改更安全。

### 如果有「两路分歧」标记（可选）

页面被复核过时，块里会出现「≠ 两路不一致 N 行」，逐行给出另一路候选。
**候选大多不对**（实测被标出的分歧里约八成是第二引擎自己的错）——
它的用途是提示你「这一行值得对照原图看一眼」，换不换由你判断。

## 4. 交回去（导出结果包）

1. 改到一个段落（或者今天收工）→ 点 **「导出结果包」**。
2. 会先给你一份摘要：已完成多少页、未完成多少页、不确定多少块、备注多少条。
3. 生成的文件很小（几十 KB），在下面列表里点「下载」，把它发给负责人。

**可以分多次导出**（例如每天发一次进度）：负责人每次只处理你新改的部分，
已经合并过的不会再问你。文件名里带「结果2」「结果3」这样的序号，按顺序给就行。

> **别忘了加备注**：拿不准的地方（原书疑似印刷错误、看不清的字）点块上的
> 「💬 加备注」写一句——备注会随结果包一起回传，负责人会重点看。

## 5. 出问题

- 界面没反应 / 提示缺少令牌 → 从终端重新复制整条带 `?token=` 的地址；
- 「打开任务包」报「这不是任务包」→ 让负责人重新发一份（可能传坏了）；
- 想改的东西在上下文页上 → 那是只读的，写备注告诉负责人；
- 其他问题：请负责人导出**诊断日志**（设置区「导出诊断日志」，不含识别文本与个人路径）
  发给开发者。
