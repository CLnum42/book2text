## 0. 一页纸摘要

- 工作流从「识别一页」改成**先版面、后识别、再比对与审校**的 11 个阶段。
- 新增两件事：**版面检测（只检测不识别）**、**在线第三引擎仲裁（可选、默认关）**。
  第二引擎先沿用现有 Apple Vision；**GLM-OCR 已调研、暂不采用**，只保留适配器接口位（见 1.7）。
- 页面状态显式化：`页面已确认 → 已检测 → 版心已定 → 已识别① → 已识别② → 差异已算 → 已仲裁 → 人工已确认 → 可导出`。
  页码定位是**旁路准备**，不阻塞 OCR，但导出前要确认或明确跳过。
- 三条硬原则：
  1. **不丢文字**：任何自动步骤的失败、未匹配、低置信都进「待人工」，不静默丢弃。
  2. **可追溯**：每个阶段保存输入版本、引擎/模型版本、输出与失败原因。
  3. **可续跑**：每阶段幂等；中断后从「卡住的那一步」继续，不从头重做。
- 引擎只通过接口接入：**换模型不改流程**。

**现成 vs 新写（概览）：**

| 阶段 | 现状 |
|---|---|
| 1 页面确认 | 现成（五类 + 确认状态） |

| 3 版心确认 | **已改（任务 59）**：检测行优先、没有检测行的页回退 OCR 行；界面不变 |

| 5 第一引擎 | 现成（RapidOCR 整页识别），**要改成按检测行裁图** |

## 1. 端到端：11 个阶段

**粒度说明：** 1–9 以「页」为单位，10–11 以「书 / 导出范围」为单位。页码定位（4）以「项目」配置模板、以「页」产生映射。

### 1.1 总览表

### 1.2 阶段 1：页面确认

- **输入：** PDF 页；`page_setup` 的只读建议（空白 / 首页 / 图像页 / 文字形态）。
- **输出：** `page.page_type`（五类）与 `page.page_confirmed`；只有 `body` 进入后续。
- **判定标准：** 用户确认了页面类型。`page_confirmed = 1`；非正文页是**终态 `excluded`**，不计入「未完成」。
- **失败处理：** 没有失败概念，只有「未确认」。未确认页不能进入阶段 2。
- **幂等：** 是。重复确认不改结果；改类型会重置 `page_confirmed`（现有行为）。
- **能否跳过：** 非正文页跳过后续全部阶段；正文页不能跳过。

### 1.3 阶段 2：版面检测（只检测、不识别）

- **输入：** 页面图像（按项目 DPI 渲染，默认 200）、页面宽高与旋转。
- **输出：**
  - 每页 `layout_run`（引擎、版本、参数、耗时、原始输出路径）；
  - `page_layout_line`：归一化 bbox、阅读顺序、行类型（正文 / 图注 / 装饰 / 表格等，能分则分）、置信度；
  - `page_layout_region`：图 / 表 / 装饰等区域（用于排除与第二引擎喂图）。
  - **不含任何文本**——检测阶段不产生文字，避免"检测模型顺带认字"污染第一引擎。
- **判定标准：** 页面的每个文本行都有框；图 / 装饰有区域标记；阅读顺序覆盖所有行。空白页允许 0 行，但要标记 `no_lines` 供人工确认，不算失败。
- **失败处理：** 渲染失败、检测引擎不可用 / 崩溃 → `failed_stage = detected`，保留错误原因；页面停在「已确认」。可重试；不生成空行冒充成功。
- **幂等：** 是。重跑删除该页旧 `layout_run` / 行 / 区域，写新一版；旧 OCR 结果标 stale（见 2.4）。
- **能否跳过：** 非正文页跳过；正文页不能跳过（它是后续所有阶段的几何基础）。

### 1.4 阶段 3：版心确认

- **输入：** 阶段 2 的检测行框；项目级默认版心；页级三态（沿用 / 自定义 / 不适用）。
- **输出：** `project.margin_box`、`page.margin_box(_mode)`，以及「这一页的版心已确认」的确认记录（见 2.2）。
- **判定标准：** 这一页有生效版心（页级 `none` 视为已确认），且确认动作发生过：
  - 用户点「确认版心 / 采用建议」，或
  - 项目开启「自动采用版心建议」（默认关；这是用户预先授权），或
  - 页级 `none`。
- **失败处理：** 推算不可靠只给「不可靠」提示，不阻断；用户可以手动拖 / 设 `none`。没有可用的行数据时版心为空，阶段停在这里，人工可先设一个框。
- **幂等：** 是。重复确认不改结果；改版心会重置 OCR 及之后阶段（见 2.4）。
- **能否跳过：** 页级 `none` 可跳过版心依赖（整页按正文处理）；正文页不能跳过「确认」这个动作。

### 1.5 阶段 4：页码定位（旁路）

- **输入：** 版心、阶段 2 的检测行框、`page_label`、已有模板 / 页码范围 / 手动映射。
- **输出：** 候选 → 位置模板（默认 + 可选页码范围）→ `page.printed_page` / `printed_page_source`；异常列表。
- **判定标准（三选一）：**
  1. 采用了一个默认模板（可加页码范围）；
  2. 逐页手动映射完成（至少覆盖需要导出的页）；
  3. 用户明确标记「这本书不做页码」。
- **失败处理：** 没有可靠模板 → 页面/项目级 `missing`，不阻塞 OCR；导出预检提示「页码未定位」。模板/范围重叠等参数错误直接 400。
- **幂等：** 是。重新聚类 / 应用模板会重算模板页，手动页不覆盖。
- **能否跳过：** 能。页码是旁路；没有映射时导出退回旧抽取（`legacy`）。

### 1.6 阶段 5：第一引擎识别（RapidOCR）

- **输入：** 页面图像、阶段 2 的行框、阶段 3 的版心；只对**版心内**的行裁图。
- **输出：** 主引擎逐行文本 + 置信度；`ocr_run(run_type=primary)`；块 / 行记录（现有 `block` / `block_line`，改为由检测行驱动）。
- **判定标准：** 版心内每个检测行都有文本结果，或有一条明确的逐行失败记录。空文本行允许，但标 `empty` 进人工。
- **失败处理：**
  - 整页渲染 / 引擎 / 落库失败 → `failed_stage = ocr1_done`，页面停在「版心已定」；
  - 单行失败 → 阶段可完成，但该行带 `issue`，进入人工审核（不静默丢）。
- **幂等：** 是。重跑替换本次主运行结果；**已有人工修改的块不自动覆盖**（沿用现有 R2 规则，或要求用户显式选择"重新识别并覆盖"）。
- **能否跳过：** 非正文 / 空白页跳过；正文页不能跳过。

### 1.7 阶段 6：第二引擎（可选；默认只有 Apple Vision）

- **默认只有 Apple Vision**（现有实现）：按第一引擎切出的行图逐行复核，写
  `block_line.aux_text` / `diff_status`；它实测比第一引擎弱（整页 CER 2.16% vs 1.08%），
  **只作分歧线索，绝不自动采用**。项目设置里的「双引擎比对」就是 RapidOCR + Apple Vision。
- **输入：** 第一引擎的行图（按行框外扩约 2% 裁图）；不需要整页图像。
- **输出：** `ocr_run(run_type=secondary)` + 行级第二路文本与 `identical / format_only /
  differs`；**不生成块**，不改 `block.text`。
- **判定标准：** 每个主行有第二路结果或明确的空结果记录。
- **失败处理：** 第二引擎不可用 / 超时 / 崩溃 → `failed_stage = ocr2_done`，页面停在
  「已识别①」；第一路成果不失败。
- **幂等：** 是。重跑替换第二路结果，第一路不动。
- **能否跳过：** 默认关。第一次打开项目时给一次引导，由用户主动开启，按项目记住；
  关闭时阶段记 `skipped`，差异分析只用第一路，人工审核仍可做。非正文页跳过。
  老项目行为保持不变（不因为升级自动开始跑第二引擎）。

**GLM-OCR 已调研、暂不采用（2026-10-25 实测结论，留档给未来的自己）：**

- **运行方式不是官方两段式：** 本机是 **llama.cpp + GGUF 裸模型，1.43 GB**，
  **没有 PP-DocLayout**；官方「版面检测 → 区域识别」两段式管线在本机不存在。
- **输出没有坐标：** 纯文本，**没有任何 bbox**；明确要求每行 bbox JSON，也只回一个
  `text` 字段；提示词控制不了行结构。
- **速度：** 200 DPI **22.7–27.3 秒/页**，300 DPI **58–64 秒/页**；
  同期 RapidOCR 整页约 **4.8 秒**。
- **有用的一面（要如实记）：** 与 RapidOCR 字符一致率 **96.6%**，并且**多抓出一整行
  RapidOCR 漏识的文字**——它不是没有价值，而是代价与可控性不匹配。
- **噪声：** 段落合并、页边页码粘进段首、圈码变 LaTeX、标点半角化、200 DPI 下自己会丢书眉。
- **许可证：** MIT / Apache-2.0，可商用；许可证不是阻碍，运行管线与输出可控性才是。
- **结论：** 保留 `RegionOcrEngine` / `align_regions_to_lines` 的接口位；将来若要重启，
  先补「区域 → 行对齐」独立层与真实书评测，不把第二路当正确答案。

### 1.8 阶段 7：差异分析

- **输入：** 第一路逐行文本、第二路对齐后的逐行文本。
- **输出：** `line_diff`：每行一条，包含
  - 比对用的归一化文本（**只用于比较，不写回原文**）；
  - 字符级操作序列（equal / replace / delete / insert）；
  - 分级：`differs_chars`（汉字/数字级）、`differs_punct`（仅标点/符号）、`missing`（第二路缺字）、`extra`（第二路多字）、`identical` / `format_only`、`no_candidate`（第二路没有可用行）；
  - 双方文本快照的哈希（用于仲裁与审计）。
- **判定标准：** 每个主行都有一条 diff 记录（包括"无候选"）。标点归一化只影响比较，原始文本不动。
- **失败处理：** 输入不完整（例如第二路未完成）→ 不进入本阶段；计算异常 → `failed_stage = diff_done`。单行的 `no_candidate` 不算页面失败。
- **幂等：** 是。重算删除旧 diff，按当前文本生成；人工改字后相关行自动失效重算。
- **能否跳过：** 不能（除非第二引擎关闭，则本阶段只产 `no_candidate` 并把页面直接送入人工 / 自动通过）。

### 1.9 阶段 8：第三引擎仲裁（在线大模型，可选、默认关）

- **输入：** 差异行的**裁图** + 第一路候选 A + 第二路候选 B（+ 只读上下文：页码、行号、相邻行文本，不发整页）。
- **输出：** `line_arbitration`：`choice ∈ {A, B, NEITHER}`、理由、模型标识 / 版本、prompt 版本、输入哈希、时间。
  **绝不输出"修正后的文本"**——仲裁只做选择，不生成内容。
- **判定标准：** 每个差异行都有决定，或明确 `skipped`（离线 / 超预算 / 用户关闭）。
- **失败处理：** 网络失败、超时、返回不是合法 JSON、choice 不在枚举内 → 该页 `failed_stage = arbitrated`（或按行记失败），保留下载给人工；**不重试到无限、不把模型理由当事实**。
- **幂等：** 是。按 `(裁图哈希, A, B, prompt 版本)` 缓存；重跑只补缺失行。
- **能否跳过：** 默认关。无差异行、用户关闭、无 Key、离线、预算耗尽都直接 `skipped`，页面进入人工审核。
- **GLM 不接入后的影响：** 跨引擎第三方意见只剩在线仲裁这一条路，它的价值上升；
  但仍然**默认关**，隐私 / 成本 / Key 规则见 3.3 与 5.3。

### 1.10 阶段 9：人工审核

- **输入：** 差异行 + 仲裁建议、漏行候选（有墨迹但没有行框）、版面 / 版心待确认项。
- **输出：** 人工决定（采用 A / 采用 B / 都不采用并自己改 / 标记不确定）；页面确认；编辑事件（可撤销）。
- **判定标准：** 页面无未处理的差异行、无未处理的漏行候选、版面已确认；或满足自动通过条件（见 2.3）。
  **自动通过条件（2026-10-25 拍板）：** `两路都有结果` + `逐行 identical / format_only` +
  `无漏行候选` + `版面已确认` + `版心已定`。
  **第二引擎没跑过的页不许自动通过**，标成 `single_engine`（可导出，但预检要报数）。
  **不引入"置信度"判据**——OCR 引擎普遍不给可靠置信度，拿它当自动通过门槛只会制造假安全感。
- **失败处理：** 无失败；未完成就是「待人工」。用户可离开、稍后继续。
- **幂等：** 是。人工修改走事件表，可撤销；重看不会重置已确认的页（除非上游变了）。
- **能否跳过：** **无差异且无问题的页自动通过**，不要求逐页点；有差异必须有人处理（或明确"忽略"）。

### 1.11 阶段 10：组装

- **输入：** 已确认页；版心 + 块类型过滤；段顺序；页码锚点；可选句级切分。
- **输出：** 段 / 句 / 锚点结构（内存 + 可预览），供导出。
- **判定标准：** 组装成功；每个段能回溯到页 / 块 / 行；页顺序稳定。
- **失败处理：** 数据缺口（引用的块被删等）→ 报错并列出页，不静默补空。
- **幂等：** 是。相同输入相同输出（句子切分结果也需确定性）。
- **能否跳过：** 不能；但可以只导出部分页范围（见 11）。

### 1.12 阶段 11：预览与导出

- **输入：** 组装结果；导出选项（范围、类型、版心判定、注释、清理规则）。
- **输出：** `body.txt` / `body.jsonl` / `notes.txt` / `notes.jsonl` / `meta.json` / `manifest.json`。
- **判定标准：** 预检成功并写盘成功；预检必须显示「还有 N 页没走完」及卡在哪一步。
  **导出门槛（2026-10-25 拍板）：不拦导出。** 确认是状态标记，不是硬闸门；预检按级别警告：
  `未人工确认 N 页 / 单引擎未复核 M 页 / 版面未确认 K 页 / 页码缺口 J 页`，
  并在 `manifest.json` 里记录**导出时的工作流状态快照**（以后能知道这份语料是怎么出来的）。
- **失败处理：** 写盘失败记录在导出记录里，不产生"半套文件"当作成功；可重试。
- **幂等：** 是。相同项目状态 + 相同选项 → 相同的正文 / 元数据（导出批次 id / 时间戳除外）。
- **能否跳过：** 不能。

## 2. 页面状态机（核心）

### 2.1 状态定义

**OCR / 审校主线**（严格按用户给定顺序）：

```
页面已确认 → 已检测 → 版心已定 → 已识别① → 已识别② → 差异已算 → 已仲裁 → 人工已确认 → 可导出
```

状态代码与含义：

| 状态代码 | 界面文案 | 含义 | 进入条件 |
|---|---|---|---|
| `page_unconfirmed` | 待确认页面 | 正文页还没确认类型 | 项目创建 / 改类型后 |
| `confirmed` | 已确认 | 页面类型已确认，正文页进入流程 | `page_confirmed=1` 且 `page_type=body` |
| `detected` | 已检测 | 行框 / 区域已产出 | 检测成功 |
| `margin_set` | 版心已定 | 这一页的版心已确认 | 生效版心 + 确认记录，或页级 `none` |
| `ocr1_done` | 已识别① | 主引擎逐行结果已落库 | 版心内行都有结果或逐行失败记录 |
| `ocr2_done` | 已识别② | 第二引擎区域 + 对齐完成 | 每行有第二路或 unmatched 记录；或项目关闭第二引擎 |
| `diff_done` | 差异已算 | 逐行差异记录完成 | 每行有 diff（含无候选） |
| `arbitrated` | 已仲裁 | 每个差异行有选择或 skipped | 仲裁完成 / 关闭 / 无差异自动跳过 |
| `human_confirmed` | 人工已确认 | 这一页审校完成 | 人工确认或自动通过 |
| `export_ready` | 可导出 | 这一页没有未完成的必经步骤 | `human_confirmed` + 必填旁路已确认 |
| `excluded` | 不参与 | 非正文页，终态 | `page_type != body` |

**旁路状态（不在主链上）：**

| 旁路 | 状态 | 存储 | 说明 |
|---|---|---|---|
| 页码定位 | `missing` / `ready` / `skipped` | `page_workflow.page_number_state` + 现有模板 / 映射 | 不阻塞 OCR；导出预检提示 |
| 版面 / 块确认 | `page.layout_confirmed` | 现有字段 | 块级版面确认；人工审核的一部分 |

**页码旁路状态怎么定：**

- `ready`：项目已采用默认模板或页码范围，或者导出范围内的页都有手动映射；
- `skipped`：用户明确选择「这本书不做页码」（存 `page_workflow.page_number_state`）；
- `missing`：以上都不是。导出预检提示，但允许按旧逻辑 `legacy` 导出（是否阻断见待拍板）。
| 失败 | `failed_stage` + 原因 | `page_workflow` | 失败不改变已完成的 `stage` |

**为什么页码不在主链：** 页码只影响 `meta.json` 的映射，不影响正文识别；把它塞进 OCR 主链会让
「改了页码 → 整页 OCR 重跑」这种不必要的事发生。但它仍是阶段 4，需要自己的完成状态。

### 2.2 数据存在哪

**原则：产物是事实，`page_workflow` 是索引 / 缓存。** 状态可以从产物重建；索引坏了不影响数据。

新增表（**迁移 0015，任务 58 已建**；本文档只描述，不替代迁移）：

```sql
CREATE TABLE page_workflow (
  page_id         TEXT PRIMARY KEY REFERENCES page(page_id),
  stage           TEXT NOT NULL DEFAULT 'page_unconfirmed',
  failed_stage    TEXT,
  failure_reason  TEXT,
  stage_times_json TEXT NOT NULL DEFAULT '{}',   -- {"detected": "...", ...}
  page_number_state TEXT NOT NULL DEFAULT 'missing', -- missing / ready / skipped
  revision        INTEGER NOT NULL DEFAULT 0,
  updated_at      TEXT NOT NULL
);
```

同一迁移还建了检测产物表：`layout_run`（引擎 / 版本 / 参数 / 耗时 / 原始输出路径）、
`page_layout_line`（归一化 bbox、阅读顺序、置信度）。**检测阶段不写文字**；区域表
（图 / 表 / 装饰）还没有实现。

各阶段的**权威产物**（状态表只做索引）：

| 状态 | 权威产物 | 现有 / 新增 |
|---|---|---|
| `confirmed` | `page.page_type` / `page.page_confirmed` | 现有 |
| `detected` | `layout_run` + `page_layout_line` + `page_layout_region` | **新增** |
| `margin_set` | `project.margin_box` / `page.margin_box(_mode)` + 确认记录 | 现有 + 新增确认字段 |
| `ocr1_done` | `ocr_run(primary)` + `block` / `block_line` | 现有 |
| `ocr2_done` | `ocr_run(secondary)` + `secondary_region` + `secondary_line` | **新增** |
| `diff_done` | `line_diff` | **新增** |
| `arbitrated` | `line_arbitration` | **新增** |
| `human_confirmed` | 编辑事件 + 页面确认字段 + 差异处理记录 | 现有事件 + 新增确认字段 |
| `export_ready` | 由以上状态派生；不单独存“已导出” | — |
| 页码旁路 | `page.printed_page(_source)` + `project.page_number_template/ranges` + `page_workflow.page_number_state` | 现有 + 新增 |

`stage` 的推进函数 `rebuild_page_stage(page_id)`：按上表检查产物，返回「最近连续完成的状态」；
所有阶段完成后、迁移后、状态可疑时都可以重算。**不允许 API 直接手写一个假的 `stage`。**

**老项目回填规则（迁移时）：**

- `page_workflow` 初始为空；打开项目时按产物回填，不伪造阶段：
  - 非正文页 → `excluded`；
  - 正文页已确认 → `confirmed`（**即使已有旧的 OCR 块，也不跳到 `ocr1_done`**：
    新流程要求先有检测行，旧块继续用于旧导出 / 只读兼容，但不冒充"已检测"）；
  - 已有 `page_number_template` / ranges 的项目 → `page_number_state = 'ready'`，否则 `missing`。
- 旧 OCR 块 / 旧导出记录**不删除**；新流程从检测重新走，写新表。旧页面在完成新流程前
  仍可按现有规则导出（预检会提示"还有 N 页没走完"），不会因为迁移丢数据。

### 2.3 怎么推进

| 从 → 到 | 触发 | 自动 / 人工 |
|---|---|---|
| `page_unconfirmed` → `confirmed` | 用户确认页面类型（现有 PATCH） | 人工（非正文 → `excluded`） |
| `confirmed` → `detected` | 版面检测任务成功 | 自动 |
| `detected` → `margin_set` | 生效版心 + 用户确认 / 项目开启自动采用建议 / 页级 none | 人工或预先授权 |
| `margin_set` → `ocr1_done` | 第一引擎任务成功（含逐行失败记录） | 自动 |
| `ocr1_done` → `ocr2_done` | 第二引擎 + 对齐完成；或项目关闭第二引擎 | 自动 |
| `ocr2_done` → `diff_done` | 差异计算完成 | 自动 |
| `diff_done` → `arbitrated` | 所有差异行有决定；或仲裁关闭 / 无差异 | 自动 + 可选在线 |
| `arbitrated` → `human_confirmed` | 人工确认；或满足自动通过条件 | 人工 / 自动通过 |
| `human_confirmed` → `export_ready` | 页码旁路为 `ready` 或 `skipped` | 自动派生 |

**自动通过条件（阶段 9，2026-10-25 拍板）：** 以下全部成立才自动确认：

- **两路都有结果**；第二引擎没跑过 → 标 `single_engine`，**不自动通过**；
- 差异行 = 0（`line_diff` 全部 identical / format_only）；
- 漏行候选 = 0（有墨迹但没有行框的横条）；
- 版面已确认、版心已定；
- 没有 `failed_stage`。

**不引入置信度判据。** 否则必须人工确认。自动通过会在事件表留一条系统事件，可撤销。

### 2.4 失败与回退

**失败：**

- 页面级失败写 `failed_stage` + `failure_reason`；`stage` **不前进**。
- 统一的失败原因枚举（界面按它给下一步建议）：
  `render_failed`（渲染）、`detector_unavailable` / `detector_crashed`（版面检测）、
  `margin_unresolved`（没有可用版心且用户未设）、`ocr_unavailable` / `ocr_crashed`（引擎）、
  `secondary_unavailable` / `secondary_timeout`（第二引擎，当前是 Apple Vision）、`alignment_incomplete`
  （仅作为 issue，不算页面失败）、`persist_failed`（落库 / 写文件）、
  `arbitration_timeout` / `arbitration_invalid`（仲裁）、`interrupted`（进程中断，可续跑）。
- 逐行失败（某行 OCR 空、第二路未对齐）不阻止阶段完成，作为 `issue` 进入人工审核。
- 重试只重跑失败阶段；成功后清空 `failed_stage`。
- 任务被暂停 / 取消 / 进程中断：`job_item` 状态保留；`stage` 仍是最后一个完成状态；续跑从 pending item 继续。

**回退（上游变了，下游必须失效）：**

| 变更 | 回到 | 失效 / 需要重做的 |
|---|---|---|
| 页面类型改为非正文 | `excluded` | 全部下游 |
| 页面类型在正文之间改（如正文 ↔ 正文排除） | `page_unconfirmed` | 全部下游 |
| 重跑版面检测 | `detected` | 版心、第一/第二引擎、差异、仲裁、人工确认 |
| 改版心 / 版心确认被重置 | `margin_set` | 第一/第二引擎、差异、仲裁、人工确认；页码旁路重算 |
| 页码模板 / 范围 / 手动值改变 | 不回退 | 只重算页码旁路；OCR 与差异不失效 |
| 重跑第一引擎 | `ocr1_done` | 第二引擎、差异、仲裁、人工确认 |
| 重跑第二引擎 | `ocr2_done` | 差异、仲裁、人工确认 |
| 重算差异 | `diff_done` | 仲裁、人工确认 |
| 重跑仲裁 | `arbitrated` | 人工确认 |
| 人工改某个块的文字 | 该页回到 `arbitrated`（或 `diff_done`，若行结构变了） | 该页人工确认；下游导出重新组装 |

实现方式：每次写入删除 / 标记下游产物为 stale，并调用 `rebuild_page_stage`；现有
`page.layout_confirmed` 的触发器思路可以复用，但**不要只靠触发器**（跨表、跨进程，触发器不够）。

**回退是自动的，但不会删人工成果**：人工改过的块 / 行保持（R2 规则）；重跑只替换"自动结果"，
并明确告诉用户"这一页有 N 处上游变化，需要重看"。

### 2.5 幂等与断点续跑

- 每个阶段以 `(page_id, stage, 输入 revision)` 为幂等键：重复执行结果一致；写入用事务，
  先删本阶段旧产物再写新产物。
- 断点续跑：任务表 `job` / `job_item` 复用现有机制；一个阶段一个任务（或一个流水线任务按阶段
  分单元），每页独立；暂停 / 取消在页边界生效。
- 启动时 `repair_unfinished` 修复中断任务，再按 `page_workflow.stage` 与实际产物做一次
  `rebuild_page_stage` 对账；不一致以产物为准。
- 所有阶段可单独重跑；**不要求整本从头重来**。

  `待比对`、`待仲裁`、`待人工`、`可导出`、`失败`、`页码未定位`。

### 2.7 与现有识别状态的映射

## 3. 引擎适配器接口（只定义，不实现）

### 3.1 版面检测

```python
class LayoutEngine(Protocol):
    engine_id: str
    def available(self) -> tuple[bool, str]: ...
    def version(self) -> str: ...
    def detect(self, image: PageImage, params: LayoutParams) -> LayoutResult: ...

# LayoutResult:
#   lines: list[LayoutLine]        # bbox / polygon / reading_order / kind / confidence
#   regions: list[LayoutRegion]    # figure / table / decoration / text_block
#   engine_id / engine_version / raw
```

- 只输出几何与区域类型，**不输出文字**。
- `LayoutLine.bbox` 与现有 `block_line.bbox` 同口径（归一化 0–1），方便复用。
- 原始输出落 `layout_runs/<run_id>.json`（与 `ocr_runs` 同样的离线、可追溯规则）。

### 3.2 第一 / 第二引擎

```python
class LineOcrEngine(Protocol):
    engine_id: str
    def available(self) -> tuple[bool, str]: ...
    def version(self) -> str: ...
    def recognize_lines(
        self,
        page_image: PageImage,
        lines: Sequence[LayoutLine],
        params: OcrParams,
    ) -> list[LineText]: ...

class RegionOcrEngine(Protocol):
    """区域级引擎（GLM-OCR）：一次吃版心整块，吐出区域文本。"""
    def recognize_regions(
        self,
        page_image: PageImage,
        regions: Sequence[LayoutRegion],
        params: OcrParams,
    ) -> list[RegionText]: ...
```

- `LineText` = `{layout_line_id, text, confidence, engine_id, version}`。
- `RegionText` = `{region_id?, bbox, text, confidence}`；**区域→行的对齐不由模型负责**。
- 对齐是独立、可单测的一层：

```python
def align_regions_to_lines(
    regions: Sequence[RegionText],
    lines: Sequence[LayoutLine],
) -> AlignmentResult:
    """返回每个主行匹配到的区域（或 ambiguous / unmatched），未用区域也保留。"""
```

- **GLM-OCR 暂不采用（2026-10-25 实测结论）。** 接口位保留：将来若模型能稳定给出区域框，
  再在独立模块里实现 `recognize_regions` + `align_regions_to_lines`；换模型不改工作流。
- **当前唯一的第二引擎是 Apple Vision**：它本来就是逐行裁图，实现 `LineOcrEngine`；
  只作分歧线索，不自动采用。项目设置里的「双引擎比对」就是 RapidOCR + Apple Vision。
- 工作流不感知具体引擎；产物记录 `engine_id` / 版本，换引擎后可对比、可回滚。

### 3.3 第三引擎仲裁

```python
class ArbitrationEngine(Protocol):
    engine_id: str
    def available(self) -> tuple[bool, str]: ...
    def judge(
        self,
        line_crop: Image,
        candidate_a: str,
        candidate_b: str,
        context: ArbitrationContext,   # 页码 / 行号 / 相邻行，不发整页
    ) -> ArbitrationDecision: ...

# ArbitrationDecision:
#   choice: Literal["A", "B", "NEITHER"]
#   reason: str
#   model_id / model_version / prompt_version
#   raw_hash
```

- **接口里没有 `text` 字段**，从类型上禁止"生成修正文本"。
- 适配器必须校验返回：choice 不在枚举 / JSON 不合法 → 抛错，由工作流记为失败或 skipped。
- 输入只允许**单行裁图 + 两路候选 + 相邻行上下文（≤1 行）**；不允许整页外传。
- **协议（2026-10-25 拍板）：** 按 **OpenAI 兼容**接口做，DeepSeek / 智谱 / 本地 vLLM 都能接。
- **默认关、无 Key 时自动 `skipped`。** Key 存在系统安全存储或环境变量，
  **不写项目文件、不写日志、不进导出**。
- **预算：** 默认每本书最多 2000 次调用（用户可改）；超了自动 `skipped` 并提示。

### 3.4 换模型不改流程

工作流只依赖上述 Protocol；模型选择由项目设置 / 自检决定。每个产物记录 `engine_id` 与
`version`，换模型后可对比、可回滚。**不允许在业务流程里写 `if engine == "glm"` 之类的分支**；
差异、对齐、状态推进都与模型无关。

## 5. 已知风险

### 5.1 GLM-OCR 的「区域 → 行对齐」风险（已调研，暂不采用）

- **当前不接入 GLM-OCR**，所以这个风险不阻塞现有流程；下面是将来重启时必须先解决的问题。
- GLM-OCR 输出的是**区域级 / 纯文本**，检测器输出的是**行框**；两者边界、合并/拆分方式都可能不同
  （一段被模型合成一个区域、一行被拆成两个区域、区域跨多行）。实测本机版本**连坐标都不给**，
  所以第一步不是对齐，而是"先让它输出可用的区域框"。
- 如果强行按最近框硬塞，会把 A 行的字塞给 B 行，**比漏识别更危险**（污染人工判断）。
- 将来重启时的要求：
  - 对齐必须是**独立模块**（`align_regions_to_lines`），有独立金标准与指标：
    对齐覆盖率、误配率、未匹配区域/行数、对齐后文本 CER；
  - 只允许"一对一"或明确标记 `ambiguous`；**一个区域跨多行必须保留为多行候选**；
  - 未匹配的行 / 区域都必须保留并进入人工审核；
  - 先在一本书上做人工核对，再扩大范围；未验证前不把第二路当"正确答案"。
- **未验证：** GLM-OCR 的区域框是否稳定、对齐算法在双栏 / 竖排 / 表格上的表现。

### 5.2 生成式第二引擎的忠实性风险（GLM 暂不采用，风险留档）

- GLM-OCR 的 0.5B 解码器可能自动补标点、改写生僻字 / 异体字、把残缺字"猜"成常见字；
  输出读起来更顺，但**不是原文**。实测噪声包括段落合并、页码粘段首、圈码变 LaTeX、
  标点半角化、200 DPI 丢书眉。
- 差异分析能抓住"第二路与第一路不同"的行，但抓不住**两路都错**或模型把原文改成"更合理"的字。
- 因此即使将来重启，也必须：
  - 第二路永远不自动成为正文；只作为候选；
  - 保存模型版本、参数、原始输出；可回溯；
  - 对"长度异常 / 新增字符 / 大段重写"的行优先人工；
  - 不在流程里做"自动润色 / 自动纠正"（说明书 1.5）。
- **未验证：** 古籍生僻字、异体字、竖排、双栏上的忠实性；需要单独评测集。

### 5.3 在线仲裁的隐私、成本与 Key

- 只发**单行裁图 + 两路候选 + 相邻行上下文（≤1 行）**，不发整页、不发全文；默认关闭，用户显式开启。
- Key **不得落盘**：用环境变量 / 系统安全存储；不写项目数据库、不写日志、不进导出包。
- 成本：只对差异行调用；**默认每本书最多 2000 次调用或用户设定值**，超预算直接 `skipped`，不阻塞流程。
- 供应商的数据保留 / 训练条款需要用户确认；离线或不允许外传时仲裁必须可关。
- 仲裁结果只存 choice + reason + 模型标识 + 输入哈希，不存裁图（或按项目设置短期缓存）。

### 5.4 边带识别与版心边界的重叠地带

- 页码候选在「版心外 + 页边」；如果版心判错，正文行可能落进边带被当页码，或页码被算进正文。
- 规则：**版心是主判据**；页边带只在版心外生效。一条检测行只能属于一个角色：
  - 中心在版心内 → 正文候选（第一引擎）；
  - 中心在版心外且在页边带 → 页码/书眉候选；
  - 两者都不在 → 版面待确认（不漏掉）。
- 版心未确认时，页码阶段不应自动写映射；页面状态要显示「版心未定」。
- **未验证：** 跨边界行（中心在版心内、框大部分在外）的归属；扫描倾斜 / 裁切不齐。

### 5.5 其他风险

- **GLM-OCR 的成本 / 速度 / 内存**：实测 200 DPI 22.7–27.3 秒/页、300 DPI 58–64 秒/页；
  整书批量不可接受，这也是暂不采用的原因之一（见 1.7）。Apple Vision 第二路仍有耗时，未整书实测。
- **磁盘增长**：每页两套行文本 + 区域 + diff + 裁图缓存，可能比现在大几倍；需要清理策略。
- **状态漂移**：`page_workflow` 索引与产物不一致；必须提供 `rebuild_page_stage` 与启动对账。
- **迁移兼容**：老项目的 `page_recognition_states` / `layout_confirmed` 与新状态并存一个版本周期；
  导出预检两套都要能读。
- **部分导出**：允许"还有 N 页没走完"就导出，还是强制走完？见待拍板。
- **Windows**：Apple Vision 在 Windows 上不可用（没有该框架）；GLM 若将来重启，其本机打包、
  推理后端、路径与内存都未验证。
