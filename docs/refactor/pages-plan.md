# `pages` 施工计划：5 个语义操作（2026-10-29 定）

> **开头先说清为什么顺延**：`pages` 不是"只差一个视图"，**也不是 371 行**。
> 它落盘两次、回滚两次，原因是**边界画错了**：63 个转发器里 47 个是"被外壳流程调用的能力"，
> 而转发器假设"外壳只剩薄转发"——两者不可能同时成立。
> **重画之后这一刀是 ≈3,200 行**（调用者 41 个 / 1,696 行 + movers 63 个 / 1,522 行）。
> 下一个人看到"只差 `pages`"时，不要以为明天半小时能收。

## 0. 单位：一个"操作" = movers + 驱动它的调用者

**单独搬 movers 一定失败**（转发器调不到模块内部，`LANDING.md §6`）。所以每次搬的单位是
**一个语义操作 + 它的全部 `stays` 调用者**，一起进模块、一起验收、一起回滚。

## 1. 顺序（按依赖判，不按行数）

| 序 | 操作 | 行数 | 为什么在这个位置 |
|---:|---|---:|---|
| **1** | **渲染与加载** | 987 | **最底层**：`renderLayoutBlocks` / `loadLayoutBlocks` / `refreshRecognizedPages` 被其余四组调用，自己几乎不反向调用别的组。**先搬它，后面四组的调用方向才都是"向模块里调"** |
| **2** | **版面建议扫描** | 110 | 只在上一步之后成立：它读渲染结果、写建议队列；调用者少（5 个），是**验证"上一组边界是否真的闭合"的最小样本** |
| **3** | **版心操作** | 255 | 依赖 1（画版心线要渲染节点）与 2（版心建议来自扫描）；它自己不被 4、5 调用 → 可以独立验收 |
| **4** | **确认与采纳** | 213 | 依赖 1（确认后重渲染）与 3（确认版心）；**它是"用户动作"，必须最后搬 UI 行为**，前面三组稳了它才是纯接线 |
| **5** | **批量识别与设置** | 131 | **最上层、副作用最大**：起识别任务、改设置、刷全量。它一搬就会触发 1–4 的所有路径 → **放最后，一次验证整条链** |

**判据（每个操作搬之前跑）**：列出该组调用者对 `app.js` 其余顶层函数的引用；
**若引用落在"还没搬的组" → 该组必须与它同批搬**。这条比上面的顺序表更硬——
顺序表是预期，这条是实测，冲突时以实测为准。

## 2. 每个操作的验收判据（同一套，不另发明）

| 类别 | 判据 |
|---|---|
| **闸** | `node tests/js/run.mjs`：R3（app.js 里 `view-pages` 字面量 **减到 0 或按比例下降**，见下）、R5（`OWNERS` 指向新 owner）、R8（导出面只降不升）、R11（边棘轮只降）、R12（登记齐全） |
| **acid** | `python3 scripts/accept_pages.py --acid`（四字段，缺一即未验）——**它是"模块真的被用上"的证据，不是"代码搬走了"** |
| **后端** | `pytest -q`（1,002） |
| **行数** | 每个操作的 `app.js` 减少量 ≈ 该操作行数 ±20 行；**少于一半 = 复制不是搬，停** |
| **回滚点** | **每个操作一笔 `move(pages): <操作名>` 提交**，单独 `git revert` 之后必须回到全绿 |

**R3 的判定要按操作分别写死**（这是唯一不能用"归零"一刀切的地方）：

| 操作 | 搬完后 R3 对 `view-pages` 的期望 |
|---|---|
| 1 渲染与加载 | 字面量大幅下降，**但不能归零**（其余四组还在 app.js 里渲染） |
| 2–4 | 继续下降，**不新增豁免** |
| 5 批量识别 | **必须归零**（这是"内部调用"的证明） |

**不批"刀一只搬接线类"**：它不会让 R3 归零，只能靠开豁免过闸——而 R3 是今天唯一抓过 40 个纠缠函数的闸。
**要么整刀，要么不切。**

## 3. 前置条件（不满足不要开工）

- `page-tile` 稳定（今天 observer 11 → 6，且酸测试绿）；**在刚换完地基的楼上浇筑 = 把两个风险叠一起**；
- `pages/movers.json` 与 `semantic-ops.md` 的基线 sha 与当天 `HEAD` 一致（否则名单过期，重算再开）；
- 63 个转发器的 4 个"无调用"已人工确认（`confirmLayoutFromPanel` / `confirmSelectedPages` / `scanVisiblePageSuggestions` / `startAuxiliaryAll`）——**零引用 ≠ 死代码，今天已误判两次**。

## 4. 禁止项

- **不开 `call(name)` 分发口**：它会让 47 个错误形状合法化，跑起来之后没人再回来改；
- **不用测试替身盖住 `undefined.apply`**（替身让用例绿、线上仍炸，`LANDING.md §6` 已记）；
- **不为过闸新增 R3 豁免**；R8 的「导出只降不升」一次都不破。

## 5. 一句话

**3,200 行不是一个下午的事，但它是 5 个能单独证伪的单元。**今天的价值不是"少切一刀"，
是**把"还差一个视图"这句话换成了"还差 5 个操作、每个有验收和回滚点"**。

## 6. 名单冻结规矩（2026-10-29，第四次"消费中被改"之后）

**冻结 = 内容 sha256 + 文件里的「冻结」头 + 一次提交 + 报出 sha。** 四样缺一不算冻结。

**盘上文件 sha ≠ 冻结 sha → 任何人不得跑生成器。** 不是"发现不一致先讨论"，是**停**：
今天同一份名单出现过 43/114/120、21/23/27、19/21 三组版本，Builder 因此白跑两次。

- 冻结人：Architect（本文件 §1 的名单类证据）；
- 唯一权威：`git show <冻结提交>:<路径>` 的 sha256，**不是"盘上那份"**；
- 恢复只许单文件 `git restore <path>`（或 `git show <sha>:<path> > <path>`），**禁止 `checkout -- .`**。
