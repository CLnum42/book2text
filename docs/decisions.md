## D-001 | 2026-10-14 | 仓库采用说明书 12.2 的目录布局

**决策：** 仓库根目录按说明书 12.2 的清单组织。开发说明书入库为 `docs/spec-v1.0.md`，UI 原型入库为 `docs/ui-mockups/`。

- 说明书的第 1 节要求同步为 `AGENTS.md`，把说明书集中放在 `docs/` 便于维护"副本 ↔ 原文"的对应关系。

**影响：** 原始文件由仓库根目录移动到 `docs/` 下，路径变更。说明书内容本身未做任何修改。

**状态：** 生效。

## D-003 | 2026-10-14 | 换行策略：源码统一 LF，仅 `*.bat` / `*.cmd` 为 CRLF

**决策：** 见 `.gitattributes`。默认 `* text=auto eol=lf`；`*.bat`、`*.cmd` 强制 CRLF；`*.command`、`*.sh` 强制 LF。

**理由：** 说明书第 10 节要求"仓库用 `.gitattributes` 统一源码换行"。同时有两个必须保留的例外——Windows 批处理在 LF 下可能行为异常，而 macOS 的 `.command` 启动脚本在 CRLF 下会因 shebang 解析失败而无法执行。

**影响：** 两个平台的检出结果一致；改换行策略需要重新规范化整个仓库（`git add --renormalize .`）。

**状态：** 生效。

## D-004 | 2026-10-14 | 前端构建产物不入库

**决策：** 忽略 `frontend/dist/` 与 `backend/book2text/static/`。

**理由：** 构建产物是派生文件，入库会造成大量无意义的 diff 与合并冲突。说明书 4.2 说明前端构建产物由后端静态托管，这属于**构建步骤**，由构建流程保证，而不靠提交产物保证。

**影响：** 从零克隆后**不能直接运行应用**，必须先执行前端构建（`npm ci && npm run build`）并安装 Python 依赖。Phase 0 的骨架与 Phase 6 的 PyInstaller 打包流程都必须包含前端构建步骤。若日后需要"克隆即可运行"的体验，改为在构建脚本中自动执行前端构建，而不是把产物提交进仓库。

**状态：** 生效。

## D-005 | 2026-10-14 | 测试样本与金标准数据入库，但不得随公开仓库分发

**决策：** `fixtures/pdf/`（测试用扫描样本）与 `fixtures/gold/`（人工校对金标准）**提交进仓库**，以保证测试可复现。

**理由：** 说明书 13.1 要求用真实书籍样本测试；样本不入库则测试无法在另一台电脑或另一平台上复现。`fixtures/gold/` 是人工校对成果，属于高价值资产，丢失无法重建。

**影响：** 测试样本取自真实出版物，**存在版权风险**。仓库在确定许可证（见 D-006）并公开前，必须先将 `fixtures/pdf/` 移出仓库或替换为可自由分发的样本。当前仓库为纯本地仓库，无远端，风险不成立。

**状态：** 生效（附带上述公开前必须处理的前提）。

## D-007 | 2026-10-14 | Git 提交身份与 GitHub 认证方式

**决策：**
- 全局提交身份：`user.name = CLnum42`，`user.email = CLnum42@users.noreply.github.com`。
- GitHub 认证：SSH 密钥 `~/.ssh/id_ed25519`（ed25519，无机密短语），远端 `git@github.com:CLnum42/book2text.git`。
- `~/.ssh/config` 为 `github.com` 指定该密钥，`IdentitiesOnly yes` 避免试探其他密钥。

**理由：**
- **身份与既有历史对齐。** 从 `CLnum42/dsh-DSchat` 的提交记录中查到开发者此前使用的身份正是 `CLnum42 <CLnum42@users.noreply.github.com>`，并验证了该 noreply 邮箱能正确关联到账号（5 条提交全部链接成功）。沿用它可以避免同一人出现两套提交身份，也不泄露真实邮箱。
- **改用 SSH 是权限所迫，不是偏好。** 原计划走 HTTPS + `gh` 凭据助手，但该细粒度 PAT 的仓库范围是"仅选定仓库"：新建仓库被拒（`createRepository` 无权限），对 `book2text` 的 API 请求返回 404。SSH 密钥不受仓库范围限制，且今后新建仓库无需再改配置。
- **修改 PAT 权限有风险。** 编辑细粒度 PAT 的仓库范围可能触发令牌重新生成，进而导致 `gh` 登录失效，需要重新走一次浏览器授权。相比之下新增 SSH 密钥是纯增量的，不会破坏既有凭据。

**影响：**
- 私钥**未设口令**（详见 `docs/known-limitations.md` L-08），文件权限 600。
- `gh` CLI 仍使用原 PAT，因此针对本仓库的 `gh` 命令会 404（详见 L-07）。日常使用 `git` 命令不受影响。
- 仓库创建与密钥添加都必须在浏览器中完成，其中添加 SSH 密钥需要 GitHub 的 sudo 模式验证（重新输入密码），**开发者本人操作，不得代为输入密码**。

**状态：** 生效。

## D-008 | 2026-10-14 | GitHub 仓库为私有

**决策：** `CLnum42/book2text` 创建为 **Private**，描述为"将没有文本层的扫描版 PDF 图书转换为可追溯、经人工审校的结构化文本的本地网页应用（Python 后端 + Vue 3 前端）"。

**理由：** 三条已有约束都指向"暂不公开"——D-006（许可证未定，且牵连 PDF 库的 AGPL 问题）、D-005（`fixtures/pdf/` 将包含真实出版物的扫描样本）。私有仓库同时满足三者，且不影响开发者本人使用。

**影响：** 团队成员（审校助手）需要被邀请才能访问。**转为公开是一键操作，但公开前必须先处理 D-005 与 D-006**，否则会把受版权保护的样本和未定许可证的代码一起发布出去。

**状态：** 生效。
