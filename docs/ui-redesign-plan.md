# UI 全面改写计划（按 docs/ui-mockups 的设计）

> 目标：把现在的"一页到底的卡片堆叠"改成效果图里的**单窗口应用外壳**：
> 顶栏（项目名 / 视图页签 / 保存状态 / 任务状态）+ 四个视图（项目库 / 页面 / 审校 / 合并）+ 若干对话框。
> 本文件是施工计划，做完后归入 `docs/development-log.md` 的记录里。

---

## 1. 现状与目标

**现状**（`backend/book2text/static/`，无构建步骤的原生 JS）：

- `index.html`（573 行）：一个长页面，从上到下依次是 首次运行 → 项目库 → 项目卡（统计 / 页面网格 / 分派 / 结构工具 / 导出 / 审校）→ 引擎自检 → 设置。
- `app.css`（649 行）：通用卡片样式，信息密度低（正文 15px、卡片 18×20 padding）。
- `app.js`（4193 行）：接口调用与业务逻辑齐全，DOM 操作散在各 `render*` 函数里。

**目标**（效果图 6 张）：

| 效果图 | 目标视图 |
| --- | --- |
| `01-library` | 项目库：项目卡片（封面、识别 / 审校两条进度、上次位置、继续 / 打开） |
| `02-pages` | 页面视图：顶部筛选栏 + 6 列缩略图网格 + **右侧已选面板** + 悬浮任务抽屉 |
| `03-review` | 审校视图：左原图（块框标注 / 工具栏）+ 右块列表（类型标签、状态 chip、编辑框、底部操作条） |
| `04-structure` | 结构工具**对话框**：左规则、右抽样预览 + 候选勾选 |
| `05-export` | 导出**对话框**：左选项、右预检摘要 + 成品预览 |
| `06-merge` | 合并审阅**视图**：左页列表、中原图高亮、右逐条变化卡片 |

设计系统（`docs/ui-mockups/styles.css`）作为 `app.css` 的基准：13px 正文、`#2563eb` 主色、
`#f3f4f6` 背景、8–12px 圆角、`chip` / `tag` / `btn` / `select` / `pbar` 等组件。

## 2. 不改的东西（重要边界）

- **后端接口一律不改语义**，只加一个只读计数（见 §4）。
- `app.js` 不重写：**保留全部函数与业务逻辑**，只改"视图路由 + DOM 结构 + 类名"。
- 不做构建步骤、不引入前端框架（说明书第 6 节的前端选型不在本次范围）。
- 不改快捷键（说明书 7.5）、不删任何现有功能（效果图里没有的按钮，收进悬浮操作或对话框）。

    <section id="view-merge"   class="view">   合并审阅三列

## 4. 数据补充（唯一的后端改动）

效果图 01 的每张项目卡要显示**审校进度**（已审页 / 纳入页）与**不确定块数**，
现有 `/api/projects` 只有识别计数。改动：

- `core/project/library.py`：`_PageCounts` 增加一次 SQL 统计 `reviewed_pages`（纳入页中"有块且块都非未审"的页）
  与 `uncertain_blocks`；`LibraryPageSummary` 加两个字段。
- 单测：`tests/unit/` 下加一条断言（新建项目 → 0/0；确认一页块后 → 1 页）。
- 落点：不改接口路径与其余字段，纯增量。

## 5. 分阶段施工

| 阶段 | 内容 | 验收（真实运行） |
| --- | --- | --- |
| **A 外壳 + 项目库** | 重写 `index.html` 外壳与项目库视图、重写 `app.css` 设计系统、`showView()`、项目卡渲染、首次运行 / 设置的对话框骨架、后端审校计数 | 启动服务：项目库卡片显示真实识别+审校进度；新建 / 打开项目进"页面"视图；顶栏页签可切换 |
| **B 页面视图** | 筛选栏（类型 / 识别 / 疑难 / 跳转 / 范围）、6 列缩略图、右侧已选面板（类型 → 纳入/排除 → 识别 → 其它）、悬浮任务抽屉 | 筛选生效；框选 / Shift / ⌘ 选择；批量纳入排除；识别任务跑起来、抽屉进度对；翻页与"在审校中打开" |

| **D 对话框 + 合并视图** | 结构工具对话框（左规则 / 右候选勾选 + 汇总）、导出对话框（左选项 / 右预检 + 对照预览）、任务包对话框（分派 / 结果包 / 导入）、合并审阅三列视图 | 预览→应用标注；导出 TXT/JSONL 并下载；分派→导出结果包；导入结果→逐条接受/拒绝→提交 |
| **E 设置 / 自检 / 诊断** | 设置对话框：名字、引擎自检表、当前限制、环境信息、诊断日志导出、平台警告条 | 保存名字后顶栏与项目卡显示；诊断日志下载 |

每阶段结束时 `git commit` 一次，保持"一个可运行、可验证的切片"。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `app.js` 里散落的 `el("…")` 在重写后取不到节点 | 保留**全部现有 id**，只改它们的容器与类名；阶段 A 先跑一遍 `boot()` 确认无报错 |
| 效果图里的按钮（如"识别样本"）功能未实现 | 不新建假按钮：只放已有功能；"样本识别"用现成的"识别所选 + 提示"表达（说明书 6.3 的口径） |
| 助手端（任务包）隐藏逻辑失效 | `applyPackageMode()` 逐一核对新 DOM；任务包视图里隐藏导出 / 结构工具 / 识别 |
| 14 寸屏幕放不下 52%+48% 的双栏 | 断点：<1180px 时审校视图改上下布局、页面视图收起右侧面板为抽屉 |
| 大改动丢数据 | 只动前端三件套 + 一个只读 SQL，不碰数据库结构与写入路径 |
