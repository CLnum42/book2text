## 一、界面复核「一次撤销三行全回」：True

`/tmp/b2t-undo`（干净副本）上走界面，不调脚本：

| 步骤 | 实测 |
|---|---|
| 点 3 行差异行 → 各追加一个标记字 | 编辑态 3 次都进去（`is-editing`） |
| 工具栏 | **`未提交 3` / `提交 3 处`** |
| 点「提交 3 处」 | 提交成功，`提交 0 处`，`未提交` 徽标消失 |
| 提交后三行文本 | 三行都带上了改动的字（库里的值） |
| `⋯ → 撤回上次提交` | 三行**全部回到原文** |
| **三行全部复原** | **True** |

库里对账：这次提交 = **一个 batch**（`01M609KKF78RFF5STW4D57VSQF`，**6 个事件** = 3 块 + 3 行），
撤销产生另一个 batch（**6 个事件**）。所以按钮点一次退的是**一整批**，不是一行。

截图：`docs/screenshots/undo-before-submit.png`、`undo-after-submit.png`、`undo-after-undo.png`。

## 四、marks 按页懒加载（新代码）

### 之前为什么慢

`/review/marks` 每次把 **5,036 个块重算一遍分歧**（复用了 `divergence_index` 之外的第二条路径）：
**0.90 s / 1.52 MB**，而且是在开项目最挤的时候跟预览抢 CPU。

### 改了什么

1. **复用 `divergence_index()`**（已按库 mtime 缓存）：marks 只做筛选，不再重算 → 11 ms；
2. **按页窗口**：`?page=36` / `?first=1`（窗口套在第一处未审页上），默认 ±10 页；
   `counts` / `page_counts` / `first_unacked_page` **始终是全书的**，进度条与"下一处"用它；
3. **落盘缓存** `<项目>/cache/reading-marks.json`（键 = 库内容签名），新进程 15 ms；
4. **前端**：marks 只加载窗口，红字**不再等 left tree**（tree 单独拉、后到）；
   翻到窗口外的页再补一块，补完只重画已铺出来的 8 段（保持滚动位置）。

### 数字

| 场景 | 之前 | 现在 |
|---|---:|---:|
| `/review/marks` 全书 | 0.90 s / 1.52 MB | 11 ms（索引已热） |
| `/review/marks` 窗口 ±10 页 | — | **1.7 ms / 72 KB** |
| 新进程第一次窗口请求 | — | **15 ms** |

冷（进程刚起 + 缓存被数据变更作废）：点击 → 红字 **4.3 s**，其中预览重建 1.07 s、

## 五、这轮顺手修掉的三个真 bug

1. **补 marks 的重画会打断正在编辑的那一行**：翻页补窗口 → 重画 → 编辑态与光标一起丢。
   改成编辑期间欠着重画，`Esc` 退出编辑后再补。
2. **四个派生缓存在开项目时同时失效**：`open` 会建出 **0 字节 `project.db-wal`**，
   它的 mtime 一变，四个缓存的签名全部对不上 → 同时重算（实测 8.6 s）。
   签名改成「`project.db` mtime + **非空** WAL」，且"没有 WAL 文件"与"0 字节 WAL"同一结果。
3. **并发首次请求各自重算同一份数据**：`divergence_index` / marks / 预览段三处加锁，
   只有一个线程真算，其余等锁后直接拿缓存（冷启动 8.6 s → 5.9 s → 见下）。

> 备注：冷启动仍是 4–6 s（一次性重建四份派生数据），热态 0.3 s。
> 进一步压冷启动要把 `finish_summary` 的逐页聚合也做增量缓存，不在这一刀里。
