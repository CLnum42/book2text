## 三条产出路径

| 路径 | 做法 |
|---|---|
| 新项目识别 | `RapidOcrAdapter.recognize(..., return_word_box=True)`：中文逐字框、英文词级框，随行一起写进 `block_line.word_boxes`（实测 34/34 行有框） |
| 已有项目回填 | 逐页跑一次识别（**只取结果、不落库**），按 `bbox IoU + 文本相似度` 配到已有 `block_line`，**只写 `word_boxes`** |
| 可搜索 PDF | 字框直接从文字层 `get_charbox` 取（`page_text_chars`），连 OCR 都不用；文字层字符框退化成零高度（不可见文字）时自动回退识别 |

## 存储

`block_line.word_boxes TEXT`（迁移 0021，JSON 数组，每项 `{text,bbox,confidence}`）。
配不上的行写 `"[]"`（"试过、没有可用字框"）——不写的话分页/续跑会反复选中同一批页。
**查询方式**：按 `line_id` 读写（一次一页的行随 `/pages/{n}/blocks` 带出），没有全表扫。

**大小**（红楼梦 3 实测）：`project.db` 11.6 MB → **40.6 MB**（+29.0 MB，9596 行有框，
约 3.0 KB/行、约 110 B/字框）。394 页约 22 万字的书，这个体积可以接受；
要更省可以改成"字宽数组 + 行框"再算，但这一刀先按可读 JSON 存。

## 入口

`⋯ → 字框回填…`：先看计划（还剩多少页/行、文字层取多少 / 要识别多少、预计耗时），
再分批回填（每批 2 页，界面显示真实进度与配对数）；`撤销字框` 一键把字框置空
（其它字段本来就没动）。关掉对话框 = 停在当前批，再点从没字框的行继续。
