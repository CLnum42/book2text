项目级建议框 `[0.1025, 0.0832, 0.8614, 0.9144]`。第一版置信度报 `low`（规则误报，已修，见 L-101）：

- 左右边缘覆盖率 74.6% / **11.7%**，提示"左右边缘只覆盖 12% 的正文行，
  各页的缩进 / 分栏可能不一致"；
- 上下覆盖率 100%，离散 3.5%。

这是**规则的误报**：这本书是**左对齐（ragged-right）**排版，绝大多数行的右端
停在不同位置，所以"右边缘覆盖 11.7%"是正常现象，不是双栏。修完之后：

- **置信度 `low` → `medium`（reliable = True）**；
- 提示语变成「这本书是「左对齐」排版：左侧有 75% 的行贴边，右侧参差（12%）是正常的，不是双栏。」；
- 判据改成三条：左右离散 ≤3%（上下放宽到 7%，章末页只排半页是排版事实）＋
  **有一侧贴齐** ＋ **参差侧的外边界（每页最右端）离散 ≤2%**。
  第三条是为了不放过"版心逐页漂移"的书（单元测试里左右各页相差 40% 页宽那种）。

## 4. 页码定位：从文字层取到了 270 页的 `Page N`，但它不是连续页码

第一版只找到 1 个候选模板、覆盖 5 页，等于没有页码。查清后发现两个原因**同时存在**：

1. 页眉印的是 **`Page 31`**（带词的数字），而候选收集只认纯数字 / 罗马数字；
2. 那行页眉**落在版心框内**，而位置规则只收"版心外"的行。

改成"数字原生 PDF 额外从文字层的页眉 / 页脚取"之后，**270 / 662 页取到了 `Page N`**。
但**它不能当页码用**：

| 印刷值 `Page N` | 出现在 PDF 第几页 |
|---|---:|
| Page 28 | 93 |
| Page 65 | 172 |
| Page 108 | 263 |
| Page 142 | 334 |
| Page 153 | 357 |

PDF 页每涨 1，印刷值只涨约 **0.53**，偏移从 65 一路涨到 192——这本书的 PDF 页数
是 `Page N` 编号的约 **2.25 倍**（658 页处只到 `Page 276`）。
所以 `Page N` 不是连续页码（大概是原书分页的残留），拿它当锚点会把目录确认指到错页。

结论：模板可信度判定为 `unreliable`，`filled: 0`、`located: false`、`skippable: true`，
界面明确告诉用户"这本书没有可用页码，目录确认只有 PDF 页序"。**这是正确处理，不是缺陷。**

## 6. 文字层伪影分类（给"以后要不要走文字层"用）

拿 656 页做同一口径对比，文字层有、OCR 没有的三类：

| 类别 | 例子 | 全书数量（文字层） |
|---|---|---:|
| 引号被拆成两个撇号 | `''Way"` | 109（撇号多出的部分） |
| 行内软连字符残留 | `self￾realization`（U+FFFE） | **101** |
| 破折号丢失 | `universethis`（原 `universe—this`） | 这本书 OCR 也有 1 处（p41），不是文字层独有 |

结论：**要拿文字层当主，提取时必须先规范化这三类**（U+FFFE/U+00AD 去掉、
`''` → `"`、行末连字符按断词还原）。这三条都能在**提取层**做掉，不需要动识别。
