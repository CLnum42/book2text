## 一、判决：Jev 不能替代「第二引擎 + 差异对照」

**① Jev 在结构级上的召回：抓到 3/4（75%），漏掉的那 1 个是原理性盲区。**
表内题字（p14）、乱码行（p23）、书眉块（p36）三处的分数分别是 0.001 / 0.000 / 0.000——**都标出来了**；
但 **p17 整行漏识它抓不到**：那一行在 OCR 输出里根本不存在，Jev 只评「已有候选」，没有候选就没有输入。
所以它**不能**替掉"漏行"这一类。

**② 字级上 P(错 | 两引擎一致) = 3.73%（26/697）。** 远高于 0.25% 的目标线，也远高于 0.5% 的容差。
砍掉第二引擎等于把这 26 行错误变成**没有任何信号**的错误——**第二引擎该留**。

**③ 每页成本：从 2.5 秒变成 17.9 秒（Metal）/ 70.9 秒（CPU）。**
一本 490 页的书：现在约 21 分钟；接 Jev 后约 146 分钟（Metal）或 9.7 小时（CPU）。

## 三、判决：PP-DocLayoutV3 不能替掉「短行等长组」启发式，但可以并用

### 数据

| 项 | 结果 |
|---|---|
| 40 页耗时（CPU） | 中位 **3.75 s/页**，p90 8.06 s，40 页合计 **188.3 s** |
| MPS | **不可用**——paddlepaddle macOS 无 MPS 后端（`paddle.device.set_device('mps')` 直接报参数错误） |
| 峰值内存 | **948 MB** |
| 区域框 | 40 页共 217 个：`text` 141 / `aside_text` **31** / `number` 33 / `image` 10 / `paragraph_title` 2 |
| 对竖排书眉 | **31 个 `aside_text`**，中心 x 0.025–0.061（正是书眉列）；与我复现的 31 个启发式块按 IoU>0.3 配上 **27 个（87%）** |
| 对 p14 图内题字 | `image` 框 `[0.081,0.546,0.475,0.934]` **完整包住题字块**（0.113–0.216 × 0.56–0.612），类型判对 |
| 误报（非正文框压在正文行上） | **0**（逐页逐行核过） |

### ② 行级归属（把 217 个区域框与 1054 条 OCR 行按"行中心落在框内"配对）

| 结果 | 行数 | 占比 |
|---|---:|---:|
| **唯一归属** | 1019 | **96.7%** |
| 一对多 | 0 | 0% |
| **完全配不上** | 35 | **3.3%** |

唯一归属的标签分布：`text` 949 / `aside_text` 31 / `number` 33 / `paragraph_title` 3 / `image` 3。

**配不上的 35 行分布**：p12 整块诗歌 **17 行**（「世人都晓神仙好…」，整块没有对应区域框）、
p1 标题与回目 3 行、页码若干（y≈0.97，落在最下框之外）、p4/p7 等书眉各 1–2 行。
→ **两套坐标系基本能对上（96.7%），但不是全对上**：整块诗歌和章首回目这两类会掉。

### 判决（三选一）

**B——能补，不能替。**

- 不能替：召准 27/31 而不是 31/31，低于启发式的 "32/32 零误伤"；而且它每页 3.75 s、948 MB，是启发式的几十倍成本（启发式随行框免费）。
- 能补：它给**类型**（`aside_text` / `image` / `number` / `paragraph_title`），启发式给不了；
  并且 p14 的图内题字被独立判成 `image` 且框完整——这类"图里印的字"是启发式靠"短行+不在正文栏"猜出来的，DocLayout 是直接判出来的。

**未验证：** 竖排正文（本书没有竖排正文，只有竖排书眉）；古籍异体字/双栏混排；Windows。

## 五、失败与未验证

- **Jev 的 p17 漏行**：不是失败，是模型边界——判官只能评"有候选"的区域。

- **PP-DocLayoutV3 无 MPS**：paddle macOS 只有 CPU。
- **两个模型都没在 Windows 上验证过。**
- **本轮没有重测 Vision 的速度**；表中"现方案 2.5 s/页"取自 2026-10-28 隔离测量（RapidOCR 1.13 s + Vision 1.41 s）。
