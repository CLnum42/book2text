# 第二引擎改为可选 + 用 PDF 文字层当第二引擎

> 2026-10-27。验收项目 `b2t_RXQ39D`《红楼梦》4_可搜索_精简（490 页，488 页带文字层，
> 436 页正文已识别、0 页第二引擎）。全部在副本上跑。

## 1. 完成判定 = 主引擎跑完

`finish_summary` 的 `engine.complete` 改成**主引擎完整度**（正文页都有主引擎结果），
`checked / total` 仍是第二引擎的进度，新增 `main_complete` / `aux_complete`。
识别步步骤条、收尾面板、`stepProgress` 同步：第二引擎 0 页也是 ✓。

进「正文审校」前如果第二引擎没跑完，弹一条警告：

- 「还在跑（N/M）」/「还没跑完（N/M）」，说明队列还会变；
- 「等它跑完再进」（没在跑就先起任务，自己轮询到结束再进）/「先开始审校」（本轮不再拦）。

## 2. 文字层当第二引擎

- 带文字层的页：`run_auxiliary(prefer_text_layer=True)` 直接读 PDF 文字层
  （`render.page_text_lines`：按换行切行、字符框外接矩形、归一化），
  **不跑 Vision**；`ocr_run.engine_id = pdf_text_layer`，params 里记 `source: text_layer`。
- 配对：**阅读顺序 + 文本相似度**做序列对齐（DP，允许两边各跳过若干行），
  **坐标只用来验证**——纵向重叠给加分、DP 漏配的行再用坐标补配
  （重叠 ≥0.6 才算），文本与坐标都不合的配对不硬塞（`aux_text` 留空）。
- 页面旋转不是 0 时不读文字层（坐标口径对不上），回退真正的第二引擎。
- 批量复核任务在**全部页都带文字层**时不要求第二引擎可用；
  逐页遇到底层没有文字层的页，才用引擎（没有就那一页失败并写原因）。
- 显式注入引擎（双引擎策略 / 测试）一律用那个引擎，不被文字层替代。

## 3. 实测数字（b2t_RXQ39D 副本）

| 项 | 结果 |
|---|---|
| 全书 436 页文字层复核 | **436 页 / 43 秒**（0.10 秒/页，含写库与比对） |
| 同一批页跑 Vision（5 页样本） | 4.3–6.2 秒/页；全书约 **41 分钟** |
| 行级状态（全书） | identical 5691 · format_only 4114 · differs 5469（共 15274 行） |
| 5 页样本对比（版心内差异，队列口径） | Vision 117 行 → 文字层 103 行（−12%） |
| format_only（5 页样本） | Vision 15 → 文字层 1（文字层标点已被 OCRmyPDF 统一） |

差异条数差异的来源：文字层里页眉/页边竖排书眉没有文本（那几行 aux 为空 → 记为 differs，
但都在版心外，不进审校队列）；反过来 Vision 的标点全角/半角差异在文字层里消失了。
"队列口径"上文字层比 Vision 少 12%，不是多出假分歧。
