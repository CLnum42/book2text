# RapidOCR 原生层段错误：padding 到 32 的倍数 + 崩溃页兜底

> 2026-10-27 热修。真项目 `b2t_XPAT9E`《鹿鼎记》200 DPI。

## 现象与定位

| 页 | 渲染尺寸 | 修前 | 修后 |
|---|---|---|---|
| 281 | 1069×1762 | 检测 / 整页识别都 SIGSEGV（3/3） | 43 行，exit 0 |
| 299 | 1066×1762 | 同上 | 43 行，exit 0 |
| 280 | 1073×1754 | 正常 43 行 | 正常 43 行 |

根因在 RapidOCR / onnxruntime 的原生预处理：宽高不是 32 的倍数时，
某些尺寸会段错误（Python 里拦不住）。补到 32 的倍数（右下补白、内容不平移）后正常。

## 修法

1. `core/ocr/base.py` 新增 `pad_to_multiple()`：只在右 / 下补纸色白，内容留在左上，
   所以引擎返回的像素坐标**不需要平移**；已是倍数时原样返回（不复制图像）。
2. `core/layout/adapters/rapidocr_det.py`、`core/ocr/adapters/rapidocr.py`
   在调用引擎前统一 padding；`normalize_quad` 仍按**原图**宽高归一化（否则框会缩小
   1069/1088）。
3. **兜底**：子进程被崩溃信号（SIGSEGV / SIGBUS / SIGABRT / SIGILL / SIGFPE）杀掉时，
   `Supervisor` 把正在跑的那一页记成「引擎崩溃（…）· 已跳过」，任务标中断；
   `pending_items(skip_crashed=True)` 从此跳过这一页，**「继续」不会再撞同一页**，
   剩下的页照常跑完。被 SIGKILL / SIGTERM 停掉的仍按"中断"处理，不算崩溃。

## 验证（本机 macOS arm64）

| 项 | 结果 |
|---|---|
| 检测 p281 / p299 | 43 / 43 行，0 崩溃 |
| 整页识别 p281 / p299 | 43 / 43 行（2.1 s / 2.6 s） |
| 随机 30 页检测（XPAT9E，1–512） | 1267 行，0 崩溃，13.8 s |
| 随机 5 页整页识别 | 11359 字，11.2 s，0 崩溃 |
| 完本抽 10 页（`b2t_BRRBR0`，267 页） | 检测 259 行 / 识别 6414 字，0 崩溃 |
| 崩溃兜底（真杀进程） | 把 worker `kill -SEGV`：失败页记 `引擎崩溃（信号 11）`；「继续」跳过该页，29/30 页跑完 |
| padding 耗时（5 页中位） | 0.203 s → 0.226 s（+0.02 s/页，约 10%） |

**没验的：** 全 512 页整本扫描（按 Chief 的允许项只跑了"会崩的尺寸那批 + 随机 30 页"）。
红楼梦项目已被用户移入废纸篓（`b2t_YV1P2Y` 不在项目库里），"抽 10 页不回归"用
`b2t_BRRBR0`（267 页完整识别）代替。

## 回归测试

`tests/unit/test_rapidocr_padding.py`：尺寸补齐 / 内容不平移 / 已是倍数不复制；
1069×1762 合成图上检测与整页识别都不崩、坐标按原图归一化。
`tests/unit/test_jobs.py`：崩溃页记页号 + 继续时跳过 + 全做完时任务结算为中断。
