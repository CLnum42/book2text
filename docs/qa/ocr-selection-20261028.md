# Book2Text OCR 选型：一页纸结论（2026-10-28）

> 评估人：OCREval。全部数字来自真书实测，命令与页号见 `ocrev/ocr-candidates-ledger.md` 对应章节。
> 机器：Apple M5 / 32 GB / macOS 27.0.1，无 NVIDIA。两本书：《红楼梦》真库 394 页、英文书 662 页。

## 一、结论

| 位置 | 结论 | 依据 |
|---|---|---|
| **主引擎** | **RapidOCR 3.10.0（ONNX）**，保持 | 40 页金标准 CER 1.21%（200 DPI）；行框 100%、版心内正文字框 99.1%；1.04–1.64 s/页；峰值内存 2.7 GB；完全离线 |
| **第二引擎** | **Apple Vision 留**，但价值仅限"独立观测" | 每百行 3.10 条真捕获；把主引擎 75.8% 的错行推到人眼前；代价是每 1 条真错伴 6.4 条假警报 |
| **第二引擎候选** | **当前候选集为空** | Tesseract 5.5.3、EasyOCR 1.7.2 均因"错误相关性"出局（见下） |
| **生成式方案** | 不作第二引擎，仅记作将来"换 NVIDIA 机器时的主引擎候选" | OXR、OvisOCR3、Surya、dots.ocr、MinerU、Marker、PaddleOCR-VL 均违反"非生成式" |

## 二、被否掉的与原因

| 方案 | 判决 | 关键证据 |
|---|---|---|
| OvisOCR3（0.8B） | 不合格 | 无字符级框（只有词/token + 区域）；自回归生成式；官方要求 vLLM+GPU，Apple Silicon 无公开跑通记录 |
| Tesseract 5.5.3 | 不合格 | 行裁图对主引擎 55 个错字**改对 0 个、100% 同错**；整页虽改对 34 个，但自引入 512 个错（主引擎的 9 倍） |
| EasyOCR 1.7.2 | 不合格 | 主引擎错的 99 行上**改对 0 行、100% 同错**；假警报/真捕获 119.7（归一化口径）或 ∞（原始） |
| 云 OCR | 不合格 | 隐私约束，一票否决 |
| PDF 文字层当第二引擎 | 不可行 | 中文那本的"文本层"其实是扫描件后加的 OCR 层，不是原生排版源 |

## 三、两条被数据推翻的既有假设

1. **"红楼梦是竖排繁体扫描件"**——错。真书是数字原生 PDF、正文**横排简体**；竖排窄行只占 3.9%，全是左侧装饰书眉与页码碎片。
2. **"两路不一致"有廉价降噪手段**——没有。文本层（不是原生层）与置信度（Vision 量化成 0.3/0.5/1.0，Rapid 挤在 0.94–1.0，AUC 0.547/0.608）都不行。队列长度是固定的，效率只能从交互挣。

## 四、未验证项（不许当结论用）

- 真实带扫描退化的旧书（倾斜/噪点/透印/装订阴影）：**未测**，两本书都是干净栅格化。
- 竖排正文（换书才会遇到）：**未测**；本项目两本书都没有竖排正文。
- 英文书的识别**准确率**：没有人工 GT；文档里的 0.32% 是"OCR 对文本层"，而英文那本的文本层是 calibre 排版层（可信度高于 OCR，但不是真值）。
- 繁体书：**未测**。
- 第二引擎的审校效率收益（省多少时间）：**未测**，只有"能圈进多少错行"。
