## P0-1 版心步不再谎报「已自动拟合」

**修前（真机截图 `p0-margin-before.png`）**同一屏三处互相打架：

- 右上「下一步」：**版心已自动拟合**；拖动四边调整，不改也算已定
- 版心摘要：**0/512 已定**；面板徽标：未定
- 底部状态：**已自动拟合 520 页版心**（比总页数还多——按"尝试次数"累加）
- 页面上**一根框都没有**

**根因两处**：

1. 进版心步的自动补把"没有行框的页"也送去 `fit-all`。这些页拟合结果只能是空，
   但 `updated` 把"处理过"算成"拟合成功"，界面再按累加值报数。
2. 文案不看本页真实状态，只要选中一页就写"已自动拟合"。

**现在**：

- 页载荷新增 `layout_lines`（最近一次成功检测的行数，一次聚合查询）。
- 自动补只送**有行框**的页；结算按后端回传的 `fitted / fallback / undetermined`
  分别说：「已自动拟合 N 页」只在真的写出框时说；没行的页说「N 页没有可用的正文行，版心仍是未定」。
- 单页文案按状态出：有框=已拟合；有行未拟合=「有 N 行检测结果，但还没有拟合出四边」；
  没行=「还没有可用的正文行（检测行 / 识别行框都没有），拟合不出版心」。
  不写"下一步去识别"这类跟着步骤顺序变的话。
- 面板下方常驻缺口提示：还差多少页、其中多少页没有行、去哪里跑检测。

## P0-2 目录确认：只有 PDF 页序时不再装成目录

`stats.complete` 原来是「有页就算完成」，所以 512 页 0 印刷页码的册子上，
步骤条亮绿勾、列表写着「未识别页码 / PDF 1…512」，看着像目录。

- `complete` 改为 `numbered > 0`；新增 `stats.page_order_only`。
- 页序模式：摘要写「仅 PDF 页序 · 512 页 · 还没有印刷页码」；
  每条只剩「PDF 第 N 页 · 无印刷页码」；顶部黄色说明条解释印刷页码从哪来；
  「按印刷页码跳转」输入框禁用并常驻原因；页头写「无印刷页码（只有 PDF 页序）」。
- 步骤条不再变绿（截图 `p0-index-empty.png`，与 `p0-index-before.png` 对照）。

## P1-3 检测入口：从版心步主位挪进「⋯ → 检测版面…」

旧按钮「检测这些页的正文行…」点击没反应的原因：它把**所有**未定页（含封面 /
空白等非正文页）传给 `POST /jobs/layout`，后端对非正文页直接 400；
错误只写进 `#pages-error`，在版心步根本看不见。

现在：入口在右上角「⋯」，先取 `GET /projects/{id}/layout/plan` 再让用户决定：

- 计划：正文页 / 已有检测 / 这次要检测 / 只补拟合 / 预计耗时 + 单页耗时；
- 估算来源优先用**本项目跑过的检测实测中位数**（本机实测 0.384 秒/页，取 0.45 保守值），
  没有历史时注明「按本机实测速度估算」；
- 只传正文页且 `prepare: true`（有检测行的页只补拟合，不重检测）；
- 建任务失败时原因就地显示在对话框里（不再只写 `#pages-error`）；
- 跑起来后版心分区有真实进度与剩余时间（按已跑出的速度算），任务抽屉照旧可暂停 / 取消；
- 结算按真实状态说：`succeeded / failed / interrupted / cancelled` 分别有不同文案，
  **中断绝不写成"完成"**。

## P1-4 审校三栏可拖

左树 / PDF / 正文之间两条 6px 手柄，拖动只改自己那一栏；宽度记在
`localStorage["b2t.readingSplit.v1"]`；最小宽度 树 150 / PDF 240 / 正文 360；
双击手柄恢复默认；<1120 宽由样式表接管（手柄隐藏、树 44px、PDF 收起）。
实测：420 → 560 px，刷新后 `pdf=560` 仍在（截图 `p1-reading-split.png`）。

## 独立发现：RapidOCR 检测器在两页上段错误

`b2t_XPAT9E` 第 **281、299** 页会让检测器 `SIGSEGV`（进程直接崩，无 traceback）：

- 同一页渲染成 PNG 再检测仍然崩 → 是**图像内容**触发，不是 PDF 渲染；
- **纯白 1066×1762 图像也崩** → 空白页同样踩雷；
- 直接单进程调用可稳定复现（exit 139）。

后果：检测任务跑到那一页就"意外结束"（`interrupted`），点「继续」会**再次**从同一页崩，
任务永远跑不完。这本 475 正文页里跑到 245 页（282 起 17 页后）就死在这里。

这一处属于管线（`core/layout/adapters/rapidocr_det.py` / onnxruntime），本轮不动，
已报给 Chief / Extractor。在它修好之前，「检测版面」对含空白页 / 这几页的书不可用。
