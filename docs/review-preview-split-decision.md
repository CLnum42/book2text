## 1. 一句话

审校页只回答「这处差异留哪个」，预览页只回答「成品还要改哪里」。两页不是把一屏切成两屏，而是把**人工审核（阶段 9）**和**组装 / 预览 / 导出（阶段 10–11）**分开——两者的完成判据本来就不同。

分界线按「谁负责发现」切：机器指得出的疑点归审校页；机器指不出的错（两路一致但都错、段落合并、标点归一误伤、断词）归预览页。**能力可以重叠，责任不重叠。**

---

## 2. 两页的边界

| | 审校页 | 预览页 |
|---|---|---|
| 唯一目的 | 把机器标出的每一处判完，让「还剩多少」是一个能对齐的数 | 以读者的方式通读成品，改掉机器没标出来的错 |
| 左栏 | 全书差异目录（汉字级逐条 + 标点汇总入口） | 书籍目录（章节） |
| 中栏 | 当前页 PDF，只标差异字（不填色、不压字） | 当前页 PDF 原文 |
| 右栏 | 当前差异的 A/B 两版，一屏只展开一条 | 组装后的干净文本，点字可改 |
| 编辑对象 | 这一处差异（留 / 换 / 自己改） | 这一行成品文本 |
| 完成度 | 进 k/6（队列归零） | **不进完成态**（D-090） |
| 数据 | `next-lines` + `marks?page` + 页图 | `segments`（唯一成品来源）+ 页图 |

## 3. 已定的技术口径（每条都能指到代码）

1. **不建成品版本表。** `Segment` 是导出时推导的（`core/export/segments.py:178`），`segment_id` = 首块 `block_id`（`:138`），合并 / 拆分就变；一存就与导出发叉（D-106 的复现路径）。
2. **预览页编辑是行级，不是段级。** 点到的字落在哪个 `line_span`，就改哪一行；跨行只能走 `merge-prev` / `split` / `continues_to_next`；合并插入的空格、断词删掉的连字符不属于任何一行，成品上只读（实测 43 字 / span 覆盖 41 / 派生 2）。
3. **写文本只有一条路：`submit-drafts`。** 它是唯一同时写 `block.text` 并 `sync_line_text` 的入口（`routes_review.py:656–666`）。`PATCH /blocks` 只写块文本，**改字会留下旧行记录**——`PATCH` 只许用于 `block_type` / `include` / `continues_to_next`。
4. **手改 = 写 `edited`。** 三值并列 `kept` / `adopted` / `edited`。今天「改完关不掉」：`kept` 带文本会静默丢弃（`editing.py:877/904`），只改文本不写 ack 会回队列（`routes_review.py:426` 只跳过有 ack 的）。加 `edited` 不动数据库（`diff_ack` 是 TEXT、无 CHECK），动枚举、事件、统计键与文案。有一条判据：改完必须同时满足 **`block.text` 变了 / `block_line.text` 同步 / `diff_ack=edited` 且 `diff_ack_text` = 新文本**。
5. **审校页不读 `segments`。** 队列 `next-lines`、差异 `marks?page`、页图自己取，三样都现成；成品只剩预览页一个消费者，前端 `/export/preview` 字面量从 2 处收到 1 处（R14 棘轮，例外表只降不升）。
6. **Jev 分数加在 `next-lines` 的 items**（`include_scores=1`，默认关，实测 ~7 ms / +20 KB），不加 marks；排序仍是 `(tier, 阅读顺序)`，**不改**，只改文案（`routes_review.py:461–474`）。
7. **失效链**：写库 → 项目 mtime → 签名变 → 下次取必是新结果；忙时缓存 10 秒（`cache_policy.py:29`）意味着写后必须清该项目的 preview 缓存，否则「改了没生效」。

## 4. 要用户拍板的三条（附建议）

1. **步骤条**：建议把第 6 步从「文件导出」改名为「预览与导出」，视图就是 `#view-preview`，导出按钮在它上面；`正文审校` 指向 `#view-reading`。不加第 7 步——D-090 已定预览不进 k/6，加步会动完成度口径。
2. **预览页完成态**：建议不设闸（不显示「预览完成」，不做「没预览过不能导出」）。导出仍由审校完成度把关，不给产品造第二个「完成」定义。
3. **版心外条目**：建议不进审校页目录，在目录底部给一行「版心外 45 条（不进审校与完成度）」，点开只读清单、可跳到版心确认。理由：它们不进导出、不进 `r.complete`，进了目录就是分母里的假条目；全藏掉，用户又永远不知道——而它往往是版心判错的信号。

## 5. 验收判据（能机检的）

| 判据 | 怎么查 |
|---|---|
| 预览 = 导出 | 同 options 下 `export/preview` 与导出的 `segment_id` / `text` 逐条相等 |
| 改一行三件事 | 改后读库：块文本变 / 行文本同步 / `diff_ack=edited` 且 `diff_ack_text`=新文本 |
| `kept` 带文本不再静默丢弃 | 接口回 400，不是 200 + 文本没改 |
| 成品单一入口 | `grep -rn "export/preview" backend/book2text/static/*.js` 的调用点 ⊆ 例外表，且只降不升 |
| 没有第二份成品 | `migrations/` 无 segment 覆盖表；`grep -rn "segment_override" backend/` 为空 |
| 两页数字不打架 | 审校页顶栏分母 = `queue_items().totals.total`；预览页段数 = `segments.length`，两者不互相推导 |
