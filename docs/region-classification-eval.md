## 1. 任务目标

回答一个问题：只靠**几何 + 跨页重复 + 文字形态**三类信号，把"页眉 / 页脚 / 页码"
的判断从**块级、分组之后**提前到**行级、分组之前**，判得准不准？

- 能不能把非正文找全（检出率）？
- 会不会误删正文（误标率，**最重要，必须接近 0**）？
- 剔除后正文 CER 相对现有基线（1.08% 行级 / 0.71% 导出路径）如何？
- 如果不够用，要不要上版面模型（RapidLayout / PP-DocLayout）？

不在范围内：改产品代码、改页眉页脚工具的交互、多本书的结论、版面模型实测。

## 2. 当前状态（开始前）

- 产品的页眉 / 页脚 / 页码是**块级**判断：`core/project/structure.py` 在分段之后
  按"页面顶部 / 底部 8%、左右 10% + 字数 ≤ 20 + high/review"标块（说明书 6.5 / D-034 / D-036）。
- 它的已知风险是**页眉行与正文首行被拼进同一个块**，于是整块被判成正文；
  反向的误伤已经发生过一次（第 37 页段末行被标成页脚，`ocr-evaluation.md` 6.3.1）。
- 没有行级的候选规则，也没有"行级规则判得准不准"的数字。

## 3. 实施计划（实际执行的步骤）

1. **复现行集合**：用产品同一条路径（`core/pdf/render.py` 200 DPI + `RapidOCR` 适配器）
   跑 40 页，拿到每行的 bbox 与文本，缓存到系统临时目录。
2. **建行级金标准**：OCR 行与按页金标准对齐（复用
   `scripts/measure_divergence.py` 的 `locate_in_gold` 前缀 + 后缀锚点），
   匹配上的判正文；匹配不上的**逐条人工分类**（131 行）。
3. **实现候选判定器**：`scripts/region_rules.py`，纯函数，三类信号 + high / review 两档。
4. **度量**：检出率、误标率、漏标率、行级与导出路径的 CER、失败案例。
5. **给结论**：只根据上面的数字。

与 `measure_divergence.py` 相同。

### 4.2 行级金标准怎么来的

- 分页金标准：`..._分页草稿.txt`（39 个页边界）。**它没有第 1 页的标记**——
  第一个 `〔PDF 第 N 页〕` 之前的内容就是第 1 页；`measure_divergence.load_gold_pages`
  会把这段丢掉（见 7.2 的顺带发现），本脚本单独处理。
- 对齐上 **933 行（87.7%）**，判正文；匹配不上 **131 行（12.3%）**，逐条人工分类。
- 分页草稿**不含三处章首回目**；全文金标准含。因此：**对齐用分页草稿**
  （回目落进"匹配不上"，人工标 `heading`），**CER 用全文金标准**（否则剔除后 CER
  会因为金标准本身缺 48 字而虚高）。

人工分类的 131 行（`scripts/region-labels-hongloumeng-40p.json`，每行带文本指纹）：

| 类别 | 行数 | 说明 |
|---|---:|---|
| header（书眉） | 38 | 37 个页面各 1 行；第 8 页被 OCR 拆成 2 行 |
| page_number（页码） | 37 | 第 1 / 14 / 25 页（章首页）没有页码 |
| heading（章题 / 回目） | 9 | 3 个章首页 ×（`第X回` + 2 行回目） |
| other（装饰 / 插图） | 15 | 10 处页码下的装饰短线 + 3 行插图题字 + 2 处插图碎片 |
| body_unaligned（正文但对齐失败） | 32 | 9 行 ≤ 3 字（定位器下限 4 字）；23 行首字 / 全角括号差异导致锚点失败 |
| body_missing（金标准漏收的正文） | **0** | 没有发现 |
| footer | **0** | **这本书没有页脚** |

**核对方式（逐条，不是抽样）**：131 行全部读过；其中 5 处靠 300–600 DPI 的版面裁图确认
（第 8 页页码下的短线、第 29 页行尾引号碎片、第 14 页插图题字、第 4 / 22 页插图碎片）；
23 行长正文另用与全文金标准的字符串比对（≥ 8 字窗口，个别用更短片段）确认确实在原文里。
标签带 `text_hash`，OCR 结果一行漂移脚本就报错，不会静默错标。

### 4.3 判定器（`scripts/region_rules.py`，规则现已移到 `core/structure/regions.py`）

| 信号 | 做法 | 参数 |
|---|---|---|
| 几何 | 以**本页正文文字块**的边界为参照：取"与最多其他行横向重叠"的那一列为正文列，框取该列外接矩形；落在框外一个容差内的行才候选 | 容差 0.25 行高 / 0.25 字宽 |
| 跨页重复 | 同一位置（bbox 中心 ±0.05）、文本相似（去空白与数字后 ≥ 0.6）在 ≥ 3 页出现 | 3 页 / 0.6 / 0.05 |
| 文字形态 | 纯数字 / 罗马数字（沿用 `structure.looks_like_a_number`）判页码；`>20` 字的长行不候选 | `max_chars=20` |

把握程度沿用产品口径：**页码形态或跨页重复 → high；只有位置 → review**。

> 实现中改了两处初版规则，都是被这批数据打出来的：
> ① 重复匹配**不再要求落在同一条带**——同一条竖排书眉可能一会儿算"左侧"、一会儿算
> "底部"（第 24 页），按条带分组会把它拆成孤例；
> ② **3 个字以内要求逐字相等**——`第一回` / `第二回` / `第三回` 的相似度是 0.67，
> 过了 0.6 的门槛，但它们位置相同、只差一个字，是**章题**不是书眉。

### 4.4 结果：检出率 / 误标率 / 漏标率

**检出率**（分母是该类金标准行数）：

| 类别 | high（可自动剔除） | 含 review（含"交给人看"） |
|---|---:|---:|
| header | **37 / 38 = 97.4%** | 38 / 38 = 100% |
| page_number | **37 / 37 = 100%** | 37 / 37 = 100% |
| heading | 0 / 9 = 0%（**正确**：回目绝不能自动删） | 9 / 9 = 100%（都被标成"边缘候选"） |
| footer | —（0 行，**未测**） | — |

**误标率**（正文被标成非正文；分母 933 + 32 = **965 行正文**）：

| 操作点 | 误标行数 | 比例 |
|---|---:|---:|
| 只剔 high（**建议操作点**） | **0 / 965** | **0.00%** |
| high + review 全剔 | **0 / 965** | **0.00%** |

**这一条要打个折扣看**：判定器是从 OCR 行里估"正文列"的，正文列自己的行不可能落在
列外（单栏页），所以 0% 有一部分是**构造使然**。真正的风险在多栏正文与章题
（它们确实在别的列里）；本书没有双栏正文，章题靠 review 兜住。

**漏标率**（非正文留在正文里；分母 75 = header 38 + page_number 37）：

| 操作点 | 漏标行数 | 比例 |
|---|---:|---:|
| 只剔 high | **1 / 75** | **1.33%** |
| high + review 全剔 | **0 / 75** | 0.00% |

污染正文的具体形态：第 8 页的竖排书眉被 OCR **拆成两行**（`红楼梦` + `CO三`），
第二行只有 3 个字、与其他页的书眉不像，只能拿到 review → 留在正文里。
它是 3 个字的碎片，位于左栏中段，导出时会粘在相邻段落上。
**块级规则反而能吃掉它**：分组把两行并回一个块，块的相似度足够判成重复。

### 4.5 结果：CER

两个口径都算：**行级拼行**（本次分类器的输出）与**导出路径**（用同一批 OCR 行
在内存里复现 `group_lines` + 块级规则 + `join_lines`，不建项目、不写库）。

| 口径 | 剔除前 | 只剔 high | high + review 全剔 |
|---|---:|---:|---:|
| 行级拼行 | 2.31% | **1.07%** | 0.91% |
| 导出路径 | 2.01% | **0.68%**（块级现状）/ **0.71%**（行级拟改） | — |

- **行级 1.07% 与文档里的行级正文 CER 1.08% 对上了**（差 0.01pp），说明测量口径是同一套；
- **导出路径 0.68% 复现了文档的 0.71%**（差 0.03pp，可能来自 OCR 运行 / 金标准版本的细微差别）；
- 因此可以放心地拿 **0.68% / 0.71% 与 0.71% 基线**比：**行级拟改比块级现状差 0.03pp（6 个字）**，
  差额正是那 3 个字碎片的插入 + 连带位移。
- `after_all` 的 0.91% **更低，但不能算更好**：它把 9 行回目也删了（CER 只看见"少了几处插入"，
  看不见"正文结构丢了"）。这也说明**不能用 CER 单独当操作点的判据**。

### 4.8 未验证 / 不能当结论的

1. **单本书、单 DPI、单引擎、单平台**：40 页 / 200 DPI / RapidOCR 3.10.0 / macOS arm64。
   Windows 与 Linux 未跑；OCR 引擎换成 PaddleOCR 未测。
2. **页脚完全未测**：这本书没有页脚，`footer` 分支只在合成单测里验证过。
3. **多栏正文未测**：本书每页只有一个正文列（章首页另有一列标题 / 插图）；双栏书的
   "第二栏正文"会被正文框排除，风险没量过。
4. **居中页码 / 页脚落在正文列内**会被框进正文框、几何信号失效（见 `region_rules.py` 头部说明），
   本书的页码在左下角，绕开了这个坑。
5. **heading 检出率不是"标题识别准确率"**：规则只输出"边缘候选（review）"，
   没有 heading 类型；9/9 只是"都被看见"，不是"都被认成标题"。
6. **金标准仍是分页草稿**（未经开发者逐页确认）：缺 48 字回目、第 1 页无标记、
   第 13/24 页末尾混入了下一章的 `第X回`。本次都按"正文"口径处理，但边界错误会小幅影响
   行级 CER（跨页错位）。
7. **行级 CER 用的是整篇逐字编辑距离**，一次约 1 分钟；`--skip-cer` 可跳过，正式结果不要跳。

## 6. 结论与建议

**1）规则够用，不需要上版面模型。**
在建议操作点（只剔 high）上：正文误标 **0/965**、页码 **37/37**、书眉 **37/38**（review 后 38/38）、
书眉/页码的漏标只剩 1 行 3 个字的碎片。版面模型能多抓到的东西（居中页脚、双栏、混合块）
在这本书上根本不存在，为它增加依赖、模型体积与许可证审查没有依据。

**2）不建议现在把产品改成"行级、分组之前"剔除。**
导出路径上，行级拟改 **0.71%**，块级现状 **0.68%**——**略差，没有收益**；
原因是块级分组会把被 OCR 拆开的竖排书眉并回一块，行级反而拆散。
40 页里也没有出现"页眉与正文首行被拼进同一个块"：块级规则的 42 个候选里 41 个 high
（文本都是 1–12 字的边缘文字），**唯一的 review 是第 37 页那句 18 字的段末正文**
（与 D-036 的教训同一处），零正文误伤。也就是说，这次要防的风险**在这本书上没有发生**。

**3）下一步只做一件事：换一本书再测。**
优先找**双栏正文**或**居中页码 / 带文字页脚**的书，用同一脚本再跑一遍；
如果那时才出现"混合块"或"居中页脚"的实测失败，再讨论块级改行级、或评估版面模型。
在那之前，产品保持现状。

## 8. 接进产品：块类型建议，与第二本书实测（任务 40）

> 这一节把第 1–7 节的规则接进产品，**以只读建议的形式**呈现，并在第二本书上复核。
> 产品行为只多了一个只读接口：**不自动改块类型、不自动剔除、不引入模型**。

### 8.1 规则怎么落进产品代码

- **唯一实现**：`backend/book2text/core/structure/regions.py`（原来在 `scripts/region_rules.py`）。
  - 行级判定 `classify_pages()` 仍是实验用的粒度；
  - 文字形态 `looks_like_a_number()`、页码候选 `page_number_candidates()`、
    标题标记 `looks_like_heading()`、重复相似度 `similar_text()` 都在这里。
- `core/project/structure.py` 从这里 import：结构工具的 `plan_header_footer()`（块级）
  与新增的 `suggest_block_types()`（只读建议，块级）**共用同一套**
  `_region_of / _propose / _with_confidence`。
- `scripts/region_rules.py` 只剩 re-export 兼容层。40 页实验脚本照旧可跑：
  `--skip-cer` 复跑后检出率 / 误标率与第 4 节**一字未变**。
- **粒度按第 6 节的结论取块级**：不是"分组之前按行剔除"。行级规则保留给实验与后续研究；
  产品建议走块级（导出 CER 0.68% vs 0.71%）。

### 8.2 只读建议接口

`GET /api/projects/{id}/pages/{page_no}/block-suggestions`

每条建议返回：

```json
{
  "block_id": "…", "current_type": "paragraph", "suggested_type": "header",
  "confidence": "high", "confidence_label": "把握较大",
  "region": "top", "reason": "整块落在页面顶部区域；同一区域有 3 处相似文字",
  "signals": {"region": "top", "chars": 9, "repeat_matches": 3},
  "page_number_candidates": [{"text": "2", "kind": "arabic", "value": 2},
                             {"text": "11", "kind": "arabic", "value": 11}],
  "page_number_hint": {"text": "11", "kind": "arabic", "value": 11}
}
```

- **只返回"建议类型 ≠ 当前类型"的块**（已经是该类型的不报，否则界面全是噪声）；
- 非正文页（未纳入、页类型不是 `body`）返回空建议 + `note`，与结构工具的作用范围一致；
- **不写库、不改 `block_type`、不记事件**：集成测试对比接口前后的
  `(block_id, block_type, revision, updated_at)` 与事件条数，全部相等；
  在真实项目 `b2t_8AFV96`（119 块）上调用前后也逐项相等（事件数 0 → 0）。

### 8.3 书眉 + 页码挤在同一行

第二本书第 30 页第 0 块的真实文本是 `2谁是巴赫金?11`（节号 + 节名 + 页码）。
接口给出：**`header`（high）+ 页码候选 `2` / `11` + 提示 `11`**。

处理方式：

- **只在判成页眉 / 页脚 / 页码的候选块里提取数字**；正文块不提取，所以正文里的数字
  （如第 20 页章号 `1`、第 26 页章号 `2`、正文里的年份）**不会变成页码建议**；
- 阿拉伯数字与**规范罗马数字**都收；罗马数字要求独立成词、值 ≤ 100——`mix`（1009）、
  `civ`（104）这类英文单词会被挡住；`xvi` / `xvii` 这类前言页码能认；
- **提示按"页码印在页面外侧"**：左半页的书眉取最左的数字（`10导读巴赫金` → 10），
  右半页取最右的数字（`2谁是巴赫金?11` → 11）。`page_number_hint` 只是提示，
  不是结论；两个候选都返回，界面 / 元数据自己决定怎么用。

### 8.4 第二本书的材料与人工金标准

- 项目 `b2t_8AFV96`（《导读巴赫金》，267 页）。为这次实测补识别到 **14 页**：
  3（版权页）、9（前言）、16/17（缩写表）、18/19（目录）、
  20/22/24/25/26/29/30/31（正文，含书眉 / 页码）。
- 200 DPI、RapidOCR 3.10.0，与产品同一条识别路径。
- **119 个块全部逐条人工分类**（不是抽样）：`header` 9、`page_number` 5、`heading` 7、
  `body` 98；**这本书没有页脚**。标签在
  [`scripts/region-suggestions-labels-bakhin.json`](../scripts/region-suggestions-labels-bakhin.json)
  （只含页码 / 块序 / 块 id / 类别，不含原文），按 `block_id` 校验；
  项目重新识别后块 id 变了会直接报错，不会静默错配。

### 8.6 失败案例（逐条）

| # | 页 / 块 | 金标准 | 建议 | 原因 |
|---:|---:|---|---|---|
| 1 | 17 / 0 | header | header · **review** | 这一页的 running head 是 `书(篇)名缩写 xvii`，与相邻页的 `导读巴赫金` 不同；只识别到一页 → 重复数 1，按"只出现一次"给 review。**不是漏标，是保守**。 |
| 2 | 19 / 0 | body（目录条目 `进阶阅读书目`） | heading · review | 目录条目长得像标题；只给 review，不删任何文字。**1/98 的噪声**。 |
| 3 | 20 / 0 | heading（章号 `1`，大字号） | 无 | 正文区里的纯数字块：为了不把正文数字误判成页码，它**不做数字形态判定**；章号只能靠字号 / 字重认。 |
| 4 | 20 / 1 | heading（章题） | 无 | 没有 `第X章` 标记，OCR 只给 bbox、不给字号 / 字重。 |
| 5 | 26 / 0 | heading（章号 `2`） | 无 | 同 #3。 |
| 6 | 26 / 1 | heading（章题 `谁是巴赫金?`） | 无 | 同 #4。 |
| 7 | 30 / 2 | heading（加粗节标题，14 字） | 无 | 无编号、字号与正文相同（只有字重不同），规则认不出。 |
| 8 | 30 / 4 | heading（加粗节标题，7 字） | 无 | 同 #7。 |

**正文被改成页眉 / 页脚 / 页码：0 条。** 唯一一条正文上的建议是 #2，类型是 heading 且
只有 review——即使被误采用也只改类型、不删文字。

另外一处**界面要注意**的地方（不是规则错）：第 30 页的页码 `11` 只出现在书眉里，
没有独立的页码块。只显示 `suggested_type == page_number` 的界面会看不到它——
必须用 `page_number_candidates` / `page_number_hint` 把页码带出来。

### 8.7 结论

1. **规则在第二本书的横排书眉上成立**：页眉 9/9、页码 5/5、正文家具误标 0/98。
   第一本书（竖排书眉 + 左下角页码）是同样的结论；两种版式都不需要版面模型。
2. **标题是弱项（1/7）**，但标题建议**永远只到 review**，不会删任何文字；
   要提升只能看字号 / 字重（版面模型）。当前用户的痛点是"所有块都是段落"，
   页眉 / 页码才是主要噪声，标题可以留在下一刀。
3. **"书眉 + 页码同行"必须靠候选数字表达**，不能指望把整块判成 page_number；
   提示（`page_number_hint`）只作参考，两个候选都返回。

### 8.8 给 Builder 的界面建议

- **每条建议一个轻量徽章**（块头 / 行内，不弹窗）：
  `页眉 · 把握较大` / `页码 · 把握较大` / `标题 · 需确认`；`reason` 放 tooltip。
- **书眉带页码时**显示 `含页码 11（候选 2 / 11）`，把 hint 标成"可能是"。
  如果产品暂时没有页码字段，就只做只读展示；**不要**为了记录它自动拆块 / 改文本——
  拆块是结构编辑，应由用户明确操作。
- **只对 high 提供"本页全部采用"**；review 必须逐条点。采用 = `PATCH block_type`，
  然后重新拉一次建议（接口只返回差异，采纳后会自然消失）。
- **不要自动应用、不要拦截保存**；进入页面拉一次，块类型变化后重拉，不轮询。
- **标题建议不要计入"待办"数字**（噪声大），只做行内轻提示；
  工具栏可以显示"本页 N 条建议"并滚到第一条。
- 第 30 页这种"页码只在书眉里"的页，块头徽章要显示页码候选，否则用户看不到页码信息。
