另外**人工校对金标准仍不存在**。详见第 4、5 节。

## 1. 这是什么

从开发者提供的两本源书按类别挑选 20 页，在 300 DPI 下渲染成灰度位图后重新拼成的
**图像型 PDF**。它没有文本层——已实测确认，20 页的文本层字符总数为 **0**，
且每页只含 1 个图像对象（无文本、无矢量路径），结构与真实扫描件一致。

| 参数 | 值 |
|---|---|
| DPI | 300（说明书预期默认值） |
| 色彩 | 灰度（`L`）——真实书籍扫描通常也是灰度，且文字识别不需要颜色 |
| 压缩 | JPEG，质量 85 |
| 页面尺寸 | 与原书一致：447 × 674 pt（红楼梦）、612 × 792 pt（安乐哲） |
| 生成时间 | 见清单 `generated_at` |

**重新生成：** 需要 `test_books/` 里存在源书（该目录不入库）。

```bash
uv run python scripts/make_scan_samples.py              # 300 DPI / 质量 85
uv run python scripts/make_scan_samples.py --dpi 400    # 换参数重出
```

## 4. ⚠ 两个重要局限：这不是真实扫描件

### 4.1 源书是原生数字排版，不是扫描件

两本源书都是**原生数字 PDF**（文字是矢量文本，不是位图扫描）。已实测确认：
每页含 20–60 个文本对象，且渲染出来是干净的排版文字。

因此本样本是**干净栅格化的结果**，不含真实扫描件的以下特征：

- 页面倾斜（skew）
- 扫描噪点、污点、装订阴影
- 纸张泛黄、透印（背面文字透过来）
- 对比度不均、深浅不一
- 半色调网点（halftone）

**这意味着：OCR 在本样本上的表现会明显好于在真实扫描老书上。**
用本样本的 CER 数字去预期真实旧书的效果会偏乐观。这一点在
`docs/technical-feasibility.md` 的风险表中已记录。

### 4.2 两个类别无法从这两本书取得

| 缺失类别 | 原因 |
|---|---|
| **中文与中英混排** | 安乐哲一书是纯英文（中文只以罗马字转写出现，如 "Lao Tzu"），全书 **0 页**含汉字；红楼梦该文件是纯中文，**0 页**含拉丁字母。两本书都不含中英混排页。 |
| **低清晰度或倾斜页面** | 源书是原生数字排版，不存在这类页面；人工合成倾斜/模糊**不能代表**真实扫描件的退化特征，故未合成。 |

这两项要么需要另找扫描样本，要么接受"暂不覆盖"并记录在案。

### 4.3 源 PDF 的文本层不可靠（重要）

红楼梦源文件的文本层存在**错字**，例如：

- 第三十八回回目 "薛**蘅**芜讽和螃蟹咏" 被写成 "薛**祷**芜讽和螃蟹咏"
- 第四十回回目 "金鸳鸯三**宣**牙牌令" 被写成 "三**宜**牙牌令"
- 第二十八回 "蒋玉**菡**" 被写成 "蔣玉**函**"

渲染出的**页面图像是正确的**，错的是文本层。这说明该 PDF 字体的 ToUnicode 映射有问题。

**两个后果：**

1. **不能拿源 PDF 的文本层当金标准**——它本身就带错字，用它做基准会把 OCR 的正确输出判成错误。
2. 这反过来印证了产品的立论：**已有的文本层未必可信**，需要按页对照原图审校。

## 5. 仍然缺失：人工校对金标准

说明书 13.1 要求 "其中 5–10 页人工校对作为金标准"，并明确
"**未经人工校对的 OCR 输出不能作为金标准**"。

**这份金标准目前不存在。** 它是 Phase 0 第 1–2 项计算 CER、分歧率、捕获率的基准，
没有它，下面这些指标一个都算不出来：

- 第一引擎的中文 / 英文 / 中英混排 CER
- 第二引擎的分歧率、捕获率、"一致但都错"率

**建议做法：** 从本样本中选 5–10 页（覆盖中文、英文、脚注、复杂版面各一两类），
由开发者对照页面图像逐字抄录成纯文本。这是人工工作，无法自动化。

由于源书文本层不可靠（第 4.3 节），**不能**用它自动生成金标准后再略作检查；
必须对照图像校对。
