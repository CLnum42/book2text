# Book2Text

将**没有可用文本层的扫描版 PDF 图书**转换为经过人工审校、可追溯、保留结构信息的文本资产的本地网页应用。

产品形态是「Python 本地服务 + 浏览器界面」：用户双击启动脚本，浏览器打开 `127.0.0.1` 上的界面，全部数据保存在本机。它不是 OCR 包装器——核心价值在于**高效、可靠的人工审校**与**可追溯的数据**。

**现在能做什么：**
- 打开应用先看到**项目库**：每个项目一张卡片——封面、识别与**审校**两条真实进度、
  "上次位置：审校 · 第 87 页"、打开 / 只读打开 / 强制打开（项目被另一个窗口占用时）。
  点卡片上的"打开"进项目，下次回来会**接着上次的视图与那一页**（说明书 7.2）。
- **四个视图**（顶栏页签与按钮切换）：项目库 → **页面**（缩略图网格 + 右侧已选面板）→
  **审校**（左原图右块文本）→ **合并审阅**（协作回传时）；导出、结构工具、任务包、
  质量统计、设置都是**对话框**，不占主界面。
- 在**项目库**里新建项目（上传 PDF），项目**持久保存**，关掉应用再打开还在。
- **缩放看页**：页面视图右上角「－ / ＋」四档：网格 → 大网格（3 列）→ 单列 → 单页
  （页宽 = 容器）。放大时自动换 `view` / `zoom` 渲染档，不会把缩略图拉糊。
  「块框」四档都可用、默认开：网格 / 大网格只画色框，单列 / 单页带 11px 顺序号；
  只给可见页画、离屏立刻清；单击 / Shift / ⌘ 多选照旧。识别进行中也是实时的：
  任务里认完一页，那一页的框当场出现（约 1 秒内），不用等整个任务结束；
  滚动时提前取数、有缓存就立刻画，停下就能看到框。
- **挑选页面**：单击选中、Shift 选一段、⌘ / Ctrl 加减一页，或输入页码范围
  （`1-12, 300-310`）；选中后可以批量设页面类型，也可以只识别所选页。
- **确认页面**：新建项目导入后会先出现「页面确认」——顶栏汇总"正文 / 正文排除 / 前置 /
  目录 / 后置 / 未确认"，右栏第一层就是五个类型按钮（只有「正文」进识别与语料，
  其余四类都不进）。类型直接点，当前类型有"当前"字样；多选类型不同会显示"混合"。
  自动建议（空白 / 首页 / 整页图像 / 目录点线 / 参考文献等关键词）只作候选，
  建议类型右上角有淡色圆点，下面给出理由，点「采用」才会改；改过类型的页会回到
  未确认。识别在第二层；第二引擎 / 全选 / 分派收在「高级操作」里，默认折叠。
  未确认不拦识别，只在你点识别时问一次。
  顶部可按**类型**、**识别状态**与**审校状态**筛选。选 3–10 页时会提示可以当样本先试识别。
  缩略图鼠标停上去会浮出"识别 / 审校"两个按钮。
- **批量识别**：点"识别所选"或"识别全部未识别页"——任务跑在**子进程**里，
  顶栏的**任务 pill**与它点开的**任务抽屉**显示进度与当前页，可以**暂停 / 继续 / 取消**，
  失败页可以**单独重试**。抽屉关掉后**不会自己弹回来**（进度收进顶栏 pill，点它才展开）；
  只有任务失败会主动提示一次。识别结果（块、行、坐标、引擎与耗时）落进项目数据库，
  刷新、重启都还在；双击某一页可看原图上的块框与该页的块文本。
- **中断不会丢成果**：识别到一半关掉应用（哪怕强制结束），不会有进程继续在后台写数据库；
  下次打开项目时那个任务是"中断"状态，点"继续"接着做没做完的页。
- **审校**：双击某一页或点页签进审校视图（左图右文）——块文本可直接编辑、停手自动保存
  （保存后光标留在原处）；确认 / 标不确定 / 排除 / 改类型 / 标记延续；改过的块能看 OCR
  原文也能恢复原文；原图上页眉 / 页码 / "不确定"的块会挂小牌子，点块框跳到对应文字；
  左侧可以缩放（－／＋／适合宽度）或临时关掉块框；**⌘/Ctrl + Enter** 确认本页并跳到下一处
  未完成；**⌘/Ctrl + Z** 撤销（撤销栈只在本次运行里）。每一次修改都写进项目的事件表，可追溯。
- **改结构**：每个块鼠标停上去会出现 **⋯ 更多**：与上一块合并 / 在光标处拆分 / 上移 / 下移 /
  在此块后新增 / 删除——同样都能撤销。漏检的区域用"✚ 框选新增块"在原图上拖一个框补上。
- **块类型建议**：有建议的块在类型下拉旁显示虚线徽章（例「页眉 · 把握较大」），
  点「采用」才改类型（走事件表、可撤销）；只有把握较大的建议才出现「采用全部建议（N）」，
  "需确认"的必须逐条点。书眉里夹着页码时显示「含页码 11（候选 2 / 11）」——**只展示**，
  不自动拆块、不改文本。建议和"未审"是两回事，不会把块变成待办。
  页面视图的缩略图右上角「建议 N」表示这一页有 N 条高把握建议（只为算过的可见页显示）。
- **页眉页脚一次改完**：页面视图右栏「全库采用高把握建议…」——先看扫描预览
  （多少页 / 多少块、页眉 N / 页码 N、前几条样例），确认后一次应用；整批可一次撤销。
  也可以打开「识别完成后自动应用高把握建议」：之后完成识别任务时，服务端会把
  「把握较大」的页眉 / 页脚 / 页码建议直接用上，顶部提示条告诉你改了几页几块，
  不满意点「撤销这次自动应用」。
- **拆块与拆页码**：块菜单「⋯ 更多」→「在光标处拆分」按光标位置切，切开后两块各有
  自己的框；书眉和页码粘在一起时用「把页码 11 拆出去」，页码变成独立的「页码」块
  （进导出元数据，不进正文）。页面视图右栏可以「批量拆分书眉页码…」：先看预览
  （影响多少页 / 块），确认后整批执行，撤销一次全部回退。
- **漏行补救**：审校页顶如果出现「可能漏了 N 处」，说明有字没被任何块框住。点
  「在图上标出」会在页面上画出候选（黄虚线框），点其中一个 → 框选面板自动填好区域 →
  「识别这块」只认这一块（不落库）→ 文字进输入框，可以改，确认后「创建这一块」。
  也可以照旧手动拖框再点「识别这块」。
- **版心**：页面视图右栏「版心」→「推算版心（全书）」：从已识别的行框跨页统计，
  给出四边、参与页数、每边离散度和把握度（页数太少 / 离散太大 / 覆盖率太低会写"建议不可靠"）；
  「采用为全局版心」写入项目默认，只影响「沿用全局」的页。打开右上角「版心」开关后，
  版心外压暗、边框可见；拖四边 / 四角会吸附到正文行边界，拖动某一页会把它变成
  「本页自定义」（只影响这一页），右栏「把本页设为全局版心」可反过来统一全局。
  选中一页可以设「沿用全局 / 本页自定义 / 不适用」，选中多页可以批量设置（执行前确认）。
- **注文建议**：审校视图里，脚注 / 旁批会在块头显示 `脚注 · 需确认 [采用]` /
  `旁批 · 需确认 [采用]`，点「采用」才改类型。它们**永远不会**进「全库采用高把握建议」/
  自动应用（误标会让文字离开正文）；页面视图的「建议 N」只数 high，也不会被脚注建议污染。
- **按版心导出**：顶栏「导出」→ 勾选「按版心判定正文」（项目设置，默认关）。打开后正文只收
  版心内的段落 / 标题，版心外一律不进正文；页码进 `meta.json`，书眉直接丢；脚注 / 旁批即使
  落在版心内也不进正文（块类型层兜底）。需要注释时勾「同时导出注释」，才会生成
  `notes.txt` / `notes.jsonl`。预检会显示「版心内 / 外 / 脚注旁批 / 页码 / 未确认版心」，
  关掉开关就回到旧的块类型判定，导出文件与改动前逐字节一致。
- **调版面**：左图的块框按类型着色，**默认只标小顺序号**（类型文字不常显，避免压住本行
  开头）；顺序号与悬停卡片都会自动避开所有文字行，密集页也不例外。鼠标停到块框上或
  选中块时才弹卡片：`#12 段落 → 页眉 · 把握较大 · [采用]`，书眉里的页码候选也在这里。
  整框拖动可以挪位置、拖四角可以缩放，松手时会**吸附到文字行边界**；改框只重算
  「行 → 块」归属，**不会重新识别、也不会改块里的文字**。一行同时落进两个框会标成
  **冲突**（黄色虚线，按重叠面积归给较大的那边），哪个框都不沾就是**未归属**
  （灰色虚线 + 计数）——这些行一条都不会被丢掉。类型在右栏下拉框改（新增"插图 / 装饰"，
  这两类不输出正文，「旁批」进注释流），顺序用「⋯ 更多 → 上移 / 下移」。
  右栏顶部「本页版面」面板里点「确认本页版面」——这是**整页**的版面确认（哪些块算正文），
  和「页面」视图的页面确认（这页算不算正文）是两个概念；改了任何块的类型 / 框 / 顺序
  会自动回到未确认。
- **新识别结果**：页面"有待选新结果"时可以**左右对比**现有块与新结果，
  选择**采用**（可撤销）或**保留现有**；顶部"疑难"筛选能在需要处理的页之间跳转。
- **导出**：顶栏点「导出」——选格式（TXT / JSONL / 两者）、范围、页面类型与清理规则；
  右边**预检摘要**分别算三条流：正文段数 / 字数、注释条数 / 字数、元数据页数与
  **页码映射抽到几页 / 共几页**（抽不到的页会列出来）。点"生成导出文件"后写进
  `exports/<export_id>/`：`body.txt`、`notes.txt`、`meta.json`、`manifest.json`
  （选 JSONL 时还有 `body.jsonl` / `notes.jsonl`），对话框里逐个下载，
  每次导出都有记录；老的导出记录仍能打开。
- **导出对照**：导出对话框里点"生成预览"——左边原图、右边导出形态的连续段文本；
  点任意一段，左边跳到来源页并把**来源块**框出来（段 → 块 → 页的溯源）。
- **页眉页脚批量标注**：顶栏「结构工具…」里按位置规则（顶部 / 底部区域）与文本条件
  （数字形态、字数上限）预览会标注哪些块，逐条确认后一次批量应用（可整体撤销）。
- **协作（负责人）**：「任务包」对话框里给助手分派——左侧填审校人与说明、生成任务包，
  右侧列出已分派的任务包（下载 / 重新导出 / 导入结果 / 作废 / 查看差异）。导入结果后
  进入**合并审阅视图**：左边变化页列表、中间原图（助手改过的块用蓝框圈出）、
  右边逐条变化卡片，底部"拒绝本页 / 接受本页"，最后提交——整批可撤销。
- **协作（助手）**：项目库点「打开任务包」→ 顶栏出现「导出审校结果」，页面顶部是审校任务
  横幅（页码、来源、截止、说明），只读上下文页会标出来；块备注（💬）随结果包回传；
  识别 / 页面类型 / 页眉页脚工具 / 导出 TXT 在这个模式里没有。
- **两路分歧**：选中几页（或整本）点「复核所选」/「复核全部未复核页」——
  后台任务逐页复核，可以暂停 / 取消；也可以在审校视图里点「第二引擎复核」单页复核（macOS 用系统自带的 Apple Vision）。
  有分歧的块会**逐行**列出"汉字级 / 标点级"与另一路候选——点行号就在编辑框里选中那一行，
  点「换成这一路」把这一行换过去（普通编辑，可撤销）。缩略图上有 `≠ N` 标记，
  顶部「审校」筛选可以按分歧筛页（汉字级 / 含标点级两条）；「质量统计」对话框
  汇总整本书复核了多少行、分歧率多少。**开之前建议先读
  [`docs/ocr-evaluation.md`](docs/ocr-evaluation.md) 第 9 节**——什么时候值得开、
  标记能圈进多少错行、哪些场景别指望它。
  **实测第二引擎比第一引擎弱**（分歧里七成是它自己的标点习惯），所以候选只作参考。

**现在还不能做什么：** 页眉页脚预览的图上高亮、断词还原的逐处人工校正、
缩略图缓存与虚拟滚动、说明书 7.5 余下的快捷键；**插图 / 装饰只能人工标**，
没有自动识别（按实测结论不引入版面模型）；整页版面确认需要人工点一次，不会自动判定。
捕获率与「一致但都错」需要人工金标准，只能在离线测量里给（见 L-30 第 4 条）。见
[`docs/known-limitations.md`](docs/known-limitations.md) L-22、L-29、L-25、L-30。

## 快速开始

```bash
uv sync --group ocr-eval  # 需要识别功能时；只看看界面可以跳过（约 300 MB）
uv run book2text          # 或双击 scripts/start.command（macOS）
```

浏览器会自动打开带会话令牌的地址；若没自动打开，把终端里打印的**界面地址**整条复制到浏览器
（**必须带 `?token=…`**，否则界面会提示缺少令牌）。按 Ctrl+C 停止。

```bash
uv run book2text --port 9000     # 换起始端口（被占用时自动向后尝试）
uv run book2text --no-browser    # 不自动打开浏览器
uv run pytest -q                 # 运行测试（641 项；未装 OCR 依赖时自动跳过需要引擎的那些）
```

项目的原始 PDF 只被读取，导出的成果写在项目的 `exports/` 下。**原始文件不会被修改。**

（`.github/workflows/tests.yml`）：

| 全量测试 | macOS 14 | 装 `dev` + `ocr-eval`，**全套 641 项**（含真实 OCR 与 Apple Vision） | ✅ 绿（run #15，2m 37s） |
| Windows 测试 | windows-latest | 只装 `dev`，`-m "not ocr"`（**deselect**，不是 skip） | ✅ 绿（run #15，2m 44s） |

两个 job 都有一条硬规则：pytest 摘要里出现 “N skipped” 就判失败（防假绿）——
样本缺失、依赖没装、平台不支持都不会静悄悄变绿。Windows 上真正没验证的是
**应用层**（启动、GUI、打包、OCR 引擎），不是测试套件。
纯文档改动（`docs/**`、`*.md`）不触发，以控制私有仓库 runner 的分钟成本
（macOS 10 倍、Windows 2 倍）。结果见仓库的 **Actions** 页。
