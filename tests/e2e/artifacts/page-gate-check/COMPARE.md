# 页面级验证能不能抓住「删错声明」

两次都用同一套 smoke（七步冒烟），同一副本、1423×900 dpr2。

| | 带 bug `2b67132` | 修复后 `df77f19`（含 `5fd4ac7`） |
|---|---|---|
| HEAD | `2b67132`（worktree，源文件干净） | `df77f19`（worktree，源文件干净） |
| smoke | **17/18**（EXIT=1） | **42/44**（EXIT=1） |
| 断在哪 | **BLOCK `[5 正文审校]`**：`等待超时：左树页列表就绪（120000ms 内没等到可观测状态）` | 只有两条已知 FAIL：K1 左栏滚到 120 页、K2 尺寸变化后高亮丢失 |
| 控制台错误 | **8 条，全部 `readingTreeOpen is not defined`**（6 个 error + 2 个 unhandledrejection） | **0 条** |
| 左树渲染 | **否**（树行永远不出现） | **是**（左树头「队列 859 处」，树路径三方 PASS） |
| 折叠展开 | N/A（连树都没渲染出来） | N/A —— **main 上还没有折叠功能**（那是 `ux/dock` 分支的） |

## 结论

1. **smoke 抓得住**这一类 bug，但方式是 **BLOCK + 120s 超时**，不是断言 FAIL：
   报告里只写“左树页列表就绪超时”，**原因（ReferenceError）在报告里看不到**，只有控制台里能读到。
   对不熟悉这套脚手架的人，它长得像“环境问题”，不像“代码 bug”。
2. 因此建议加一条硬断言：**smoke 全程控制台零错误**。
   收集器已在 `72c7932` 落进 `prepare()`（`window.__b2tErrors`），
   现在只差在 smoke 结束时读一次并计入报告（`error_watch` / `mode: read`）。
3. 两次的差别是**唯一的**：8 条 `readingTreeOpen is not defined` → 0 条。
   这条对比可以直接写进验收纪律，作为“页面级验证有效”的证据。
