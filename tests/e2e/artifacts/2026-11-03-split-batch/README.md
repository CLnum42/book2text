## 3. 执行（真实写盘）

`POST /split-page-numbers { dry_run: false }` 200 → 面板关闭 → 页面视图提示
「已拆分 4 块（4 页）。整批算一个操作：到「审校」视图点「撤销」可以一次回退。」

| 页 | 块数（前 → 后） | 新增页码块内容 | 原块剩余文本 |
|---|---|---|---|
| p.1 | 9 → **10** | `4` | `THE STORY OF\nTHE STONE` |
| p.32 | 23 → **24** | `228` | 新增段 `送果品小郎惊叵测\nChapter 90`（原 block_id 变成页码块） |
| p.60 | 19 → **20** | `1` | `27` |
| p.88 | 21 → **22** | `1` | `55` |

**关于「各少了 1 块」**：实际是每页 **+1 块**（原块保留文字，另加一个 `page_number` 块），不是 -1；
p.32 是块首拆，服务端把原 block_id 复用成页码块、新插一个段落块，文本没有丢。

### 缺陷：p.1 拆出的页码块 bbox 高度为 0

```
p1  pn block 9131  bbox=[0.045052, 0.170758, 0.659694, 0.170758]  (y0 == y1，高度 0；x 覆盖整行)
     它的 line   bbox=[0.509398, 0.117396, 0.612228, 0.170758]  (正常)
p32  bbox 高度 0.02135 · p60 高度 0.01868 · p88 高度 0.02134  （都正常）
```

原文那行是 `THE STONE 4`（页码与正文同一行、在块尾），源行 bbox 本身正常，
所以是拆分的块级 bbox 退化成「整行宽的水平线」，不是源数据脏。
影响：这一块在页面/审校视图里显示成一条横线（零高度），块框命中区与版心/重叠判定都会跟着偏。
其余三页（页码独占一行或块首）没有这个问题。
