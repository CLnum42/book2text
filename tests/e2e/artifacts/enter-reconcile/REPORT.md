# "Enter 落不落草稿"对账

## 结论：两个测量量的不是同一对象

| 版本 | 线 | 操作序列 | `readingDrafts` | 进度 |
|---|---|---|---|---|
| `2d33dd4`（tag run-2026-10-28，main 基线） | main | 进审校页 → 不开面板 → 连按 20 次 Enter | **0**（第 1/2/5/10/15/20 次都是 0） | 已审 0 / 567 全程不動 |
| `df77f19` | main | 同上 | 0 | 0 / 567 |
| `eb02997`（L1） | main | 同上 | 0 | 0 / 567 |
| `90e667e`（L2） | main | 同上 | 0 | 0 / 567 |
| `f192e09` / `209afd4`（任务 91） | **ux/dock** | 同上 | **+20** | **0 → 20** |

所以：
- main 的 Enter 只有"下一处未审"的跳转，**没有落草稿**；
- `ux/dock` 那条线（任务 91 键盘闭环）才有"Enter=保留并下一处"。
- 基线里那条 `0 → 20` 是 dock 线的读数，**不能拿来当 main 的基线**；已写进 `BASELINE.md` 的说明。

## 因此 L2 的 #4/#5 改判

用**面板自己的「保留原文」按钮**造草稿（不依赖 Enter 分支），在 `90e667e` 上实测：

```
点「保留原文」 : drafts=1，进度 已审 2/567
点「提交」     : confirm「提交 1 处改动？」→ drafts=0，进度 已审 2/567（已入队）
点「撤销」     : confirm → 进度 已审 3/567 → 2/567（回滚成功）
```

- #4 提交：**PASS**（草稿清空 + confirm + 进度不变/入队）
- #5 撤销：**PASS**（确认框 + 进度回退）
- 之前判 FAIL 的原因是"用 Enter 造草稿造不出来"，那是 main 上 Enter 的既有行为，不是提交/撤销处理器坏了。

## 顺带确认

- `submitReadingDrafts` / `undoReadingSubmit` 搬进模块后**接线正常**（confirm 文案、drafts 清空、进度回滚都对）。
- 需要单开的是另一件事：**main 上键盘 Enter 不落草稿**（dock 线有），属于 D-107/任务 93 那条键盘闭环没有 backport 到 main。
